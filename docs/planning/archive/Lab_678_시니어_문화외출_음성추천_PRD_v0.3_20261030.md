## 먼저 확인 | 팀 즉시 공유용 확정 범위 (Product Freeze)

**한 줄 요약:** 혼자 생활하는 시니어를 위해, 기존 KONNECT `Right now`의 **지도+하단 추천 카드**를 기본으로 하고 `Anything else?` 안에서 **한국어 AI 음성·텍스트 Guided Chat**으로 추천 조건을 수집한다. 사용자가 여러 장소를 묶어 달라고 하면 같은 입력 대화에서 **문화루트 1개(2~3곳)**를 생성하며 `My Route`도 유지한다. **두 번째 별도 서비스 메뉴는 없다.**

| 번호 | 합의된 내용 | 상태 |
|---|---|---|
| Q1 | **비회원도 음성 대화 및 반복 추천을 이용**. 계정 장기 저장·개인화 이력 이용 시 로그인 유도. Google 로그인·최초 선호 설정·My Page 기능 유지 | **[확정]** |
| Q2 | 걷기·이동 관련 발화는 **Soft 선호 / Hard 필수 제한을 구분**. 중요하지만 모호하면 한 번 더 질문. 확인할 수 없는 도보·접근성을 사실로 주장하지 않음 | **[확정]** |
| Q3 | **`Right now` 단일 서비스 진입**. `Plan a route`의 별도 진입을 없애고, Guided Chat과 루트 생성·지도·My Route는 `Anything else?` 대화 안으로 통합 | **[확정]** |
| Q4 | 출발지·시작/종료시각을 **화면에서도, 말로도 입력**. 음성에서 추출한 값은 동일 입력 필드에 반영해 확인·수정. 추측 금지 | **[확정]** |
| Q5 | 추천 결과에는 **별도 AI 채팅창을 만들지 않음**. **조건 수정 → 기존 `Anything else?` 입력 화면 복귀**, 확인된 입력값·대화 맥락을 유지해 재추천. 저장한 Pick/Route는 명시적으로 바꾸기 전까지 보존 | **[확정]** |
| 이름 | 표시 문구는 **임시 한국어 UI 카피**를 사용. 코드 명칭·API·원 기능 레퍼런스는 KONNECT 원명을 병기하고, 한국어 정식 서비스명은 추후 결정 | **[임시·변경 가능]** |

**화면명세서와의 경계:** 본 문서는 **무엇을 유지·변경·추가하고 어떻게 동작해야 하는지**를 결정하는 PRD다. Figma의 구체 배치·버튼 크기·화면별 상세 전이는 후속 화면명세 및 UX 단계에서 결정한다. 미합의 디자인 상세를 이유로 PRD 공유를 지연하지 않는다.

### 임시 한국어 UI 명칭 — 사용자에게 보이는 레이블 [임시·미확정]

| KONNECT 기존 용어 | 시니어 UI 임시 표기 | 적용 위치·주의 |
|---|---|---|
| `Right now` | **나들이 찾기** | 홈의 **유일한 핵심 진입 버튼**. 당일과 향후 날짜의 문화루트도 처리하므로 '오늘만'으로 제한하는 명칭은 피함 |
| `Anything else?` | **더 원하는 게 있으세요?** | 입력 화면의 **AI 대화 영역 제목**. 말하기·글 입력 모두 가능 |
| Voice action / Mic | **말로 이야기하기** | 마이크 버튼의 접근성 레이블/동작명. 상태 표시는 '듣고 있어요', '확인하고 있어요' 등 |
| `Find experiences` | **나들이 추천받기** | 개별 장소 후보 생성, 대화가 코스 의도를 확인한 경우 루트 결과로 연결 |
| `Edit conditions` | **조건 바꾸기** | 결과에서 기존 입력+AI 대화로 복귀 |
| `Find new options` | **다른 곳 찾기** | 새 추천 요청; 필요 시 조건 바꾸기 경로 연결. 비회원 로그인 강제하지 않음 |
| `My Pick` | **내가 고른 장소** | 임시 선택과 계정 장기 저장은 명확히 구별 |
| `My Route` | **내 나들이 코스** | 루트 선택·저장·재접근; 별도 서비스 진입 메뉴와 다름 |
| `My Page` | **내 정보** | 로그인, 저장한 장소/코스, 선호 관리 진입 |
| `Save to My Pick` | **이 장소 저장하기** | 장기 계정 저장 시 로그인 유도. 저장 ≠ 예약 ≠ 방문 |
| `Go with this route` | **이 코스로 정하기** | 루트 선택 확정. 계정 저장 정책은 별도 적용 |

**문구 적용 원칙:** 위 한국어는 **화면용 임시 레이블**이며 코딩 식별자·데이터 필드·기존 소스 근거의 `Right now`, `Plan a route`, `My Pick`, `My Route`는 변경하지 않는다. UI 명칭만 교체하는 작업이 새 기능/새 화면을 뜻하지 않는다.

### 0.2 증거 단계의 엄격한 구분

- **QA 문제/미확인**: 실제 최종 구현에도 결함·불완전한 시나리오가 있을 수 있음. PRD에서 조용히 ‘완료’로 전환하지 않음.
- **기획 기준**: 요구사항으로 존재하지만 코드 구현/QA 증빙과 다를 수 있음. 소스 충돌 시 차이를 명시.
- **신규 전환**: 한국어 시니어 UX·음성 STT/TTS 등은 기존 KONNECT 구현으로 주장하지 않음.

- 운영진 답변 전 개발 담당자는 새로 작성 가능한 작업을 중심으로 계획한다. 기획·화면 구조 참고와 소스코드 재사용을 구분한다.

## 1. 제품 정체성 — 변하는 것과 변하지 않는 것

### 1.1 제품 한 줄 정의 [변경]

**혼자 생활하는 시니어가 AI와 한국어 음성으로 대화하며, 현재 위치·날짜·가용시간·관심사·이동 부담을 고려해 실제 선택 가능한 문화경험을 찾거나 하루 문화루트를 구성하고, 지도·카드·공식 정보로 방문 결정을 내리는 모바일 웹 서비스.**

- **[승계] 핵심 가치:** 개인화 문구 자체보다 **현재 조건에서 실제 선택 가능한 문화경험인지 확인해 선택을 좁히는 것**.
- **[변경] 사용자:** 서울 자유여행 외국인 FIT → 시니어, 1차 페르소나는 혼자 생활하는 고령 1인 가구. 모든 시니어가 이동이 어렵거나 디지털 기기에 익숙하지 않다고 가정하지 않는다.
- **[변경] 두 가지 대표 문제:** ① 무엇을 할지 몰라 문화활동을 발견하기 어려움 ② 거리·걷기 등 외출 부담 때문에 방문을 망설임.
- **[추가] 핵심 인터페이스:** 한국어 **양방향 음성 대화**(사용자 STT → 기존 대화형 조건 수집/추천 원리 → AI 음성 TTS), 텍스트·선택 입력 경로 병행.
- **[승계·변경] 핵심 행동:** **하나의 `Right now` 기반 ‘나들이 찾기’**에서 장소 추천과 선택적 다중 장소 코스 요청을 모두 처리. 추천 후보/루트 검토, 선택·저장, 공식정보·길찾기, 조건 수정·재탐색, 계정/선호 관리 기능은 보존.
- **[변경] 기존 복지·생활지원 DB 추천:** 시니어 원본 PRD의 분야이지만 이번 통합 문화활동 MVP의 주 기능 **밖**으로 확정. 문화 추천과 혼합해 가짜 통합 추천을 만들지 않음.
- **[제안] 검증 권역:** KONNECT와 연속성 있는 서울 문화권에서 시작. 특정 구·시니어 연령 구간·최대 이동거리는 아직 확정하지 않음.

### 1.2 유지할 콘텐츠 범위 [승계]

- 문화경험 유형 5개: **직접 참여 체험 / 공연 / 전시 / 문화·역사 장소 방문 / 축제·행사**.
- 사용자 관심사 6개: **전통문화 / 역사·궁궐 / 문화 체험 / 미술·전시 / 공연 / 축제·이벤트**. 복수 선택·미선택 허용.
- 야외 여부는 독립 추천 유형이 아닌 속성. 일반 맛집·쇼핑·스포츠·레저·종합여행 계획은 기존 서비스 핵심 범위 밖. 팝업은 기존의 데이터 수집 제약을 보존하고 이번 MVP 자동 추가를 약속하지 않음.
- 이미 알고 있는 콘텐츠 범위를 시니어용이라는 이유로 **노인복지관 프로그램만으로 축소하지 않는다**. 단, 참여 대상 연령·예약조건 등 공식 정보가 부적합하면 제외한다.

### 1.3 유지할 신뢰 경계 [승계]

**미확인 ≠ 무료 / 예약 불필요 / 이용 가능 보장.** 공식 확인 전 실제 회차·좌석·예약·시설 접근성·현장 운영을 보장하지 않는다. AI 설명과 LLM 해석을 사실 판정에 사용하지 않는다.

## 3. 공통 추천 규칙 — 최종 KONNECT 승계

### 3.1 입력/컨텍스트

- **[승계]** 핵심 위치·시간을 구조화하고, 관심사·예산·이동 선호·날씨 선호·제외조건·기존 계획 등은 상황에 따라 선택 정보로 사용.
- **[승계]** 사용자가 제공하지 않은 시간·출발지를 임의 확정하지 않음. 현재 위치 사용 시 권한·정확도 확인, GPS 실패·거부 시 직접 장소 입력.
- **[승계]** `Use current location / Search a place / Popular starting points` 등 위치 입력 보조 개념. 기존 관광 대표 지점 5개 Quick Select는 **[변경]** 시니어용으로 자동 노출할지 미확정; 서울·지점명을 임의로 시니어의 출발지로 강제하지 않음.
- **[승계]** 해석된 자연어 조건의 편집 가능한 확인 시트, 잘 모르는 값의 보류와 필수 모호값 확인.
- **[승계]** 기존 일정은 **선택형** Context. 실제로 구조화·계산하지 못한 약속을 자동 반영했다고 표시하지 않음.
- **[확정 Q4]** 음성·텍스트로 파악한 출발지·시작/종료시각도 **현재 화면의 동일한 구조화 입력 필드에 반영**한다. 변경·확인된 값만 추천/루트 요청에 사용한다. 인식된 발화·AI 추정값·사용자 확인값을 구분해 표시한다.
- **[변경]** 시니어라는 사실만으로 보행 제한, 건강 상태, 복지 대상 조건을 추론하거나 필요 이상의 상세 건강정보를 요청하지 않음.

### 3.2 Hard/Soft/상태

| 범주 | 기준 | 대표 예 |
|---|---|---|
| Hard constraint | 사용자의 명시적 절대 상한, 공식 운영·대상 조건 충돌 | “도보 10분 넘기면 안 돼요”, 종료된 행사, 명시적 미허용 대상 |
| Soft preference | 바람·취향·일반 부담 | “많이 걷고 싶진 않아요”, 전시 선호, 저렴한 곳 선호 |
| 확인 필요 | 충족 판정에 필요한 근거 부족 | 예약 필요 여부·가격·시설 편의·도보 경로 미확인 |
| 상태 표시 | **조건 충족 / 추가 확인 필요 / 조건 완화 대안** | 내부 `제외`는 일반 결과에 노출하지 않음 |

- 실제 이용 불가/명시적 Hard 충돌은 정상 결과에서 제외. `추가 확인 필요`를 `조건 충족`으로 포장하지 않음.
- 정렬은 관심사·이동 부담·검증된 시간 여유·정보 신뢰도 등에 근거. 추천 이유는 **확인 가능한 경우 후보당 0~2개**이며 사실·주 상태와 구분.
- 가격 미확인 ≠ 무료, 예약 미확인 ≠ 예약 불필요. 계획 체류시간/실제 운영시간/계산 이동시간을 구분.
- 검증 가능한 후보가 1~2개면 그대로 노출하고 3~4개로 강제 충원하지 않음.
- **[확정 Q2]** 시니어 이동 부담 발화에서 `Soft` 선호와 `Hard` 명시적 제한을 구별하고, **추천에 큰 영향을 주지만 모호한 경우 필요한 기준만 AI가 추가 질문**한다. 도보 이동시간·경사·계단·무장애 여부는 **데이터로 확인되는 범위에서만** 판단. 직선거리로 보행 가능 여부를 단정하지 않음.
- **[승계]** 추천 제외, 조건 수정, 다른 후보 요청 시 **후보 집합·정렬/판정을 실제로 갱신**. 이유 문구만 변경하는 것은 재추천이 아님.

## 4. Right now — A 즉시 추천 **전체 승계 기준**

### 4.1 입력·검증 [승계]

1. 홈 `Right now` 클릭 → 입력 화면.
2. 출발지: 현 위치(권한 요청 및 정확도 확인) / 장소 직접 검색 / Quick Select(확정 여부 재검토).
3. 시작시각(변경 가능한 현재 시각) + 종료시각(사용자 명시, 자동 연장/자동 기본 종료 금지).
4. `더 원하는 게 있으세요?`에서 **음성·텍스트 양방향 AI Guided Chat**으로 관심사·예산·걷기/이동·실내/실외·기존 일정·명시적 제외·**코스 요청 의도**를 수집한다. 위치·시각도 여기서 말하면 **①~③ 입력 필드에 동기화**한다.
5. 자연어 해석 결과·기존 필드 통합 요약을 사용자에게 확인/편집받은 후 **개별 장소 추천 또는 사용자 요청 시 다중 장소 루트 생성**.
6. 시간/출발지 검증: 무효 입력 → 입력 오류 안내/수정, **유효하지만 후보 0건**과 구분.
7. 요청 후 로딩·진행 표시 및 실패 시 조건 유지.

**중요 기존 기준/코드 차이 [미확인]:** 최신 Product 기준에는 `최소 60분, 시작일 24:00 종료 상한`으로 기록되지만, 확인한 백엔드 `backend/app/domain/input_validation.py`는 `MIN_AVAILABLE = 30분`, 같은 스냅샷의 프론트 `pages/input.js`는 `MIN_WINDOW_MIN = 60`을 사용한다. 따라서 **60분 충족 구현으로 표시하지 않고** 팀이 통합 전에 일치시킬 항목으로 남긴다. 본 통합 작업에서 임의로 30분·60분 중 하나로 변경하지 않는다.

### 4.2 지도+하단 카드 [승계·필수]

- **결과 화면 기본 구조는 상단 지도 + 하단 추천 장소 카드 가로 캐러셀**이다. 채팅 말풍선만 출력하거나 목록으로 바꾸지 않는다.
- 지도: 출발지 마커·추천 후보 마커·가능한 경우 실제 도보 이동경로 선과 거리/시간. 미확인 경로를 직선으로 그려 실제 이동경로라고 주장하지 않음.
- 결과 카드: 장소 사진/아이콘, 장소명·유형, 조건 충족/확인 필요/대안 상태, 추천 이유 0~2개, 시간·운영, 가격, 예약/참여조건, 이동 부담, 확인 필요 항목, 공식 링크, 길찾기. 미확인 내용은 숨기지 않음.
- **지도 마커 ↔ 카드 스와이프/선택의 포커스 동기화**: 마커를 누르면 해당 카드로 이동, 카드를 넘기거나 누르면 지도 중심·마커/경로 강조 변경. 코드 `pages/results.js`, `map.js`에 관련 동작 존재.
- **후보 수**: 기존 Right now 기준 소수 최대 3~4개(시니어 전환 초안의 임의 최대 3개 고정 **취소**). 서버 실반환 개수 및 새 UI 최종 상한은 검증 필요.
- **[확정 Q5]** `조건 바꾸기(Edit conditions)` → **기존 `Right now` 입력 화면의 `Anything else?`**로 복귀. 출발지·시간·확인된 선택 조건·대화 맥락을 유지하고, 수정된 조건으로 실제 추천을 다시 계산한다. **결과 화면에는 별도의 AI 대화창을 추가하지 않는다.** `다른 곳 찾기`도 비회원 로그인을 강제하지 않는다.
- **[변경]** 시니어 사용성을 위해 글자·터치 표적·정보 위계를 조정하되 마커↔카드 연동, 실제 방문 확인 정보를 손상시키지 않음.

### 4.3 선택·상세·저장 흐름 [승계]

- **`Select experience`는 임시 후보 선택**, 이 단계에서 `My Pick`에 최종 저장됐다고 표시하지 않음.
- 선택 상세(기존 LF-09 역할)에서 `저장 전`/`이 장소 저장하기(Save to My Pick)`을 구분한다. **[확정 Q1]** 비회원이 추천·임시 선택·재추천하는 데 로그인은 필요 없고, **계정에 장기 저장**하려는 경우 로그인 유도한다. 현 대화 중 임시 선택값은 로그인 없이 유지하고, 로그인 취소 시 손실되지 않게 한다.
- 저장된 경우 `My Pick`, `See on map`, `Directions`, `Official website`, `Find other options` 등으로 복귀/다음 행동. 상세 LF-06은 선택적으로 열 수 있고 필수 경유가 아님.
- **저장 ≠ 예약 ≠ 방문 완료**. 원래 저장 선택이 있는 상태에서 다른 후보를 임시 선택하고 이탈하면 기존 저장값 보존. 새 후보 최종 저장 후에만 교체.
- **근거:** QA-A08에서 2026-10-13 홈·My Page·새로고침 간 `My Pick` 저장·교체·재접근 정상 관찰. 다른 기기·장기 보존까지 자동 확장하지 않음.

## 5. Plan a route — 별도 홈 메뉴 제거, **기능은 단일 진입에 통합**

> **[확정 Q3]** 최종 KONNECT의 루트 생성·지도·수정·저장 기능은 보존한다. 다만 기존 `Plan a route` **별도 진입 메뉴와 독립된 사용자 출발 화면은 없애고**, `Right now`의 `Anything else?` 대화에서 사용자가 여러 장소 코스를 요청했을 때 **루트 생성 분기**로 진입한다. 구현에서 내부 A/B 로직·엔드포인트가 분리되어 있어도 사용자에게는 하나의 서비스다.

### 5.1 Guided Chat·조건 수집 [승계·변경]

- 홈 **‘나들이 찾기(Right now)’** → `더 원하는 게 있으세요?(Anything else?)`의 **대화형 Guided Chat** → 사용자가 코스/여러 곳 방문 의도를 명시하면 **루트 요청 분기**. 별도 `Plan a route` 홈 버튼이나 중복 채팅 화면을 생성하지 않는다.
- 기존 필수 4값: **날짜, 출발 위치, 시작 시각, 종료 경계**. 자연어로 여러 값을 한 번에 제공해도 구조화하고 부족/모호/충돌한 필수 조건만 재질문.
- **S1 시작 안내·예시 → S2 보완 질문 → S3 Ready/요약 확인 → V1 직접 수정·모호값 보정**의 기준을 이어감. 기존 입력 문장을 필요 없이 반복 요구하지 않음.
- 편집 가능한 조건 요약, 필요할 때 직접 입력과 Quick Action을 제공. 미래 날짜의 출발지를 현재 GPS로 무단 대체하지 않음.
- **[확정 Q3·Q4]** 사용자가 음성으로 말하면 STT로 통합 `Anything else?`에 입력하며 AI 응답은 TTS로도 읽는다. 출발지·시각을 대화에서 이해한 경우 같은 화면의 입력 필드에 반영하고 확인받는다. 텍스트 채팅·직접 수정 기능은 계속 제공.
- **[변경]** 여행 일정 대신 시니어 문화 외출 일정 맥락으로 자연어 예시·질문·결과 문구 교체.

### 5.2 루트 생성·결과 [승계]

- 출발점+가용시간을 기준으로 **문화경험 2~3곳으로 구성된 순서 있는 루트 1개**(기존 개발 PRD/QA의 2~3곳 기준)를 목표로 한다. 실제 코드/QA에서 5곳 생성 관찰이 있어 **정책 충족 완료로 간주하지 않는다**.
- 운영기간·회차·휴무·체류시간·구간 이동시간·예약/비용을 검증해 가능한 방문 순서를 제시.
- UI: `route-card.js`, `route.js`, `map.js` 기반의 방문 순서, 타임라인, 장소별 상태, 전체 비용 확인 여부, 루트 지도/경로, 장소 상세(선택적으로 열기).
- 여러 후보 중 2곳을 신뢰할 수 없으면 실제 데이터에 근거한 개별 추천 또는 구성 실패/시간 수정 경로 제공. 불가능한 루트 강제 생성 금지.
- 실제 운영/시각·예상 이동/체류·Product 계획값을 구분. 시간과 이동 수치를 AI가 임의로 생성하지 않음.
- 코스 장소 삭제(Remove), 조건·날짜·시간 수정, 재구성 요청, 실패 후 이전 유효 루트 복귀. 변경된 조건으로 재검증하지 않고 기존 결과만 다시 그리는 것을 성공으로 보지 않음.
- **[변경]** 걷기 부담·명시적 이동 상한을 루트의 각 구간 및 전체 부담에 반영하는 것을 신규 검증 과제로 둠. 확인 불가한 무장애/계단/휴게정보는 직접 사실로 생성하지 않음.

### 5.3 My Route 저장·복귀 [승계]

- `Go with this route`를 통한 명시적 선택·저장, 홈의 현재 루트 카드, My Page 재접근.
- 저장하는 것은 사용자가 선택한 장소·출발지·시간창 등 **참조 정보**이며, 다시 볼 때 실제 데이터 재조회/재구성하는 처리 코드 존재. 이를 **과거 정보의 영원한 동일 보장**으로 오인하지 않음.
- 사용자가 확정하지 않은 새 루트로 기존 `My Route`를 조용히 교체하지 않음. 재조회에서 일부 장소가 삭제·운영 변경되면 변동/누락과 확인 필요 정보를 알려야 함.
- **[확정 Q1]** 비회원의 코스 탐색·재구성·임시 선택은 로그인 없이 허용한다. **계정에 `내 나들이 코스(My Route)`를 장기 저장하는 시점**에 로그인 유도한다. 기존 QA의 저장 오류는 재검증하되, 과거의 첫 B 저장 비회원 허용 정책을 이번 서비스에 자동 승계하지 않는다.

## 7. 한국어 양방향 음성 대화 **신규 Delta**

### 7.1 범위 [확정: 양방향 음성 목표 / 세부 방식 제안]

- **[확정]** 한국어 사용자 음성 입력 + AI 한국어 음성 질문/응답. 단순 STT 검색창이 아니라 **다중 턴 대화**.
- **[제안]** 마이크 누르기 → 사용자 발화 인식(STT) → 텍스트 확인/수정 → 기존 대화·추천 처리 → AI 텍스트 표시와 음성 읽기(TTS) → 다시 마이크로 답변하는 **턴 기반** 경험.
- **[확정 Q3·Q4]** 음성 입력은 **하나의 `Right now` 입력 화면 속 `Anything else?` Guided Chat**에 연결한다. 같은 구조화 조건 모델에서 **개별 추천 또는 코스 추천**으로 분기하며 별도 음성 전용 추천 엔진·홈 메뉴를 만들지 않는다. 출발지·시간은 직접 필드 조작과 대화 입력을 양방향 동기화한다.
- **[제안]** AI의 응답 텍스트는 항상 화면에 남기고, 다시 듣기·음성 끄기·텍스트 직접 입력/조건 수정 경로 제공.
- **[제안]** AI가 말하는 동안 음성 인식을 중지하고 중복 턴을 방지. 권한 거부·음성 미지원·인식 오류·무음·TTS 실패 시 기존 텍스트 흐름으로 돌아감.
- **[미확인]** Web Speech API `SpeechRecognition`/`speechSynthesis` 사용 가능 브라우저·한국어 음질·호환성·시연 기기·대체 STT API·사용량 비용.
- **[보류 결정]** ChatGPT처럼 실시간 끼어들기·상시 듣기는 **양방향 음성 목표에 자동 포함되지 않음**. 별도 승인·기술 증빙 없으면 범위 확대 금지.

### 7.2 AI 대화 상태 [제안]

`idle → listening → transcript-review → thinking → speaking → idle`.

- `listening` 중 현재 사용자가 말하는 상태를 명확히 표시.
- `transcript-review`에서 인식 오류가 생긴 고유명사/출발지/시간은 재확인·수정 가능.
- `thinking` 로딩·타임아웃/재시도·취소, 이전 유효 조건 보존.
- `speaking`에서는 화면 텍스트와 동기화·다시 듣기.
- 사용자의 직접 입력, 음성 인식 결과, AI의 추정 조건, 사용자가 확인한 구조화 조건을 구분하며 서버가 최종 확인값을 받도록 함.

### 7.3 시니어 접근성 Delta

- 큰 마이크 버튼/명확한 대화 상태·큰 터치 영역, 충분한 명도 대비·읽기 쉬운 글씨·짧은 질문·사용자 용어.
- 초반에 한꺼번에 조건을 요구하지 않고 **부족한 핵심값만** 물음. 위치·시간은 추측하지 않음.
- 손의 떨림, 청력·시력·보행능력 등은 사용자마다 다르므로 ‘모든 시니어가 동일하다’는 고정 UX 가정을 금지.
- 음성 사용을 강제하지 않고 **동일한 추천에 도달하는 텍스트/선택 경로 보장**. 음성 출력 중지를 쉽게 제공.
- 장소 결과는 대화 말풍선 안에만 숨기지 않고 **기존 지도+하단 카드/문화루트 화면**에서 읽고 비교하게 한다. **[확정 Q5] 결과 화면에는 AI 채팅창을 추가하지 않고 `조건 바꾸기`로 입력 화면에 복귀**하여 대화 맥락을 이어간다.

## 9. 백엔드·데이터 계약 — 기존 API와 신규 Delta의 경계

> **기존 엔드포인트와 구현된 개념을 문서화**한 것이며, 직접 코드 재사용 승인·스키마 호환성·새로운 통합 구현 완료를 뜻하지 않는다.

| 기능 | KONNECT 확인된 API | 이번 서비스의 역할·변경 |
|---|---|---|
| 생존·설정 | `GET /health`, `GET /api/config` | 유지; 공개 설정만 출력, 비밀키 노출 금지 |
| 자연어 조건 파싱 | `POST /api/parse` | 기존 A 확인 시트용. 음성 전사 텍스트도 동일한 확인값으로 전달 가능 |
| Right now | `POST /api/recommend` | 날짜·시간·위치·선호·제외 반영, 필터/정렬/지도 후보 |
| 문화루트 생성(내부 B) | `POST /api/route` | **단일 입력 대화에서 코스 의도를 확인한 뒤 호출**. 별도 B 홈 화면은 없으며 루트/저장 재조회 기능 유지 |
| Agent 대화 | `POST /api/chat` | **`Anything else?` 안의 텍스트/STT 입력 하나로** 누락값 질문·확인된 입력 필드 동기화·RAG·추천/코스 요청 분기. 결과 화면에서 별도 채팅창 호출 금지 |
| 대화 이력 | `GET/DELETE /api/chat/history` | 정식 계정의 이력 조회/삭제 가능 구조 확인. 새 개인정보 정책·보존 합의 필요 |
| FAQ/RAG | `POST /api/ask` | 기존 여행 정보에서 시니어 문화 안내로 지식 재구성 |
| 사용자 세션 | `GET/PUT /api/session` | 현재 선택·조건·루트 참조 유지. JWT로 계정 구분 |
| 장기 선호 | `GET/PUT /api/preferences` | 관심사/추가 선호/온보딩 완료/수정·초기화 |
| 기존 번역 | `POST /api/translate` | 원문 한→영 번역. 한국어 기본 UI가 되면 필요성과 표기 규칙 재검토 |
| 신규 음성 I/O | **기존 API 없음** | [추가] 프론트 STT/TTS 또는 별도 서비스. 실제 아키텍처/요금은 기술 검증 뒤 결정 |

**새 인터페이스 제안**: 사용자 텍스트든 STT에서 확인된 텍스트든 같은 `message`, `confirmed_context`, `conversation_history` 등으로 전달. `reply_text`, 구조화 조건, 질문 상태, `recommendations`/`routes`, 미확인 사항을 반환. 새로운 `/api/conversation/turn` API를 **필수로 신설할 근거는 없음**; 기존 `/api/chat` 계약을 먼저 점검하고 필요한 필드만 확장.

### 9.1 원래 AI·데이터 파이프라인

- FastAPI + Pydantic, HTML/CSS/Vanilla JS(ES Modules), Supabase(Postgres/Auth/pgvector), LangChain·LLM, RAG(FAQ), 자체 도메인 판정, Map/Route 클라이언트 구조를 **기준선으로 기술**.
- `orchestrator.py`(A)·`route_orchestrator.py`(B), `chat_agent.py`/`agent_loop.py`(대화), `domain/{normalize,timing,budget,ranking,status,route,operational,reservation,reasons}`에 구현 단위 확인.
- **기존 호출 구조 존재 ≠ 실서비스 모든 요청이 성공.** 시니어용 데이터 원천·조건·목소리 처리와 전체 QA는 신규 검증해야 한다.
- 서비스 밖 외국인 언어·FAQ 전용 로직은 삭제하기 전 의존성 영향 확인. 시니어 데이터/예시로 바꿔도 A/B/로그인 저장 흐름을 깨지 않음.

### 9.2 추천 응답의 최소 정보·경계 [승계]

`candidate_id`, `title`, `type`, `official_source`, `source_checked_at`, `coordinates|null`, `address|null`, `opening/period`, `price`, `reservation/participation`, `travel_distance/duration`(근거 표시), `status`, `reasons(0..2)`, `checks_required`, `official_url|null`, `directions_url|null`.

- 이름/키는 새 통합 계약을 위한 **개념 필드**. 실제 코드의 Pydantic 필드명·enum은 `backend/app/models/` 확인 후 확정.
- 값이 없으면 null/미확인; 시니어에게 불편하다는 이유로 근거 없는 정보를 채우거나 누락 표시를 삭제하지 않음.
- B 루트는 방문 순서, 시간대, 단계별/전체 비용 확인 여부, 구간 이동, 사용자 확정 조건, 변경·복구 가능 여부를 추가 포함.

## 11. 예외·보존·개인정보 정책

1. **위치 거부·모호:** 다른 조건 보존, 출발지 직접 입력. 임의 지도 좌표 대체 금지.
2. **시간 오류:** 필수 종료 미입력·역전·경계 미달은 추천 0건이 아닌 입력 오류. 기존 Product/백엔드 60/30분 충돌을 먼저 해결.
3. **후보 0건:** 원래 Hard 조건을 몰래 완화하지 않고 수정/대안 경로 제공. 실제 없는 후보를 생성하지 않음.
4. **부분 데이터:** 확인된 운영/가격/예약/편의 정보와 `확인 필요`를 분리. 공식 경로로 연결.
5. **전부 실패/타임아웃:** 최근 유효 조건·결과 보존, 다시 시도·이전으로 복귀. 무한 로딩 금지.
6. **비동기 경합:** 음성 전사 늦게 도착/대화 응답 중복/오래된 추천이 최신 결과를 덮어쓰지 않음.
7. **선택과 저장:** 임시 선택/최종 저장/로그인 취소/외부 지도 왕복을 구분. 클릭 ≠ 예약 ≠ 실제 방문.
8. **저장·선호 경계:** 사용자 계정별 구분, 선호 초기화가 현재 Pick/Route를 삭제하지 않음. 다른 계정 데이터 노출 금지.
9. **루트 복원:** 저장 ref 기반 새로 조회 시 변경된 장소·운영을 감추지 않고, 새 추천임을 표시. 복구 불가능하면 실패·조치 안내.
10. **개인정보:** 음성 녹음·전사 텍스트에는 위치·개인 사정이 포함될 수 있음. 필요한 최소값만 수집·전달, 원본 음성 저장 여부·보존/삭제·동의·외부 API 처리 범위를 구현 전 정의. 건강 상태를 자동 추론/기록하지 않음.
11. **모바일/음성:** 음성 기능이 작동하지 않는 기기에서도 **통합 단일 진입에서 텍스트/직접 필드 입력으로 개별 추천과 코스 요청**이 가능하도록 함.
12. **보안:** API Key, Supabase Secret, 민감한 요청 원문을 프론트·깃·공개 로그에 노출하지 않음.

**완료 수준 구별**

1. **PRD 완성**: 모든 기존 기능을 기준선으로 포함 + 시니어 Delta/미확인 구분. 이 문서는 이 상태를 목표로 한다.
2. **UI·API 착수 가능**: 화면/필드/전이 최소 계약과 책임자 확인.
3. **기능 구현**: 실제 앱의 요청→처리→표시가 동작. 코드 존재만으로 판정 불가.
4. **검증 완료**: 실데이터·시연 브라우저·오류/상태 및 중요 회귀 QA 통과. 기존 QA 기록을 새 서비스 QA 완료로 대체하지 않음.

## 15. 팀 인수인계 — 지금은 요청사항을 보내지 않고 취합

**사용자 요청:** 김동조님에게 전달할 기술 요청은 지금 개별 전송하지 않고, 기획 합의가 끝났을 때 한 번에 공유하도록 취합한다.

| 담당 | 먼저 준비할 자료 | 확인·합의 시점 |
|---|---|---|
| 정민규(Product) | 기존 KONNECT 전체 기능 기준선·시니어 Delta·핵심 User Flow·QA 수용 기준 정리 | 지금 이 PRD를 기준으로 문서 관리 |
| 손희영(팀장·UX/UI) | **단일 홈 진입**, `Right now` 입력 안의 AI 음성 대화, 결과 지도+카드, 코스 결과/지도, My Pick/Route, 계정 기능에 임시 한국어 라벨 적용·시니어 접근성 검토 | **PRD만으로 핵심 화면 UI 착수 가능**. 구체 배치·상태 상세는 후속 화면명세 |
| 김동조(Tech) | 코드 재사용 허용 범위, 기존 B 대화/API 동작, 음성 PoC, 새 국문 데이터, 최소시간 충돌, B 저장 및 로그인/루트 QA | **요청 목록 취합 완료 후 일괄 전달**. 새 구현/기존 코드 재사용 수행 여부는 팀 규정 확인 후 |

### 일괄 전달용 미확인 체크리스트(임시 · 아직 전송하지 않음)

1. 최종 KONNECT 소스 기준 커밋과 실제 배포에 사용된 코드·환경의 일치 여부.
2. 운영진에게서 기존 프로젝트 코드/에셋/API 클라이언트 사용 허용 여부·공개 방식 확인.
3. **두 홈 진입을 하나로 축소**하고 `Right now`의 `Anything else?`에 B Guided Chat을 통합하는 동작. A/B 내부 로직/결과·지도·마커, Pick/Route, 로그인/온보딩/My Page 정상 회귀 여부.
4. 프론트 `60분`과 백엔드 `30분` 최소시간 정책 및 실제 배포 값 확인.
5. 브라우저 한국어 STT/TTS 2~3턴 PoC(권한 거부/무음/다시 듣기 포함), 대체 입력 경로 검증.
6. `/api/chat` 기반 **단일 입력 화면** 다중 턴/STT 연결, **출발지·시간 양방향 필드 동기화**, 코스 의도시 `/api/route` 연결, 결과→조건 수정→입력/대화 맥락 복귀. 신규 API 필요 시 사유·요청/응답 계약.
7. TourAPI/서울문화포털 국문 정보·참여대상·기간·운영·가격·예약·좌표·공식 링크의 실제 사용 가능 레코드 확인.
8. 이동 부담 계산의 신뢰 가능한 도보 경로/시간 정보와 데이터 없을 때의 `확인 필요` 처리.
9. B의 요청 날짜/시간 오반영·루트 개수·저장/재구성 실패, A의 가격·참여/운영 오판 및 0건/오류 회귀.
10. AI 응답 지연·비용·외부 키 노출 금지·개인정보 처리·시연 기기 지원.
11. **Q1 신정책**: 비회원 재추천/코스 요청 로그인 Gate 제거, `내가 고른 장소`/`내 나들이 코스` 계정 장기 저장·선호 사용 시 로그인·취소 후 이전 상태 보존.
12. **임시 한국어 UI 명칭**과 기존 영문 코드 식별자 매핑 및 실제 UI 적용 검토.

## 16. 변경 이력 및 남은 검수

- **v0.1:** 기존 KONNECT 일부만 선택적으로 도입, 음성/시니어에 집중. 지도+카드 누락 보완 후에도 B 루트·계정 등 주요 기능을 임의 후속 처리.
- **v0.2:** **최종 KONNECT 전체 구현 범주를 PRD 기준선으로 복원**. `Right now`(정확한 기능명), `Plan a route`, 상단 지도+하단 카드/마커 연동, 루트 지도·수정·저장, My Pick/Route, 로그인·온보딩·My Page, RAG/데이터/예외/번역까지 대응. **외국인→시니어/한국어/음성/외출 부담 변경만 Delta**로 표시. 과거 QA 문제·정책/코드 차이 명시.
- **v0.3(이번 수정):** **Q1 비회원 반복 추천·계정 저장 로그인, Q2 걷기 Soft/Hard 확인, Q3 Right now 단일 진입+Plan a route 기능 내장, Q4 음성·필드 양방향 동기화, Q5 결과→입력 Anything else? 복귀·맥락 보존** 확정 반영. 한국어 기본 메뉴를 임시 카피로 적용하고 검증·화면명세 항목을 갱신.
- **미확인 상태**: 이 문서는 코드와 기존 QA 자료를 읽어 정리한 **문서 대조본**이다. 모든 화면을 실제 브라우저로 반복 시연하거나 새 앱을 구축·테스트한 결과는 아니다.

**다음 산출물**: 이 PRD v0.3을 **팀에 우선 공유**하여 대기 없이 UI/기술 착수. 기존 LF 화면↔단일 진입의 새 화면 매핑, AI 음성·조건 수정·이동 부담 관련 상세 화면명세, 최소 API 계약 및 동조님 일괄 기술 검토 요청서를 후속 산출물로 작성한다. **PRD 공유를 화면명세서 완료 전까지 미루지 않는다.**
