## 3. S02 | 통합 입력·한국어 AI 대화

- **상태/우선순위:** [확정/기준 요구], 1차 선착수.
- **목적:** 사용자가 한 화면에서 위치·시간·관심 및 이동 조건을 말/글/직접 입력으로 제공하고, AI가 누락된 필수정보만 묻게 한다.
- **진입/연결:** S01 `나들이 찾기`; S03/S05 `조건 바꾸기`로 복귀. 확인 가능한 값이 준비되면 S02a → S03 또는 S05.
- **UI·표시 데이터:** 출발지(현재 위치 권한 또는 장소 직접 검색·선택), 출발 날짜, 출발 시각, 종료 시각; `더 원하는 게 있으세요?` 음성/텍스트 대화; 마이크 시작/중지, 전사 텍스트, AI 질문·답변 텍스트, 음성 재생/중지, 조건 요약, `나들이 추천받기`/수정. 시니어 친화적 큰 글씨·터치 영역·명료한 상태를 확보하되 수치 확정은 UX 담당.
- **선택 조건:** 문화 관심(전통문화/역사·궁궐/문화 체험/미술·전시/공연/축제·이벤트), 예산, 짧게 걷기, 실내외, 제외할 대상, 기존 일정 등. Hard/Soft 구분·UI 노출 방식 [미확인].
- **입력·검증:**
  - [기준 요구] 출발지와 날짜/시각·종료 경계는 추천 전 확인해야 함. 위치 거부/좌표 미확정이면 장소 수동 검색·확정 제공; **출발 좌표 임의 대체 금지**.
  - [기준 요구] 종료시각 임의 설정 금지. 과거 시간·종료가 시작보다 빠른 경우 등 시간 오류는 별도 검증·안내 [상세 정책 미확인]. 종료 날짜의 처리·자정 경계 [미확인].
  - [미확인] **최소 추천 시간 60분(UI 기준) vs 30분(기존 서버)**: 한쪽을 임의 채택하지 않음. 기술/제품 합의 전 해당 경계 테스트는 보류. 예시 14:00~17:00 3시간은 착수 시나리오로 사용 가능.
  - [확정] 말에서 인식한 출발 위치·날짜·시간은 같은 필드에 반영; 필드 수정 시 최신 수정값을 조건 해석·추천 요청에 사용. **사용자 확인 전 전사 후보를 확정 요청값으로 취급하지 않음.**
  - [확정] “많이 걷고 싶지 않아요”는 기본 Soft 선호. 명시적으로 상한/제외를 지정한 경우만 Hard. 안전에 중요한 모호함은 추가 질문하되 건강 상태를 추론하지 않음.
- **인터랙션:** `마이크`→권한 확인→발화→전사 내용 표시·필요 시 수정→AI 답변(텍스트+가능한 경우 TTS); 텍스트 보내기도 동일 조건 처리; AI는 필요한 항목만 질문. 준비 조건 충족 시 확인 상태(S02a)로 이동. `조건 바꾸기`로 돌아온 경우 기존 필드·대화·선택 이력을 보여주고 **변경분만** 반영. 추천/재추천 횟수에 따른 로그인 Gate 없음.
- **데이터·API:** 논리적 입력 `start_location`, `start_at`, `end_at`, `interests`, `budget_limit`, `mobility_preference`, `hard_constraints`, `excluded_places`, `existing_plans`, `request_kind`, `confirmed_fields`, `conversation_context`. AI 응답 개념 `assistant_text`, `need_clarification`, `missing_fields`, `updated_condition_draft`, `ready_to_search`. 실제 이름·타입·API 경로·호출 시점 [미확인].
- **상태·예외:** 대기/듣는 중/전사 확인/처리 중/음성 읽는 중/오류 [제안]. 마이크 미지원·권한 거부·무음·STT 실패→텍스트 전환; TTS 실패→화면 텍스트 유지. 네트워크 실패→기존 입력·대화 유지/재시도. 중복 요청·오래된 응답으로 최신 필드 덮어쓰기 방지.
- **완료 기준:** AC02~AC04, AC08, AC12~AC14: 위치 거부 후 수동 선택 가능, 전사/필드/최종 요청 일치, 부족 정보 확인, 재추천 시 조건·대화 보존, 음성 불가 시 텍스트로 결과 도달.
- **미확인/영향:** STT/TTS 공급원·권한과 호환성 → 김동조; 필드 상태·대화 API 계약 → 김동조+정민규+손희영; 최소 시간·날짜 경계 → 정민규+김동조. 각 요소의 개발/연결 전에 협의.

## 4. S02a | AI 조건 확인 (S02 내부 상태 **제안**)

- **상태/우선순위:** 제품의 조건 확인은 [기준 요구/확정], **독립 페이지가 아닌 S02 상태 또는 시트는 [제안]**.
- **목적:** AI가 해석한 의도/위치/시간/관심/이동 제약을 사용자가 확인·수정하고, 최신 확인값만 실제 추천 요청에 적용.
- **진입/연결:** S02 입력·대화 후 준비 상태→S02a. 부족/모호한 항목 발생→S02 대화로 복귀; 확인 완료→개별 장소 S03 또는 코스 S05.
- **UI·표시 데이터:** `개별 장소/여러 장소 코스` 요청 의도, 출발지, 날짜/시작/종료, 관심사, 걷기 선호 또는 Hard 조건, 추가 확인 필요 항목, `수정하기`, `확인하고 추천받기` [버튼 문구·형태 제안].
- **입력·검증:** 필수값/모호한 조건 및 위치 좌표 확인. 조건 불충분이면 다음 단계로 넘기지 않고 해당 필드·AI 질문에 포커스 [제안]. 유효 최소 시간 기준 [미확인].
- **인터랙션:** 항목 수정→S02 관련 입력에 반영; 확인→수정된 현재값 기반으로 추천 요청 시작. AI가 제시한 초안과 사용자가 확인한 최종값의 혼동 방지.
- **데이터·API:** 대화 Draft와 Confirmed Condition 구분 [제안]. 실제 상태 구조·검증 순서 [미확인].
- **상태·예외:** 미해결 항목, 조건 충돌, 검증 중, 통신 실패는 S02 데이터 보존 후 복귀. 연타 시 중복 추천 생성 방지.
- **완료 기준:** AC02/AC03/AC08/AC12: 확인 전후 필드 일치; 장소·코스 의도 맞게 분기; 입력 수정이 실제 요청에 반영됨.
- **미확인/영향:** 시트 vs 인라인 vs 별도 페이지 결정 → 손희영+정민규, S02/S03 연결 전. 데이터 Draft/Confirmed 경계 → 김동조+정민규, API 연동 전.

## 5. S03 | 개별 추천 결과 (지도 위·카드 아래)

- **상태/우선순위:** [확정/기준 요구], 1차 선착수.
- **목적:** 공식 근거에 따라 추린 문화활동 소수 후보를 지도·카드로 비교하고 자세히 확인하거나 조건을 바꿀 수 있게 한다.
- **진입/연결:** S02a 확인 → 추천 조회 → S03; 카드의 상세 액션→S04; `조건 바꾸기`→S02(기존 상태 보존).
- **UI·표시 데이터:** **상단 지도 + 하단 가로 카드**, 후보별 명칭/유형/주소/위치·운영/가격/예약/이동 근거·최대 0~2개 추천 이유·`조건 충족`/`추가 확인 필요`/`조건 완화 대안`, 공식 확인 필요 항목. `다른 곳 찾기`는 조건 기반 재조회 [버튼 정책 미확인].
- **입력·검증:** 추천은 명시적 Hard 조건 위반 후보를 정상 적합으로 표시하지 않음. **가격·예약·운영·이동 미확인은 무료·예약 불필요·방문 가능으로 표현 금지.** 좌표 없는 후보는 핀 임의 생성하지 않고 카드에서 정보 확인 가능하게 처리 [제안]. 실제 경로가 없으면 이동 시간 단정 금지.
- **인터랙션:** 지도 마커 선택→해당 카드로 포커스 전환; 카드 스와이프/선택→해당 마커 포커스. 카드 상세→S04. `조건 바꾸기`→S02. 카드 터치·스와이프 외 조작 대체(버튼/키보드) [접근성 제안].
- **데이터·API:** 후보 `id`, `title`, `address`, `lat/lng`, `status`, `reasons[]`, 운영·가격·예약·이동 정보, `checks_required`, `official_url`, `source_checked_at`는 **논리적 예시**이며 실제 응답 타입·키 미확인. 결과가 최신 확정 조건에 대응하는지 구분; 느린 이전 요청의 응답이 최신 결과를 덮지 않음.
- **상태·예외:** 로딩(중복 요청 방지), **정상 0건**(조건 조정 CTA), 시스템/외부 API 실패(재시도), 지도 표시 실패(카드 계속 제공), 일부 좌표·사진·공식 URL 누락(해당 요소만 미확인/비노출), 조건 완화 대안은 정상 충족 후보와 구별.
- **완료 기준:** AC05/AC06/AC12/AC14/AC16: 위/아래 배치, 마커↔카드 양방향 동기화, 사실·미확인 구분, 0건/오류 차별화, 조건 변경 복귀 및 갱신.
- **미확인/영향:** 지도 SDK·정확한 결과 키·상태 분류 → 김동조+손희영+정민규; 카드 건수 최대(기존 3~4 참고만) → 제품+기술, 화면/API 연결 전. 실제 추천 결과 수는 보장하지 않음.

## 7. S05 | 여러 장소 코스 결과

- **상태·예외:** 계산 로딩, 조건 충돌, 2곳 미만/유효 후보 부족, 경로 확인 불가, API 오류, 재생성 실패. 정상/확인 필요/대안 구분.

- **미확인/영향:** 코스 엔진의 운영·이동/체류 기준, 재계산 계약 → 김동조+정민규; 화면 레이아웃 → 손희영, 관련 기능 연결 전.

## 11. 데이터·API 합의 대기 목록 (개념 계약이며 구현 확정 아님)

### 입력과 상태
- **추천 요청 개념:** `request_kind` (`place`/`route`), `start_location`(출발지 식별자·표시명·확인된 좌표), `start_at`, `end_at`, `note`, `conditions`, `confirmed_fields`, `conversation_context`. 날짜·타임존 명시 필요. **키 이름·중첩 구조·자료형·필수 여부·HTTP 경로/메서드 모두 [미확인].**
- **AI 해석 개념:** `assistant_text`, `need_clarification`, `missing_fields`, `updated_condition_draft`, `ready_to_search`. 입력 필드·대화 초안·최종 확인값의 우선순위 협의 필요.
- **추천 응답 개념:** `candidates[]` 또는 `route(stops[])`, `status`, `reasons`, `facts`, `checks_required`, `official_url`, `source_checked_at`. 실제 후보 `id`·좌표·운영/가격/예약/참여·이동 정보는 **공식 출처 또는 미확인**으로만 처리.
- **브라우저 상태:** `demoSignedIn`·선호·저장 장소·저장 코스·온보딩 완료는 논리 개념; 브라우저 실제 키와 데이터 수명 [미확인].

### 개발팀 확인 없이는 확정하지 않을 것
1. 엔드포인트, 메서드, 필드명·자료형, 오류 응답 형식과 재시도 가능 여부.
2. 실제 문화정보/지도/경로 API 연결 성공·공식 데이터 필드 결측·확인 시각.
3. STT/TTS 브라우저·권한·지연·실패 시 동작.
4. 추천 최소 이용시간, 날짜/자정 경계, Hard 이동제약을 판정할 실제 경로 근거.
5. 코스 일정 계산·재생성·저장 복원, 오래된 응답 취소/무시 정책.
6. 실제 데이터와 Mock 구분, 기존 코드/디자인/에셋 재사용 허용 여부.

## 12. 화면별 구현 전달 패키지 — 즉시 복사·공유 가능

### A. 손희영 | UI 착수 요약 (팀 합의 전 **초안**)

- **S01:** 메인 CTA `나들이 찾기` 하나, 저장 결과·내 정보 진입, 데모 상태 표시.
- **S02:** 위치·날짜·시작·종료 입력 + `더 원하는 게 있으세요?` 한국어 음성/텍스트 AI 대화; 전사/AI 질문/필드 동기화; 음성 실패→텍스트 대체; 조건 변경 복귀 시 대화 보존.
- **S02a:** 최종 조건·누락·Hard/Soft 확인과 수정/확인. **S02 내 상태/시트는 제안**, 최종 표현 협의.
- **S03:** **지도 위+가로 카드 아래**, 지도 마커↔카드 양방향 포커스, 후보 상태·확인 필요, 0건/로딩/오류/지도 실패, `조건 바꾸기`.
- **S04~S07:** 상세·임시 선택 vs 저장, 2~3곳 코스, 체험용 로그인·선호/Skip/전체 초기화, 저장 재접근은 후속 범위로 보존.
- **선결 확인:** S02a 형태, S04 상세 형태, S06 로그인·온보딩 복귀 흐름, 실제 Figma 프레임. 확정 전 제안은 시안 표시.

### B. 김동조 | 개발 착수 요약 (팀 합의 전 **초안**)

- **첫 연결 흐름:** S02에서 사용자 확인값 생성 → 조건 구조화 및 실제 소스 조회 → S03의 최소 후보 구조 → 변경 조건 재조회. 추천 전 출발지 좌표/날짜·시간 검증.
- **대화/음성:** 말한 출발지·시각↔화면 필드↔실제 추천 입력 일치, 부족 정보만 질문, STT/TTS 실브라우저 테스트 및 텍스트 대체.
- **응답/근거:** 실데이터 1건, 실패·결측 1건을 출처·확인시각 포함해 제공. 0건과 API 실패 분리, Hard/Soft 구분, 미확인값 추정 금지, 좌표 없는 후보 핀 금지.
- **후속:** S05 코스 2~3곳 한 개·장소 제외 재계산 실패 시 이전 상태 유지; S06/S07 데모 로그인·브라우저 저장/복원/전체 초기화.
- **확인 요청:** 실제 HTTP 계약 및 필드·타입, 데이터 응답 품질, 최소 추천 시간, STT/TTS, 지도/경로 연동, Mock 정책. 재사용 코드는 운영진 승인 전 이식 금지.

### C. 정민규 | 명세·QA 인수인계 요약

- **우선 검증:** S01→S02→S02a→S03→S04 / 결과→S02 재추천, 음성 실패시 텍스트 대체.
- **핵심 수용:** AC01~AC07, AC12~AC14, AC16 중 해당 정상/실패/복귀 테스트를 실제 실행한 경우만 PASS 기록.
- **미결정 관리:** 아래 §13의 담당·영향·결정 시점을 정리하고, 관련 팀원 합의 전 기존 확정 정책을 변경하지 않음.
