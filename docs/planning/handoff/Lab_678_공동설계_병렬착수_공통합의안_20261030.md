# Lab 678 | 공동설계 및 병렬작업 착수 — 공통 합의안 v0.1

- 작성일: 2026-10-30
- 기준: `Lab_678_시니어_문화외출_독립형_PRD_v0.5_20261030.md`, `Lab_678_공동설계_운영지침_v1.1.txt`
- 상태: **팀 공동 확인용 제안**. 별도 표시 없는 `[확정]`은 제품 Q1~Q6의 확정사항이지, 담당자 간 API/디자인 세부 합의 완료를 뜻하지 않는다.
- 목표: 전 화면 설계 완료를 기다리지 않고, **조건 입력 → AI 처리·실데이터 조회 → 지도·카드 결과**의 수직 흐름을 먼저 동작시키면서 독립 모듈 병렬 개발을 진행한다.

## 1. 제품 흐름 — 변경 금지 기본선

**[확정]** 홈의 핵심 CTA는 **나들이 찾기 하나**. `S02`에서 출발 위치, 출발 날짜/시각, 종료 시각을 직접 입력하거나 한국어 음성·텍스트로 AI와 대화한다. AI는 이미 정해진 값을 반복 질문하지 않고 모호한 필수값만 확인한다. 전사·대화에서 추출한 값과 입력 필드, 실제 API 요청은 일치해야 한다. 

```text
S01 홈
  → S02 통합 입력/Anything else? 음성·텍스트 AI 대화
  → S02a 조건 확인(독립 페이지가 아닌 S02의 상태/시트로 구현 제안)
     ├─ 개별 장소 요청 → S03 상단 지도+하단 카드 → S04 상세/선택
     └─ 코스 요청 → S05 순서·시간·지도·장소 카드(2~3곳 한 코스)
S03/S05의 [조건 바꾸기] → S02(기존 조건·대화 보존)
장소/코스 저장 및 개인화 → S06 체험용 로그인·선호 → S07 내 정보/재접근
```

**[확정]** 결과 화면에는 별도 AI 채팅 패널을 추가하지 않는다. 실제 OAuth 없이 데모 로그인 버튼으로 상태를 전환하고, 사용자가 명시적으로 저장한 장소·코스·선호는 현재 브라우저 저장소에 보존한다. 비회원의 반복 추천·음성 대화는 제한하지 않는다.

## 2. 역할별 병렬 착수 — 팀 승인 전 업무 분장 제안

| 담당자 | 지금 바로 착수 | 첫 인계물 | 다른 담당자 기다릴 필요가 없는 범위 |
|---|---|---|---|
| **정민규 / Product** | S01→S02→S02a→S03→S04의 화면명세 초안, 대표 사용자 시나리오·버튼 전이·검증 | 화면명세 1차 + 질문·결정 로그 | 정책·필드 의미·문구 및 화면 동작 정의 |
| **손희영 / UX/UI·팀장** | S01 홈, S02 통합 입력+마이크/대화, S03 지도·카드 기본 프레임 | Figma 3화면 + 공통 상태 | 화면 목적·필수 구성요소는 확보됨. 실제 API 연결을 기다리지 않고 UI 구성 |
| **김동조 / Dev** | 개발 환경/실제 문화정보 API 도달 여부, 결과 공통 스키마, 한국어 STT/TTS 기술 스파이크 | 실데이터 조회 및 추천 응답 샘플, 음성 입력·출력 가능 여부 | 외부 API 테스트·로깅/시크릿 준비·독립 기술검증 |

**후속 병렬:** 손희영 `S04/S05/S06/S07`, 김동조 코스 판단·저장 상태·오류 처리, 정민규 해당 화면명세와 QA. **Q3 확정에 따른 코스 기능은 범위에서 삭제하지 않는다.**

## 3. 첫 번째 수직 시연 시나리오 [제안·팀 확인 필요]

> “청량리역에서 내일(10월 31일) 오후 2시부터 5시까지 전시를 보고 싶어요. 가까운 곳이 좋겠어요.”

1. S02 음성·텍스트 입력 → `출발지/2026-10-31 14:00~17:00/전시/가까움(Soft)` 추출·필드 동기화.
2. 필요한 출발일·위치 근거를 확인하고 사용자가 `추천받기` 선택.
3. 실제 소스 조회·판정 → 신뢰 가능한 **소수의 개별 장소 후보** 반환.
4. S03에 **지도 위/카드 아래** 표시. 마커↔카드 포커스 변경.
5. `조건 바꾸기` → S02 복귀; 이전 입력·대화 유지; 재추천 후 실제 결과 갱신.

*이 시나리오는 구현 검증용 예시이며, 특정 장소·결과 수·운영시간·경로 가능성을 보장하지 않는다.*

## 4. 화면 합의 표(1차 착수용)

| ID | 분류 | 주요 요구 | 우선 착수 |
|---|---|---|---|
| S01 | 화면 | 단일 핵심 진입, 데모 로그인 상태, 저장 재접근 | 즉시 |
| S02 | 화면 | 위치·날짜/시작/종료 입력, Anything else? 음성·텍스트, 수정·요청 | 즉시 |
| S02a | S02 내부 상태 [제안] | AI가 이해한 조건, 미확인·충돌, 수정·확인 | 즉시 |
| S03 | 화면 | 위 지도+아래 카드, 로딩/0건/실패, 조건 바꾸기 | 즉시 |
| S04 | 화면/상세 상태 | 정보·추천 이유·확인 필요·공식 링크, 임시 선택/명시 저장 | 다음 |

**상태 설계 원칙:** 로딩·음성 권한 거부·인식 실패·API 실패·정상 0건·입력 오류를 각 UI 상태로 분리한다. 별도 풀페이지인지 인라인 상태인지는 UX/UI 결정.

## 5. 실제 연동을 막지 않기 위한 최소 인터페이스 체크(잠정)

1. **S02→추천 요청:** `request_kind: "place"|"route"`, `start_location:{label,lat,lng}`, `start_at`, `end_at`(날짜·시각과 타임존 포함), `note`, `conditions`, `confirmed_fields`.
2. **AI 질의 결과:** `assistant_text`, `missing_fields`, `updated_condition_draft`, `request_kind`, `ready_to_search`. 전사 내용과 실제 적용 필드는 사용자 확인 전 확정하지 않는다.
3. **추천 후보:** `id`, `title`, `address`, `lat`, `lng`, `status`, `reasons[]`, `opening_info`, `price_info`, `reservation_info`, `mobility_info`, `official_url`, `checks_required[]`, `source_checked_at`.
4. **코스 결과:** `stops[]`(후보+방문순서+계획시각), 구간 이동·전체 비용 확인상태. 모르는 값은 `null`/`미확인`, 추정 생성 금지.
5. **상태값:** `ready`, `need_input`, `no_results`, `error` 등은 **개념 수준**이며 실제 HTTP 경로·필드·상태명은 김동조 제안 후 공동 확정한다.

**데이터 원칙:** 실 API 데이터와 화면 개발용 Mock은 반드시 표시·구분한다. 외부 API 장애 시 Mock으로 바꾸어 놓고 실제 연동 성공으로 보고하지 않는다. 기존 프로젝트 코드·에셋 재사용은 운영진 허용 범위를 확인할 때까지 확정하지 않는다.

## 7. 인계·통합·검증(모든 상세 문서 완료를 기다리지 않음)

- UI: S01·S02·S03 화면 프레임 준비 즉시 URL/스크린샷 및 인터랙션 상태 공유.
- Dev: 1건의 실제 소스 응답 샘플, 1건의 실패 응답, 음성 STT/TTS 지원 테스트 결과를 전달. 실제 연결 못 했으면 그 사실을 표시.
- Product: S01/S02/S03의 버튼·전이·검증조건을 먼저 전달하고, 이어 S04/S05/S06/S07 순으로 화면명세 보강.
- 병합 전: 코드/파일 소유권·브랜치/PR 절차는 **TEAM_WORKFLOW.md 확인 후** 따른다. 공통 파일 변경은 담당자 합의 선행.
- **첫 통합 통과:** 조건 입력/해석→유효 API 응답→지도·카드 렌더→조건 바꾸기 복귀. 이어 STT/TTS, 코스 2~3곳, 데모 저장·초기화, 오류·0건 순으로 회귀 검증.
