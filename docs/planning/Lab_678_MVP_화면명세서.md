## 0. 화면 설계 핵심 원칙

1. **서비스명 `오늘 나들이`**는 유지. 캐릭터는 홈에 들어오자마자 나들이를 제안하지만 실제 OS 푸시를 보내지는 않는다. [H01]
2. 말/글 입력을 동등하게 취급. AI가 활동·기분을 우선 파악하고, 출발지·날짜·시간 중 **없는 것만** 질문한다. [H02/H03/H09]
3. 정보가 충분하면 전체 요약·승인 화면을 매번 거치지 않고 검색. 이미 확정한 값과 **새 입력이 충돌할 때만** 변경 전후를 확인한다. [H04 + 기존 D09]
4. 결과는 **S02 안에서 최대 3개 세로 추천 카드**로 보여준다. 카드 기본 행동은 상세 보기. [H05~H07/H18]
5. 상세의 **큰 지도 보기**, **보조 내 나들이에 저장**이 기본 행동. 실제 경로 계산이 성공했을 때만 보행시간 표시. [H12/H18]
6. 방문 필수 운영/예약 정보 미확인 후보는 기본 추천에 넣지 않는다. **최초 0건·추가 0건·API 실패를 구분**한다. [H11 보완]
7. 로그인 없이 추천·상세·지도까지 탐색, 저장 시에만 원클릭 체험 시작. 장소·선호는 해당 브라우저 저장, 전체 대화 기록 영구 저장 안 함. [H13/H14/H19]
8. AI의 음성 답변은 텍스트와 함께 제공하고 끄기 가능. **한 번 시작한 자동 턴 대화 우선**(기술 미확인), 실패 시 큰 버튼형 입력. [H15/H16]
9. 이동 부담을 시니어라는 이유만으로 단정하지 않는다. 가까운 장소 우선, 사용자가 걷기·거리 선호를 말하면 반영. [H17]
10. 기존 S05(다중 장소 코스), S06 전체 삭제·선호, S07 저장 내역을 무단으로 폐기하지 않는다. 새 흐름 연결과 구현 우선순위는 [팀 검토 대기].

## 2. P0 화면별 상세 명세

### S01 | 홈·캐릭터 첫 인사

- **상태:** 캐릭터 즉시 등장·나들이 권유 [H01 기획 확정]. 새 버튼/레이아웃 [UX 세부 미확인].
- **우선순위:** P0 [제안].
- **목적:** 조작을 헤매지 않고 캐릭터에게 나들이에 대해 바로 말하거나 글로 이야기하도록 돕는다.
- **진입/연결:** 서비스 최초 로딩/돌아오기 → S01. 음성 시작→S02, 글자 입력→S02, 내 정보→S07.
- **UI/데이터:** 캐릭터(화면을 가리지 않는 위치), 큰 인사말, **'말로 대화 시작하기'** 강조 버튼, **'글자로 대화하기'** 대체 경로, 음성 켜짐/꺼짐 상태, `내 정보` 또는 `내 나들이` 접근. 저장 장소가 있을 때만 홈 저장 미리보기(기존 D06).
- **입력/검증:** 홈 첫 방문에서 마이크·위치 권한 자동 요청 금지. 음성 시작 버튼을 누른 뒤 마이크 권한 요청. 현재 위치는 S02에서 사용자가 명시 선택했을 때만 요청.
- **동작:** 음성 시작→권한 요청→허용이면 S02 ‘듣는 중’, 거절이면 큰 버튼형/텍스트 대체 설명. 글자로 시작→S02 텍스트 포커스. 내 정보→비로그인도 S07로 이동.
- **API/저장:** 현재 브라우저 저장 항목 유무 확인, STT 시작/권한(구현 방식 미확인).
- **상태/예외:** 최초, 복귀, 저장 내역 있음/없음, 음성 권한 거부/미지원, 체험 모드 표시 [미확인].
- **완료:** 캐릭터가 보이고 음성 또는 텍스트로 S02 진입; 불필요한 권한 팝업 없음; 저장 목록 없을 때 허위 미리보기 없음.
- **미확인·변경 영향:** 홈 CTA 기존 `나들이 찾기` 텍스트와 음성 시작 버튼 배치(손희영), 실제 브라우저 마이크 정책(김동조), Figma S01 프레임 대응(정민규·손희영).

### S02 | AI 대화·조건 수집·재추천

- **상태:** 한국어 자유 음성/텍스트, 기분·관심 우선, 누락 조건 질문, 재추천 중 조건 유지 [H02/H03/H08/H09/H10/H15/H16/H17/H20 기획 확정; 구현·기술 검증은 미확인].
- **우선순위:** P0 [제안].
- **목적:** 대화로 문화 관심과 가능한 방문 조건을 정한 뒤 실제 문화 장소를 추천받는다.
- **진입/연결:** S01에서 새 대화; S04/S08에서 뒤로 오면 대화·추천 맥락 보존. S03은 S02 안 결과 상태. S05 코스 연결 [팀 검토 대기].
- **UI/데이터:** 캐릭터 대화 버블, 큰 텍스트 입력창, 마이크 상태/음성 끄기, 음성 시작·종료, 발화 전사·정정, 필요 시 출발 위치/날짜/시각 선택 UI, **현재 위치 사용**(직접 요청 시), 조건별 최신 확정값. 추천이 준비되면 S03 카드가 같은 대화에 등장.
- **입력·검증:** 활동·기분 중심, 출발지·방문 날짜·시간 중 누락/모호한 필수값만 요청. 이미 한 문장에 제공했으면 중복 질문 금지. 기존 확인값을 바꾸는 입력은 변경 전후 확인. 좌표 해석 실패 시 다시 질문, 임의 서울 좌표 금지. 기존 최소 가용 60분 정책 유지, 종료시간 획득·검증 구현은 [미확인]. 입력 선택 UI 오류는 관련 필드 바로 아래 안내(기존 D13).
- **인터랙션:** `사용자 발화/전송`→AI 파싱·조건 상태 갱신→불충분하면 S02a로 질문→충분하면 **별도 전체 확인 버튼 없이** 장소 검색→S03 인라인 카드. `더 가까운 곳`→거리 조건만 변경해 재추천. `다른 곳`→같은 조건으로 새 후보 시도. 조건 변경은 H08에 따라 자연어로 변경한 값만 반영한다. H10에 따라 문화 나들이와 무관한 질문은 짧게 답하고 나들이로 복귀한다.
- **음성 상태:** 준비→듣는 중→전사→AI 응답(TTS+텍스트)→다시 듣는 중(지원 브라우저에서). 말하는 중 마이크 입력을 일시 정지하여 자기 음성 재인식 방지. 음성 끄기 선택 시 이후 자동 재생하지 않음. 자동 턴 기술 실패→큰 마이크 버튼으로 매 발화 시작. 텍스트 입력은 계속 사용 가능.
- **API·계약 [논리적 예시]:** `message/text`, `recognized_text?`, `conditions_state`, `confirmed_fields` → `assistant_text`, `condition_patch`, `missing_fields`, `ready_to_search`; 실제 엔드포인트·스키마는 김동조 확인. 사용자 입력 vs 대화 파싱 최신값 경합 처리 필요.
- **상태/예외:** 처음, 음성 권한 거절, 듣는 중, 무음/인식 실패, AI 생성 중, 중복 요청 방지, 필수조건 누락, 위치 지오코딩 실패, 추천 API 실패, 사용자가 음성 답변 끔.
- **완료:** 모든 조건 한 번에 입력해도 바로 추천, 위치만 누락 시 위치만 질문, 59분/60분 규칙 확인(종료시각 계약 확정 후), 조건 변경 시 나머지 조건 보존, TTS 실패해도 텍스트 유지, 이전 늦은 응답 무시.
- **미확인:** 연속 음성 브라우저 지원·STT/TTS 경합(김동조+손희영), 종료시각 수집 정책(정민규+김동조), 위치 지오코딩(김동조), 대화 UI·마이크 상태(손희영).

### S02a | S02 내부 보완·충돌 확인 상태

- **상태/형태:** **필요할 때만 노출**. 별도 페이지·항상 노출되는 최종 조건 검토창 아님 [H04/H09].
- **목적:** 예약/시간/출발지 등 필수값이 빠지거나 사용자가 이전 값을 바꾸는 경우 정확히 확인한다.
- **진입/연결:** S02가 누락·모호·충돌을 감지하면 S02a 발화/선택 UI 표시 → 해소되면 다시 S02에서 자동 추천.
- **UI:** 한 번에 필요한 질문 한 가지, 확인 가능한 큰 버튼/위치·시간 선택 UI, 기존값·새값(충돌일 때), 수정/취소.
- **인터랙션:** 확인→새 값 반영; 취소→이전 확정값 보존. 필요한 정보 전부 확보 후 추천 API 실행, 반복적인 전체 요약 승인 없음.
- **검증/예외:** 불명확한 장소명을 근거 없는 좌표로 변환하지 않음. 조건 충돌 해결 전 잘못된 추천 실행 금지.
- **API:** `missing_fields`, `need_clarification`, `previous_value`, `proposed_value` 등 논리 계약 [미확인].
- **완료:** 확정값 충돌은 승인 없이 덮지 않음; 값이 완비되면 전체 확인 단계를 다시 강제하지 않음.
- **미확인:** 인라인 질문 및 버튼·필드 배치(손희영), 조건 패치 승인 상태(김동조).

### S03 | S02 안의 장소 추천 카드 상태

- **상태:** **기존 별도 결과 화면 S03을 인라인 상태로 변경** [H05/H07]. `S03` 식별자 자체는 기존 문서 추적용으로 유지.
- **우선순위:** P0 [제안].
- **목적:** 캐릭터의 설명을 들으며 0~3개의 방문 가능한 후보를 비교해 상세로 이동한다.
- **진입/연결:** S02 필수 조건 확정→자동 추천 호출→대화창에 S03 카드 표시; 카드 `상세 보기`→S04; 자연어 조건 수정→S02 조건 처리.
- **UI:** 캐릭터의 간단한 추천 안내, **최대 3개 카드 세로 표시/스크롤**, 장소명·사진(있을 때)·주소·짧은 추천 이유·확인된 운영/예약 정보, **카드 CTA `상세 보기`만**. 카드에 지도를 별도 버튼으로 두지 않음.
- **데이터 검증:** 실제 장소 ID·명칭·좌표 필수. 방문 날짜·시간에 맞는 운영기간/운영조건과 필요한 예약조건을 검증할 근거가 없으면 **기본 추천 제외**. 가격은 확인값만 표시, 유료 여부 확정 안 됐으면 무료라고 쓰지 않음. 후보 부족 시 억지 채움 금지. '운영 확인'은 실시간 입장 보장과 다름.
- **행동:** 상세 보기→S04, 뒤로→S02의 이전 카드·스크롤 상태 보존 [복원 방식 제안]. `가까운 곳`, `다른 곳` 음성/텍스트→S02에서 재추천, 기존 조건 보존.
- **API [제안]:** 추천 요청은 출발 위치 좌표, 방문 날짜·시간, 관심 활동·기분, 선택적 걷기 제약 및 제외 장소 목록. 응답은 `candidates[]` 최대 3, 각 `id,name,lat,lng,address,verified_visit_info,reasons` 등. 백엔드 실 필드/검증 수준 [김동조 미확인].
- **상태/예외:** 로딩, 정상 1~3개, **첫 추천 0건**(대화에서 조건 변경 권유), **재추천 0건**(기존 카드 보존 + 신규 없음 안내), API 실패(0건과 별도), 검증 정보 누락 후보 제외, 뒤늦은 이전 응답 무시.
- **완료:** 0~3개/허구 후보 없음, 카드 세로 배치, 카드가 상세만 연결, 첫 0건/추가 0건/API 실패 구별, 기존 카드 보존.
- **미확인:** 카드 크기·스크롤 감도·캐릭터 노출 밀도(손희영), 검증된 후보 확보 가능 수/필터(김동조).

### S04 | 장소 상세·지도·저장 진입

- **상태:** 카드 선택 후 상세 화면, **지도 보기=주 행동 / 내 나들이에 저장=보조 행동** [H06/H18].
- **우선순위:** P0 [제안].
- **목적:** 해당 장소가 언제, 어떻게 방문 가능한지 확인하고 지도 또는 저장으로 이어진다.
- **진입/연결:** S03 `상세 보기`→S04. `지도 보기`→S08, `내 나들이에 저장`→S06(체험 미시작 시) 또는 현재 브라우저 저장. 뒤로→S02의 추천 결과 복원.
- **UI:** 장소명·사진·유형·주소·행사/운영 기간·방문 날짜 관련 정보·예약/참여 대상 확인 결과·가격(검증된 경우)·추천 이유·출처/확인 기준, 눈에 띄는 **'지도 보기'**, 보조 **'내 나들이에 저장'**. 저장됨 상태·내 정보에서 보기.
- **검증:** 위 정보의 출처가 확인된 범위만 사실로 표시. 예약이 필요하고 실제 예약완료/잔여가 확인되지 않았다면 보장하는 문구 금지. 빠진 비필수 정보는 확인되지 않았다고 설명 가능하나, 방문 필수 정보 누락 후보는 S03 기본 추천에 등장하면 안 됨.
- **행동:** 지도 보기→S08(출발지 좌표 확인 후 경로 요청). 저장 클릭→S06 원클릭 체험 시작(미로그인)→저장 행동 자동 1회 실행→S04 유지/저장됨. 저장 취소→저장하지 않고 S04 유지. 저장 중 중복 클릭 차단.
- **API:** 장소 ID로 상세 정보 조회, 원본 출처·검증 날짜, 좌표, 실데이터 여부. 저장 데이터는 현재 브라우저에 기록.
- **상태/예외:** 상세 로딩 실패, 근거 변경·재검증 실패, 지도 이동 불가(목적지 좌표 없음은 추천 필터에서 막아야 함), 저장 실패, 저장 완료, 저장 중복.
- **완료:** 큰 지도 보기·보조 저장, 비회원도 상세/지도 이용, 저장 요청 시 단 한 번 저장, 저장 성공 후 상세 유지, 데이터 미확인 사실을 허위 안내하지 않음.
- **미확인:** 종전 `이 장소 선택` 독립 행동 유지 여부 [정민규+손희영], 장소 사진/공식 URL 정보 밀도(손희영), 상세 조회 재검증 계약(김동조).

### S08 | 내부 지도·보행 경로 [신규 ID 제안]

- **상태:** TMAP 보행 경로 재사용 우선 **[H12 기획 확정·기술 미확인]**. S08 ID는 Figma 대조 후 확정.
- **우선순위:** P0 기술 검증 조건부 [제안].
- **목적:** 선택한 장소를 찾아갈 때 출발지와 목적지, 가능한 경우 보행 경로·예상 시간을 보여준다.
- **진입/연결:** S04 `지도 보기`→S08. 뒤로→S04. 출발지가 없거나 불명확하면 S02에서 확인/수정한 뒤 경로 요청.
- **UI:** 지도 영역, 정확한 출발지 라벨·목적지 라벨, 경로 폴리라인(성공한 경우), **예상 보행 시간**(API 응답 기준), 길찾기 불가 안내·재시도. 외부 지도 연계 버튼은 fallback [팀 결정 필요].
- **검증:** 출발지·목적지 좌표 모두 실제 확인값이어야 API 요청. 경로 계산 실패/미응답이면 **추정 소요시간과 가짜 경로를 출력하지 않음**. 직선 거리=보행 시간으로 안내 금지. 현재 위치 권한은 사용자가 `현재 위치 사용`을 선택할 때만 요청.
- **인터랙션:** 진입→경로 요청→성공 시 지도 선·소요시간/실패 시 오류·재시도. 경로 문제로 장소 상세 접근이 막히지 않게 뒤로 제공.
- **데이터/API [논리 계약]:** `origin{lat,lng}`, `destination{lat,lng}` → `geometry`, `walk_minutes`, `status`, `source`. TMAP 실제 요청·권한·요금·키 노출/오류 계약은 김동조 검증.
- **상태/예외:** 로딩, 성공, 경로 없음, 인증/쿼터 오류, 네트워크 오류, 지도 타일 오류, 출발지 미확인. API 정상 0건과 연결 오류 구별.
- **완료:** 실좌표 기반 보행 경로·시간만 표시, 실패 시 과장 없는 안내, 상세로 되돌아갈 수 있음. 기술 실패 시 축소안을 팀 승인 후 적용.
- **미확인:** 코드 재사용·API 권한·에러 방식(김동조), 지도 SDK와 반응형 배치(손희영), 대체 외부 지도 링크의 최종 승인(세 명 공동).

### S06 | 원클릭 체험 모드·선호·초기화

- **상태:** 실제 계정 아님, 저장을 누른 순간에만 모드 시작 권유 [H13/H19]. 기존 D03/D18~D20의 저장 자동 완료·전체 삭제 기본선은 유지.
- **우선순위:** 장소 저장과 함께 병렬 [제안].
- **목적:** 계정 생성 없이 현재 브라우저에 나들이 장소와 간단한 선호를 기록한다.
- **진입/연결:** S04 저장 요청(체험 전)→S06; S07 선호 설정/체험 종료→S06 관련 상태. 체험 시작 성공→S04로 돌아가 원래 저장을 정확히 한 번 수행; 취소→S04 무저장 복귀.
- **UI:** **'체험 시작하기'** 큰 버튼, `이 기기·브라우저에서만 저장되고 실제 계정이 아닙니다` 안내, 취소, 관심사 선택(선택사항), 체험 종료 및 데이터 삭제 확인. 실제 소셜 인증/이메일/전화번호 입력 없음.
- **입력/검증:** 저장할 장소 ID의 유효성, 원래 저장 요청 맥락 유지, 중복 저장 방지. 선호 조건은 미설정·복수 선택 가능. 전체 대화 로그 영구 저장 금지.
- **행동:** 체험 시작→로컬 체험 상태 활성화→**원래 저장 요청 자동 1회 완료**→S04로 복귀·저장됨. 초기 선호 설정으로 저장 지연 금지; 저장 후 `관심사 설정하기/나중에` 선택적으로 제안(기존 D19/D20). 체험 종료는 확인 후 데이터 초기화; 취소 시 유지.
- **API/저장:** `demo_active`, `saved_places[]`, `preferences`, `pending_save_id`는 개념 명칭, 구체 키·형식·마이그레이션 [김동조 협의]. 네트워크 인증 호출 금지.
- **상태/예외:** 체험 미시작, 시작 완료, 저장 중, 저장 실패, 스토리지 사용불가/Quota, 관심사 미선택, 삭제 확인·완료·실패.
- **완료:** 저장 요청은 로그인 완료 뒤 한 번만 저장, 같은 브라우저 새로고침에서 복원, 다른 기기 동기화 없음, 대화 원문 영구 저장 안 함, 초기화는 확인 때만.
- **미확인:** 모달 vs 화면 형태(손희영), 저장 스키마·초기화 범위·고장 대응(김동조), 음성 전사/대화 임시 메모리 수명과 삭제 정책(정민규+김동조).

### S07 | 내 정보·내 나들이

- **상태:** 비회원도 진입, 세로 섹션형(기존 D04/D05), 장소·선호 저장(H14/H19). 코스 저장 항목은 기존 요구로 유지 [팀 검토 대기].
- **우선순위:** 저장과 병렬 [제안].
- **목적:** 나중에 마음에 든 장소를 다시 찾고 간단한 취향을 관리한다.
- **진입/연결:** S01 `내 정보/내 나들이`→S07, S04 저장 후 `내 정보에서 보기`→S07, 장소 선택→S04.
- **UI:** 세로 섹션 '내 나들이(저장 장소)', '선호 조건', '체험 모드', '체험 종료/삭제'. 기존 코스 저장 목록은 유지 필요 여부/연결을 별도 팀 검토. 비회원은 빈 상태 및 체험 안내.
- **입력/행동:** 저장 장소 누르면 상세, 선호 선택/수정/초기화, 체험 종료 요청 시 확인창. 선호만 초기화할 때 저장한 장소를 삭제하지 않음.
- **검증:** 저장된 장소를 다시 열면 과거 저장 당시 정보가 현재 운영 조건을 보장하지 않음을 알리고 필요 시 조회/검증. 장소·선호가 다른 브라우저와 연동된다는 설명 금지.
- **API/저장:** 로컬 저장된 ID/선호 조회, 상세 조회는 해당 시점 실데이터 조건에 맞춰 재검증. 서버 인증 없음.
- **상태/예외:** 비회원/빈 목록, 저장 장소 있음, 저장 읽기 실패, 장소 정보 변경, 선호 미설정, 전체 삭제 취소/완료.
- **완료:** 비회원 진입, 저장 항목 선택 가능, 새로고침 복원, 초기화 후 홈 미리보기와 목록 모두 비움.
- **미확인:** 기존 `내가 고른 장소` vs 신규 `내 나들이` 문구 정리(손희영+정민규), 코스 섹션 연결(팀), 재검증 방식(김동조).

### S05 | 다중 장소 문화 코스 결과 [기존 요구 유지·새 UX 연결 미확인]

- **상태:** 기존 v0.2.1에서 2~3개 장소 한 코스·제외 예정→명시 재생성·저장 정책은 유지. 추가 UX 결정 H01~H20은 **다중 코스 삭제를 승인하지 않았음**.
- **우선순위:** P0/P1 및 구현 여부는 [팀 검토 대기].
- **목적:** 여러 문화장소를 순서와 시간에 맞게 확인하고 코스로 저장한다.
- **진입/연결 [기존]:** S02가 복수 장소 요청을 해석→조건 검증→S05 결과. 추가 H 결정과의 연결 방식은 [팀 검토 대기].
- **UI/데이터 [기존]:** 순서 있는 2~3곳, 예상 시간과 이동 근거, 지도, `이 장소 제외`, `제외 예정` 취소, `코스 다시 만들기`, `조건 바꾸기`, 코스 저장.
- **인터랙션 [기존]:** 제외 버튼만 누르면 즉시 재생성하지 않고 제외 예정으로 표시; 명시적 재생성 후 새로운 유효 코스만 갱신; 실패하면 이전 유효 결과 보존.
- **검증/예외:** 방문 기간·운영·예약에 대한 H11 보완 필터를 코스의 각 장소에도 적용할지 [팀 검토 대기]. 2곳 미만 코스를 유효한 2~3곳 코스라고 표현하지 않음.
- **API:** 기존 `route(stops[])`, 시간·구간 검증 등 재사용 [실제 계약 미확인].
- **완료:** 기존 요구를 변경 없이 임의 삭제하지 않았는지 추적; 개발·시연 포함 범위와 데이터 검증 상태를 팀에서 확정.
- **미확인:** S05 유지 또는 후속 이관 승인 여부(세 명 공동), 신규 캐릭터와 전이/지도 연결(손희영), 코스 데이터 검증(김동조).

## 4. 논리 데이터·이벤트 계약 [제안, 실제 API 확정 아님]

| 이벤트 | 입력 | 성공 시 UI | 실패 시 UI |
|---|---|---|---|
| 대화 전송 | 발화/텍스트, 현재 조건·확정 필드 | 답변, 누락값 질문 또는 추천 시작 | 오류 안내·조건 유지 |
| 좌표 확인 | 사용자가 말한 장소 또는 선택 주소 | 표기 이름·확인 좌표 반영 | 위치 다시 질문/선택 UI |
| 현재 위치 사용 | 명시 버튼 클릭 후 권한 | 출발지 좌표 반영·확인 | 수동 입력 유도 |
| 추천 요청 | 출발 좌표, 방문일·시간·관심사·선호 | S02 내부 0~3개 카드 | 0건/실패 구분 |
| 상세 조회 | 장소 고유 ID | 출처·운영·예약 근거 및 지도/저장 CTA | 오류 안내·뒤로 |
| 보행 경로 요청 | 출발·도착 확정 좌표 | 지도 경로+예상 보행시간 | 지도 오류·재시도, 숫자 미표시 |
| 저장 | 유효 장소 ID, 체험 상태 | 로컬 저장·S04에 저장됨 표시 | 저장 실패·재시도 |

**백엔드 수신·응답 필드명, HTTP 경로, 요청 시점, 캐시, STT/TTS 연동 방식은 동조님 최종 확인 후 공통 인터페이스 계약에 기록한다.** 프론트에서는 Mock과 실 API 화면 표시를 구분해야 한다.

## 6. 담당자별 즉시 전달 요약

### 손희영 | UX/UI·프론트

- **바로 착수:** S01 홈 캐릭터+음성 시작, S02 채팅·음성 상태, S03 대화 내부 **세로 카드 최대 3개**, S04 큰 지도 보기/보조 저장, S08 경로 성공/실패.
- **디자인 미결정:** 기존 홈 CTA 문구와 새 음성 버튼 병치, S02→S03 스크롤, 음성 켜기/끄기 상태, S08 ID/Figma 대응, 기존 임시 선택 CTA 존치.
- **상태 시안:** 빈 추천/추가 0건, API 실패, 음성 미지원, 지도 경로 실패, 저장 안내 및 성공.
- **기존 Figma 프레임을 덮어쓰기 전:** 문서상 변경점을 별도 비교해 확인. 기존 S03 지도+가로 카드가 최신 UX가 아님을 표시.

### 김동조 | 백엔드·API·배포

- **바로 검증:** TourAPI/서울문화포털의 날짜별 운영·예약 근거 확보 가능 여부, 조건 파싱/패치, 내부 TMAP 경로, 연속 STT·TTS 자동 전환 및 fallback.
- **우선 계약:** 대화 조건(최신값·충돌), 추천 0~3개(방문 검증 근거), 상세 조회, 보행 경로 상태, 브라우저 저장 계약(프론트와 합의).
- **위험:** 검증 가능한 장소가 0개일 수 있음, STT 자기 음성 재인식, TMAP 재사용 권한·기존 코드 의존성, 과거 응답 경합, 마이크/위치 권한 거부.
- **주의:** 기존 코드 동작 보고와 현재 서비스 통합 PASS는 구분. API 키/토큰·개인 위치/음성 원문 로그를 공개 저장소에 포함하지 않음.

### 정민규 | Product·화면명세

- 이번 H 결정 1~20의 확정 근거 유지, 기존 D 결정과 충돌 매핑. S08 신규 ID와 Figma 매핑 합의.
- **팀 확인 우선:** S05 코스 유지·우선순위, S04 `이 장소 선택` 존치, 60분 정책 관련 종료시각 취득, 외부 길찾기 fallback 승인.
- 타깃 표현은 '1인 가구 대표 사례'와 '서비스 이용 대상'을 구분. 사회적 고립 개선을 검증된 효과로 주장하지 않음.
