## 0. 타깃·문제정의와 화면 설계 원칙 (기획 정리본 반영 · 팀 검토 대기)

**브랜드 표기 [사용자 확인]:** 서비스명은 **‘오늘 나들이’**이며 홈 CTA는 **‘나들이 찾기’**다. 서비스명을 바꾼다고 기존 S01~S07의 화면·행동 구조를 변경하지 않는다.

> **출처·상태:** 2026-10-31 `Lab 678 | 타깃·문제정의 최종 정리본 v1.0`에 따른 **[기획 정리본·팀 검토 대기]**. 문서에는 1인 시니어 가구의 대표 사례·우선 검증 역할에 대해 **손희영님의 구두 찬성**을 기록했지만, 타깃·문제정의 문구 전체는 **팀 문서 검토 후 PRD 반영 예정**이다. 아래 방향을 Lab 678 전체 승인이나 검증된 서비스 효과로 표기하지 않는다.

- **서비스 출발점:** 사회적 교류·외출 기회가 줄어드는 시니어에게 새로운 문화·여가활동을 경험할 계기를 제공하고자 한다. 이는 **기획 동기**이며, 서비스가 사회적 고립을 감소시켰다는 **효과 입증**은 아니다.
- **핵심 타깃:** 문화·여가활동을 해보고 싶지만 장소 탐색과 시간·거리·걷기·참여 조건을 살펴 **나들이를 선택하고 결정하는 과정**에 부담을 느끼는 시니어.
- **대표 사례·우선 검증 집단:** **1인 시니어 가구**. 다만 **혼자 살아야 이용할 수 있는 서비스가 아니며**, 부부·동행 시니어도 이용 가능하다. 1인 거주 여부를 가입/추천의 필수 조건이나 이용 제한으로 두지 않는다.
- **적용·검증 범위:** **서울 생활권 우선 검증**. 이를 전체 서비스의 지역 접근 제한이나 서울 외 이용 불가로 자동 해석하지 않는다. 실제 조회 가능 지역·시연 데이터 범위는 기술·팀 합의가 필요하다.
- **직접 해결하는 문제:** 문화 정보의 양적 부족이나 고립 자체가 아니라, **문화나들이를 선택하고 방문을 결정하는 과정의 부담**.
- **핵심 경험:** **말하고**(S02 음성·텍스트로 장소·시간·관심/이동 부담 전달) → **확인하고**(S02a/S03/S04에서 누락 조건 및 운영·예약·이동의 근거·미확인 확인) → **선택한다**(S03/S04의 지도·카드, S05의 2~3곳 코스 비교·선택·조건 변경).
- **화면·카피 작성 원칙:** 혼자 사는 사람 전용, 모든 시니어가 디지털 사용이나 보행에 어려움이 있다는 전제, 예약·방문 가능성 보장, 사회적 고립 감소 효과의 입증을 암시하지 않는다. `새로운 외출의 계기`와 `결정 부담 완화`를 메시지의 중심에 둔다. **최종 사용자 카피·비주얼은 손희영 UX 및 팀 검토 대상**이다.
- **해커톤 발표용 문장(출처 문안):** “일상에 새로운 외출의 계기를. 문화활동을 경험하고 싶지만 선택이 막막한 시니어가 AI와 대화하며 자신에게 맞는 나들이를 결정하도록 돕습니다.” **[기획 정리본·팀 검토 대기]**

**전 화면 공통 불변 조건**

1. 홈의 핵심 시작 CTA는 `나들이 찾기` **하나**. 홈에서 개별 장소와 코스를 별개 메뉴로 나누지 않는다. [PRD 확정]
2. 개별 장소/코스 의도 분기는 S02의 동일 AI 대화에서 수행한다. 결과 화면(S03/S05)에 별도 AI 채팅 패널을 만들지 않는다. [PRD 확정]
3. 추천·대화·재추천은 비회원도 제한 없이 이용한다. 저장·개인화는 체험용 로그인 안내를 거친다. OAuth/실제 사용자 계정 DB/기기 간 동기화는 범위 밖. [PRD 확정]
4. 사용자 최종 확인값이 실제 추천 요청값이며, 이전 AI 해석이나 느린 과거 응답으로 덮어쓸 수 없다. [PRD 확정/기준 요구]
5. 정상 적합·추가 확인 필요·조건 완화 대안은 구별한다. 운영/예약/가격/이동·접근성에 대해 검증되지 않은 사실을 만들지 않는다. [기준 요구]
6. 저장은 방문·결제·예약을 의미하지 않는다. 임시 선택과 명시 저장을 분리한다. [기준 요구]
7. 1인 시니어 가구는 **대표 사례·우선 검증 집단**이지 유일한 사용자 자격이 아니다. 서울은 **우선 검증 지역**이며, 실제 지원 지역·API 데이터 범위와 구분한다. [기획 정리본·팀 검토 대기]
8. 사회적 교류·외출 기회 감소는 기획 출발점이지만 **사회적 고립 감소를 검증된 서비스 효과처럼 표현하지 않는다**. [기획 정리본·팀 검토 대기]

## 2. 화면별 명세

### S01 | 홈

- **상태/우선순위:** 핵심 단일 진입 [PRD 확정], 비로그인 내 정보 접근·조건부 미리보기 [기획 확정]; 선착수 [제안].
- **목적:** 문화·여가활동을 어디서부터 찾아야 할지 막막한 사용자가 **나들이를 선택하는 첫 행동**을 쉽게 시작하고, 재방문 시 저장한 장소·코스에 접근한다. 1인 시니어 전용 화면으로 표현하지 않는다. [기준 요구/기획 정리본·팀 검토 대기]
- **진입·이탈:** 최초 접속/홈 이동 → `나들이 찾기`로 S02, `내 정보`로 S07. 저장된 장소/코스 미리보기의 항목을 누르면 해당 정보로 이동 [기준 요구, 상세 라우팅 UX 미확인].
- **UI 구성·표시 데이터:** `나들이 찾기` 단일 핵심 CTA, `내 정보` 진입, 현재 체험용 상태 안내 [기준 요구]. **실제 저장 내역이 있을 때만** 홈 하단에 `내가 고른 장소`·`내 나들이 코스` 미리보기 표시. 저장이 없으면 이 영역을 숨김 [기획 확정].
- **입력·검증:** 홈 자체 필수 입력 없음. 미리보기 표시 여부는 현재 브라우저 저장 결과에 근거해야 한다. 비회원에게 빈 저장 이력을 허위로 보여주지 않음.
- **인터랙션:** `내 정보` 클릭 시 **비로그인도 S07 먼저 진입**, 빈 내역 안내와 `체험용 로그인` 이용 안내 가능 [기획 확정]. 저장·개인화 동작 시에만 로그인 유도. S01 진입 자체에서 로그인 팝업 자동 노출 금지.
- **데이터·API:** 체험 상태 및 명시 저장 내역은 현재 브라우저 저장소를 사용 [PRD 확정]. 실제 키/스키마·브라우저 저장 실패 처리는 개발 협의.
- **상태·예외:** 첫 방문/비로그인 또는 저장 0건→미리보기 비노출; 저장 내역 존재→섹션 노출; 로컬 데이터 접근 오류→저장 현황을 성공한 것처럼 표시하지 않음 [제안].
- **완료/QA:** AC01, AC10, AC11. 비로그인 `나들이 찾기`와 `내 정보` 진입, 저장 후 홈 미리보기, 전부 삭제 후 미리보기 숨김을 검증.
- **미확인·영향:** 홈 미리보기 개수/형태·체험 상태 표시 밀도(손희영, S01 UI 마감 전); 브라우저 저장 복원 계약(김동조, 연결 전).

### S02 | 통합 입력·한국어 AI 대화

- **상태/우선순위:** 음성·텍스트 통합, 대화↔입력 필드 동기화 [PRD 확정]; 자동 대화, 충돌 확인, 오류 표시, 최소 60분 [기획 확정]; 선착수.
- **목적:** 문화활동을 선택할 때 부담이 되는 **장소·시간·거리·걷기·참여 조건**을 한 화면에서 말하거나 직접 입력하고, AI와 부족한 정보만 확인해 탐색 부담을 줄인다. [기준 요구/기획 정리본·팀 검토 대기]
- **진입·이탈:** S01 `나들이 찾기` / S03·S05 `조건 바꾸기`→S02. 필수 조건 확인·검증 후 S02a 조건 확인 영역으로 진행.
- **UI 구성·표시 데이터:** 출발지(현재 위치 권한/장소 검색·선택), 출발 날짜, 출발 시각, 종료 시각; `더 원하는 게 있으세요?` AI 음성·텍스트 대화 영역; 마이크, 인식된 문장, 수정/다시 말하기, AI 응답 텍스트·읽기 중지, 조건 요약, `나들이 추천받기` [기준 요구/기획 확정]. 문화 관심·예산·걷기·제외·기존 일정은 대화 및 선택 입력으로 수집. 선택 조건의 별도 컨트롤 노출은 [미확인].
- **음성 대화 [기획 확정]:** **마이크로 발화 → STT 인식 종료 시 별도 `보내기` 없이 AI가 자동 처리**(턴 기반). 인식 문장은 화면에 표시하고 바로잡기/다시 말하기를 제공한다. AI의 답변은 텍스트로 표시하며 가능한 환경에서 TTS로 안내; 중지 가능. 상시 청취·전이중 대화는 필수 요구가 아니다. 자동처리된 내용을 나중에 바로잡는 정정 동작과 실행 중 응답 경합 처리는 [미확인: 김동조/손희영].

- **인터랙션:** `이 장소 선택`→임시 선택 표시(저장 아님). `내가 고른 장소에 저장`→체험 로그인 상태면 로컬 저장; 비로그인 시 S06 체험용 로그인 안내→로그인 클릭 성공 시 **앞서 명시 요청한 저장을 자동으로 1회 완료**하고 S04로 복귀 [기획 확정]. 로그인 취소 시 저장하지 않고 기존 상세/임시 선택 유지. 저장 실패는 성공 문구를 내지 않고 재시도 안내.
- **저장 성공 [기획 확정]:** **S04 화면 유지**, `저장되었어요.` 표시, 저장 버튼을 `저장됨` 상태로 바꿔 중복 저장 방지, `내 정보에서 보기`로 S07 이동 선택 가능. 저장된 장소·선택/추천 결과 유지.
- **관심사 후속 안내 [기획 확정]:** 최초 체험 로그인으로 저장을 완료했다면 **저장 성공 후** `관심사를 설정하면 더 알맞은 나들이를 추천받을 수 있어요.`를 가볍게 표시하고 `설정하기`/`나중에` 선택 제공. 팝업 강제 이동/저장 차단 금지. 상세 카피·배치 UX 협의.
- **데이터·API:** 후보 ID·운영/가격/예약/참여·이동 필드, 공식 출처/검증시각; 저장 스키마·상세조회 계약 [미확인]. 저장된 정보 재열람 때 새 공식 정보 확인/누락 고지 [기준 요구].
- **상태·예외:** 상세 로딩/정보 누락, 공식 URL 없음, 체험 로그인 안내/취소, 저장 처리 중/성공/실패/중복 방지, 오래된 운영정보 재검증 실패.
- **완료/QA:** AC05/07/11/11b/15. 선택만 하면 저장되지 않음; 로그인 완료 시 요청 저장 자동 완료; 취소하면 저장 없음; 저장 후 S04 유지/완료 안내; 동일 브라우저 재방문에서 저장 복원.
- **미확인·영향:** S04 전체 페이지 vs 상세 오버레이, 버튼 위치·우선순위, 확인 필요 정보 밀도, 관심사 안내 배치(손희영); 저장 흐름·선택 ID/복원 계약(김동조).

### S05 | 다중 장소 나들이 코스 결과

- **상태/우선순위:** 동일 S02에서 코스 의도 판별 [PRD 확정], **2~3곳 순서 있는 1개 코스** [기준 요구], 제외 예정→명시 재생성 및 실패 시 이전 결과 보존 [기획 확정]. 코스 기능 삭제 불가.
- **목적:** 여러 문화장소 중 무엇을 어떤 순서로 방문할지 판단하도록 **방문 순서·시간표·이동 부담·운영/예약 확인 상태**를 비교하고 코스를 수정·저장한다. [기준 요구/기획 정리본·팀 검토 대기]
- **진입·이탈:** S02a에서 `route` 확정→S05. `조건 바꾸기`→S02(대화/조건 보존). 장소 자세히→S04 또는 코스 내 상세 UI [표현 미확인]. 저장→S06(비로그인), 저장 후 S05 유지 방향은 S04와 동일하게 적용할지 [UX 확인].
- **UI 구성·표시 데이터:** 2~3개 순서별 장소 카드, 방문 계획 시각·체류 예상(실제 운영시간과 구분), 구간 이동·근거, 코스 지도, 가격/예약/운영/참여 및 확인 필요, 제외 선택·취소, `코스 다시 만들기`, `조건 바꾸기`, `내 나들이 코스에 저장`.
- **장소 제외 동작 [기획 확정]:** 특정 카드에서 `이 장소 제외` 선택 시 **즉시 API 재생성하지 않고 `제외 예정` 표시**, 제외 취소 가능. 사용자가 `코스 다시 만들기`를 누르면 제외 조건을 포함하여 재판정. 여러 곳 동시 제외·2곳 미만 처리의 안내 방식은 [미확인]; 다만 유효 2~3곳을 만들지 못한 결과를 정상 코스로 단정하지 않음.
- **재생성 실패 [기획 확정/기준 요구]:** 새 유효 코스가 없거나 API 실패 시 이전 **유효한 코스**를 유지하고 사용자에게 이유/재시도/조건 수정 경로를 안내. 이미 저장한 코스는 무단 변경 금지.
- **저장 및 관심사:** 코스도 사용자의 명시 저장 요청→비로그인 S06→체험용 로그인 후 **원래 코스 저장 자동 완료**, 취소 시 이전 코스 보존 [기획 확정]. 저장 성공 후 관심사 설정은 선택적으로 가볍게 안내하고 먼저 저장 처리 [기획 확정].
- **데이터·API:** 개념 `route(stops[])`, 순서·방문예정시각·체류계획·구간이동·운영 적합·전체 비용 확인 여부. 실제 요청/응답·시간대·재계산 로직 [미확인]. 근거 없는 도보시간·운영·무료·무장애 단정 금지.
- **상태·예외:** 생성 로딩, 정상, 0건, 장소 제외 예정, 재생성 중, 재생성 실패(이전 유효 코스 보존), 지도 오류 시 장소/순서 카드 유지 [제안, S03 원칙 준용], 정보 미확인, 저장 중/실패.
- **완료/QA:** AC08~AC10/AC12/14. 2~3곳 1개, 제외 예정에서 즉시 재생성 없음, 취소 복구, 명시적 재생성 후 새 결과, 실패 시 이전 코스 유지, 코스 저장·재접근.
- **미확인·영향:** 코스 카드·지도·순서 배치, `제외 예정` 디자인, 코스 저장 후 안내(손희영); 코스 재계산·운영/이동 근거(김동조).

### S06 | 체험용 로그인·선호 관리·체험 종료

- **상태/우선순위:** 외부 OAuth 없는 브라우저 데모 [PRD 확정]; **체험 종료 및 전체 삭제(B안)**, **로그인 후 원래 저장 자동 완료**, **저장 우선·관심사 나중**, **가벼운 관심사 제안** [기획 확정].
- **목적:** 실제 인증 없이 저장·개인화 체험을 시작하고, 공유 기기에서도 체험 데이터를 분명하게 관리한다.
- **진입·이탈:** S04/S05 저장 요청, S07 관심사 설정/체험 로그인, 홈에서 별도 접근 가능 여부 [미확인]. 취소→원래 화면과 조건·임시 선택 보존; 로그인 완료→대기했던 사용자 저장 행동을 한 번 자동 실행하고 원래 상세·코스 맥락 유지.
- **UI 구성:** `체험용 로그인` 명칭 및 브라우저 저장/기기 간 동기화 불가 안내, `체험용 로그인 시작`·`취소`; 처음 관심사 선택(전통문화/역사·궁궐/문화 체험/미술·전시/공연/축제·이벤트), 자유 선호, `건너뛰기`, 수정·선호 초기화, `체험 종료 및 데이터 삭제`와 확인창.
- **입력·검증:** 실제 Google/Kakao/OAuth·계정 토큰·서버 회원 DB 없음. 이름·전화번호 등의 민감 정보 불필요. 관심사는 미설정/복수 선택 허용. 로그인 성공 여부와 브라우저 로컬 저장 성공 여부는 서로 구분하여 검증.
- **로그인 동작 [기획 확정/PRD 확정]:** 비로그인 사용자의 `저장` 명시 요청을 복귀 맥락으로 보관 → 체험용 로그인 클릭으로 데모 상태 활성화 → **추가 저장 클릭 없이** 동일 요청을 1회 실행 → 저장 성공/실패에 맞는 안내 → 요청한 상세 화면 또는 코스에 머무름. 로그인 취소 시 저장하지 않고 기존 상태 보존.
- **관심사 동작 [기획 확정]:** 최초 로그인 직후 관심사 설정을 **필수 선행 절차로 강제하지 않음**. 원래 저장을 먼저 완료한 다음 `설정하기` 또는 `나중에` 선택 가능한 가벼운 안내 제공. S07에서도 설정/수정/건너뛰기 가능. 관심사 설정/초기화는 저장된 장소·코스를 임의 삭제하지 않음.
- **체험 종료 [기획 확정]:** 사용자에게 `체험 종료 및 데이터 삭제` 확인창을 표시하고 **확인했을 때만** 데모 로그인 표시, 저장 장소/코스, 선호·온보딩 체험 정보를 초기화. 취소하면 아무 것도 삭제하지 않음. 브라우저 닫기/새로고침은 종료로 취급하지 않아 같은 브라우저 저장 복원. 대화·위치의 임시 상태와 원본 음성 보관/삭제 범위는 기술·개인정보 정책 확인 필요.
- **데이터·API:** 현재 브라우저 저장소 예: `demoSignedIn`, `demo_preferences`, `demo_saved_pick`, `demo_saved_route`, `demo_onboarding_done` (개념 명칭). 최종 저장 키·원자적 초기화 방식·스토리지 장애 처리 [미확인]. 실제 인증 권한으로 서버 API 접근 금지.
- **상태·예외:** 체험 로그인 유도/취소/전환, 로그인 후 저장 처리, 브라우저 저장 실패, 선택적 관심사 안내, 초기화 확인/취소/성공/실패. 실패 시 `저장 완료`·`초기화 완료`로 거짓 표시 금지.
- **완료/QA:** AC11/11a/11b/15/16. 인증 리다이렉트 없음; 저장 자동 이어짐; 로그인 취소 시 무저장; 재접속 복원; 체험 종료 취소 시 유지, 삭제 확인 시 데모 데이터 초기화; 관심사 미설정해도 저장 성공.
- **미확인·영향:** 로그인/선호를 모달·페이지·단계 중 어떤 형태로 표시할지, 삭제 확인창·관심사 제안 위치(손희영); 저장/초기화 범위 및 오류·프라이버시(김동조+정민규).

### S07 | 내 정보·재접근

- **상태/우선순위:** **섹션형 세로 스크롤 [기획 확정]**, 비로그인 직접 진입 [기획 확정]; 전체 정보 구조는 [기준 요구].
- **목적:** 사용자가 하나의 화면에서 저장한 장소·코스·관심사·체험 상태를 쉽게 보고 관리한다.
- **진입·이탈:** S01 `내 정보` 클릭 시 **로그인 여부와 관계없이 S07 진입**. S04 `내 정보에서 보기` → S07. 저장 장소→S04, 저장 코스→S05(최신 운영 확인 여부 안내 필요). 관심사 수정→S06 관련 UI.
- **UI 구성 [기획 확정]:** **탭형이 아닌 세로 섹션형**. 순서: `내가 고른 장소`(미리보기+전체 보기), `내 나들이 코스`(미리보기+전체 보기), `관심사 설정`(조회/수정), `체험용 로그인 상태`, `체험 종료 및 데이터 삭제`. 실제 섹션 카드 형태·미리보기 개수·버튼 배치는 [손희영 UX 협의].
- **비로그인 [기획 확정]:** S07 진입은 허용하고 빈 내역 안내/체험용 로그인 CTA 제공. 실제 저장/선호 반영을 시도할 때 체험용 로그인 유도. 허위 계정 정보나 저장 목록을 보여주지 않음.
- **인터랙션:** 저장 장소/코스 열람, 선호 선택/수정/초기화, `체험 종료 및 데이터 삭제` 확인창 호출. **선호 초기화만으로 저장 장소·코스를 삭제하지 않음**. 전체 초기화 후 목록·체험 상태·홈 미리보기를 일관되게 비움.
- **데이터·API:** 같은 브라우저 저장값 조회. 저장 결과 재열람 시 운영정보가 변경/확인 불가일 수 있음을 알림 [기준 요구]. 실제 재조회 시점·실패/변경 표현·브라우저 스키마 [미확인].
- **상태·예외:** 비로그인/저장 없음, 저장 장소만 있음, 코스만 있음, 양쪽 모두 있음, 관심사 미설정, 재검증 실패, 저장 읽기 실패, 전체 초기화 성공/실패.
- **완료/QA:** AC07/10/11b/15. 비로그인 즉시 진입, 저장 상태에 따른 정확한 섹션, 관심사 수정, 삭제 확인/취소 및 동일 브라우저 복원.
- **미확인·영향:** 섹션 밀도·미리보기 수·전체 보기 세부 이동, 모바일 스크롤/접근성(손희영), 저장·재검증 정책(김동조).

## 9. 변경 이력 (v0.1 → v0.2.1)

1. 2026-10-30~31 제품 기획 대화의 **20개 승인 결정**(D01~D20)을 S01~S07 화면 요구와 QA로 통합.
2. S02 음성 자동 대화·인식 정정·값 충돌 확인, **최소 60분** 및 필드 인라인 오류 규칙 반영.
3. S02a를 **S02 내부 인라인 조건 확인 영역**으로 결정하고, 레이아웃 세부만 UX 협의로 남김.
4. S03 같은 조건 추가 추천/추가 0건 기존 결과 유지/최초 0건 유지/지도 오류 카드 보존/항목별 확인 필요 명시.
5. S04 임시 선택·저장 두 CTA, 저장 성공 S04 유지, 비로그인 체험 로그인 후 자동 저장.
6. S05 제외 예정→명시적 코스 재생성, 실패 시 이전 유효 결과 유지.
7. S06 체험 종료=확인 후 전체 삭제, 저장 우선/관심사 나중, **저장 후 관심사 설정 가벼운 안내(D20)**.
8. S07 섹션형, 비로그인 직접 접근, 저장 내역이 있을 때만 S01 홈 미리보기.
9. 손희영 UX 협의와 김동조 데이터·API 계약을 분리하고 팀 검증 미완료 표시를 유지.
10. **v0.2 팀 공유 전 내용 보완(버전 번호 유지, 2026-10-31):** 타깃·문제정의 최종 정리본 v1.0의 핵심 타깃/대표 사례/서울 우선 검증, 직접 해결하는 문제와 `말하고→확인하고→선택` 경험을 문서 0절·S01~S05 목적·UX 검토·콘텐츠 QA에 반영. **D01~D20, 화면 ID·서비스 범위·API 정책은 변경하지 않음.** 해당 정리본의 팀 문서 검토는 미완료로 표시.
