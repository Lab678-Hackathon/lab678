## 2. AI 협업 시 문서 우선순위와 충돌 처리

1. **확인 가능한 최신 팀 합의**가 우선이다. 단, 구두 동의·개인 기획 확정·팀 전체 최종 승인을 구분한다. 확정 근거가 없으면 임의 승격하지 않는다.
2. **PRD.md**는 **무엇을/왜/어디까지 만드는지**에 대한 기준이다. 기능·정책·사용자 가치의 1차 기준으로 삼는다.
3. **MVP 화면명세서**는 해당 PRD를 실제 화면으로 표현하는 **동작·상태·전이 상세 기준**이다. PRD와 불일치하면 조용히 고쳐 쓰지 말고 항목·영향 화면을 기록해 Product와 관련 담당자에게 확인한다.
4. **실제 코드·API 응답·테스트 결과**는 구현 여부와 기술적 사실의 근거다. 요구사항과 구현이 다르면 구현을 자동으로 제품 정책으로 간주하지 않는다. 완료·미완료·Mock·오류를 구분한다.
5. **handoff**는 역할별 **착수 참고 자료**이며 현행 PRD 또는 화면명세서를 대체하지 않는다. **archive는 비교/이력용**으로만 열람한다.
6. 새 대화·AI 도구가 오래된 문서만 발견하거나 기준 문서를 읽지 못하면 **추측하거나 이전 PRD로 대체하지 않는다**. 최신 문서 경로와 접근 실패를 먼저 보고한다.

**미해결 충돌 보고 형식:** `대상 화면/기능 | 기존 기준 | 새 근거 | 제안 수정 | 상태(확정/제안/미확인) | 확인 담당`. 공통 API, 화면 이동, 제품 정책, 다른 담당자의 파일 변경은 관련 담당자 확인 후 적용한다.

## 3. 담당자별 AI 시작 순서

- **정민규 · Product:** `PRD.md` → `Lab_678_MVP_화면명세서.md` → 필요한 `handoff/` 참고 → 기획 결정·미확인을 구분해 전달. 타깃·발표 문구의 **팀 검토 대기** 표시를 제거하지 않는다.
- **손희영 · UX/UI:** `PRD.md`(제품 목적·확정 기능) → `MVP 화면명세서`(필드·버튼·상태·오류) → `handoff/UI` → 실제 최신 Figma. 기존 착수 화면과 최신 합의가 충돌하면 최신 합의를 확인한다.
- **김동조 · 개발:** `TEAM_WORKFLOW.md` → `PRD.md`(정책) → `MVP 화면명세서`(화면 연동) → `docs/development/current-state.md` 및 실제 코드·테스트 → 필요할 때 `handoff/DEV`. 가상 데이터·기존 코드의 동작을 새 서비스의 검증된 완료로 기록하지 않는다.

**공통 인계:** 각자 AI가 제안한 변경은 `확정/팀 검토 대기/미확인`과 함께 PR·작업 공유에 남긴다. 담당자 개인 AI의 답변만으로 팀 합의가 생기지는 않는다.

## 4. 이번 버전에서 꼭 알아둘 제품 경계

- **서비스:** '나들이 찾기' 단일 진입. 개별 장소 추천(상단 지도+하단 카드) 또는 동일 대화에서 2~3곳 문화코스 요청.
- **대화:** 한국어 음성/텍스트. S02에서 필드 동기화, 충돌 시 사용자 확인, 조건 확인은 같은 화면의 S02a 인라인 영역. 권한 실패 시 텍스트 대체.
- **재추천:** '조건 바꾸기'는 입력·대화 맥락 유지, '다른 곳 찾기'는 동일 조건으로 새 후보 탐색. 유효 후보 없으면 기존 결과 보존.
- **추천 시간:** **최소 60분**(기획 확정). 구현·서버 검증 일치 여부는 별도 QA.
- **저장:** 실제 OAuth 아님. 체험용 로그인 + 같은 브라우저 저장·복원·초기화. 비회원은 대화·추천 이용 가능.
- **타깃:** 시니어의 문화나들이 **선택·결정 부담**에 집중. **1인 시니어 가구는 대표 사례·우선 검증 집단**(희영님 구두 찬성); 전체 타깃 문구·발표 카피는 **팀 문서 검토 대기**.
- **데이터:** 운영·가격·예약·도보·이용가능은 AI가 추정해 보장하지 않는다. 미확인 상태를 표기한다.
- **범위/완료:** 모든 PRD 항목이 구현·배포됐다는 의미가 아니다. P0 최종 범위·QA 통과 항목·실제 API 계약은 담당자 검증과 팀 합의가 필요하다.

## 5. 변경·보관 원칙

- PRD를 고칠 때는 **`PRD.md` 한 파일**을 갱신하고, 버전·변경 이력·합의 상태를 기록한다. 별도의 새 PRD 복사본을 활성 폴더에 계속 만들지 않는다.
- 화면명세서를 고칠 때는 PRD·화면 ID·기능 ID를 대조한다. PRD와 충돌하면 반영 전 확인한다.
- 과거 PRD는 `archive/`에 보존하고, 구버전에서 **현행 결정/기능을 자동 복원하지 않는다**. 오래된 문서의 링크는 기록·경로 이관 이후 별도 검증한다.
- 이 README는 **문서 경로·버전·상태·읽는 순서만 관리**한다. 기능 정책을 중복 정의하는 별도 PRD가 아니며 제품 내용 수정은 정본에 반영한다.
