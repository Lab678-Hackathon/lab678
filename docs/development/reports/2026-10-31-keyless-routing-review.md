**도보는 우리도 이미 API 키 없이 가져옵니다. 다만 현재 도보 서버로 서울 대중교통까지 조회할 수는 없었습니다.** 제시하신 다른 앱의 방식은 참고할 부분이 있지만, 설명만으로 “정확한 대중교통·무장애 길찾기”가 구현됐다고 판단하기는 어렵습니다.

우리 도보는 **OpenStreetMap 도로망 → Valhalla 경로 계산 → 앱의 텍스트·지도 표시** 순서입니다. FOSSGIS 공개 서버에 출발·도착 좌표를 보내 실제 길을 따라 계산한 예상 거리·시간·이동 단계를 받습니다. 키는 없지만 외부 서버는 사용합니다. [Valhalla 공식 안내](https://valhalla.github.io/valhalla/)

| 구분 | 다른 앱의 제시 방식 | 현재 LAB678 |
|---|---|---|
| 거리 | 하버사인으로 좌표 사이 거리 계산 | 후보 정렬은 하버사인, 도보 안내는 도로망 경로 |
| 이동시간 | 평균속도·대기 버퍼로 추정 | 도보 엔진이 반환한 예상시간 |
| 대중교통 | 저장한 인접역과 안내 문장 조립 | 카카오 연결 코드 준비, 실제 조회는 키 대기 |
| 접근성 | 저장된 엘리베이터·무장애 값 | 아직 확인된 무장애 경로로 판정하지 않음 |

**하버사인은 실제 보행거리가 아닙니다.** 강·철길·횡단보도·출입구를 반영하지 않습니다. 여기에 지하철 평균속도를 적용해도 탑승 노선, 방향, 환승역, 운행시간은 나오지 않습니다. 보내주신 설명에는 속도·대기시간 수치도 빠져 있어 계산 정확도를 재현할 수 없습니다.

미리 검증한 장소 정보를 저장하는 방식은 좋습니다. 하지만 예시의 `hasElevator: true`만으로 **선택한 출구부터 목적지까지 계단이 없는지** 알 수는 없습니다. 엘리베이터 위치·연결 층·가동 여부와 실제 이동 동선을 확인해야 합니다. 서울시는 승강기 가동현황 데이터를 별도로 제공합니다. 또한 예시에는 도보 시간이 3분과 4분·6분으로 섞여 있어 기준 출구를 구분해야 합니다. [서울시 승강기 데이터](https://data.seoul.go.kr/dataList/OA-15994/S/1/datasetView.do)

Valhalla 자체에는 대중교통 기능이 있습니다. 그러나 **노선·정류장·운행시간표 데이터(GTFS)를 추가로 넣어야** 합니다. 방금 현재 서버에서 청량리역→돈화문 구간을 시험했을 때 경로 조회는 실패했고, 두 지점 주변의 대중교통 가용성도 모두 `false`였습니다. 이 결과는 해당 서버·시험 지점 기준입니다. [Valhalla 데이터 설명](https://valhalla.github.io/valhalla/api/)

키 없는 자체 대중교통도 가능합니다. 공개 시간표와 도로망을 갖춰 Valhalla나 OpenTripPlanner를 운영하는 방식입니다. 대신 데이터 확보·갱신·서버 운영이 필요하므로, 짧은 해커톤에서는 부담이 큽니다. [OpenTripPlanner](https://docs.opentripplanner.org/en/latest/Data-Sources/)

**제 추천은 현재 도보를 유지하면서, 검증된 대중교통 정보를 4단계 카드로 간단하게 보여주는 것입니다.**

1. 목적지별 역·출구·엘리베이터 정보를 출처·확인일과 함께 저장합니다.
2. 대중교통은 API 실조회 또는 미리 검증한 시연 구간만 안내하고, 추정값과 구분합니다.
3. 화면은 ‘탑승 → 하차·환승 → 출구 → 목적지까지 도보’로 단순화하고 음성으로 읽습니다. 환승이 여러 번이면 단계를 생략하지 않습니다.

상용 API라고 모두 유료만 가능한 것도 아닙니다. 카카오는 조건에 따른 무료 쿼터가 있습니다. **API 키 필요와 유료 결제 필요는 별개**입니다. 외부 API의 복잡한 화면도 그대로 사용할 필요 없이, 받은 데이터를 우리 화면으로 쉽게 표시하면 됩니다. [카카오 이용 조건](https://developers.kakao.com/docs/ko/kakaomap/common)
