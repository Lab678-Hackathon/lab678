**2. 최소 나들이 시간 60분**

최신 기획에서 확정됐지만 **백엔드는 아직 미반영**입니다. 현재 같은 날인지와 종료가 시작보다 늦은지만 검사하며, 직접 호출해 보니 59분도 허용됩니다. **59분 차단·60분 허용** 테스트와 함께 반영하고, 프론트의 시간 입력 아래 오류 안내도 같은 기준으로 맞춰야 합니다.

**3. API 계약과 CORS**

개인 점검용 추천·도보·대중교통·음성 API는 있습니다. 다만 **팀 공통 계약 확정과 다른 포트용 CORS/OPTIONS는 아직 완료되지 않았습니다.** 현재는 같은 주소에서 점검 화면과 API를 사용합니다.

희영님 프론트의 브랜치·실행 포트·요청 형식을 받아 `route/course` 구분, 응답 필드·단위·미확인값·오류 처리를 맞추겠습니다. 개발 프록시 또는 허용 주소를 제한한 CORS 중 연결 환경에 맞게 정하면 됩니다. 현재 localhost 서버는 다른 PC에서 바로 접근하는 공용 API가 아닙니다.

**4. 대중교통 안내 수준**

카카오 API 실조회와 최대 3개 경로의 시간·환승·요금·이동 단계, 경로 선택·복귀를 **개인 점검 화면에서 실제 확인했습니다.** 해당 PC에서는 시연한 기능입니다.

다만 최종 시연 환경에서는 키·네트워크·쿼터를 다시 확인해야 합니다. GPS 실시간 내비게이션이나 대중교통을 반영한 코스 일정 계산은 아닙니다. 총 도보량·미래 출발시각·접근성은 미확인으로 유지하고, 대중교통 지도는 외부 카카오맵 링크로 제공합니다.

**5. 팀 최종 UI 연결 상태**

현재 제가 확인 가능한 `frontend`에는 안내 문서만 있어 최종 UI의 연결 여부를 확인하지 못했습니다. 희영님 작업이 없다는 뜻은 아닙니다. 실제 브랜치나 실행 주소를 받아 확인해야 합니다.

추천·지도/카드·음성·코스·경로안내의 개인 검증을 팀 UI 통합 완료로 보고하지 않겠습니다. 장소 상세, 체험 로그인·저장·내 정보는 제 구현에서도 아직 남아 있습니다.

**음성 처리 차이**
