## 1. 우선 제안

**외부 지도에서 상세 길찾기를 열고, 서비스 안에는 검증한 이동 요약과 실제 경로만 표시하는 방식을 우선 검토한다.** 제공사 선정은 아래 기술검증 뒤 결정한다.

1. **외부 길찾기:** 카카오맵의 HTTPS 도보·대중교통 링크를 첫 후보로, 네이버지도 앱 연결을 선택 후보로 검증한다.
2. **서비스 내부 도보 데이터:** KONNECT에 있는 T map 도보 클라이언트를 재사용 후보로 먼저 점검한다. 카카오 공개 도보 API도 비교할 수 있다.
3. **서비스 내부 대중교통 데이터:** Kakao Developers 공개 API와 TMAP 대중교통 API를 실제 키·날짜 조건으로 비교한다. ODsay는 대안이다.
4. 지도 표시 SDK, 경로 데이터 제공사, 외부 길찾기 앱은 별개로 선택할 수 있는 구조를 제안한다. **서로 다른 제공사 데이터를 같은 지도에 표시할 수 있는 계약·출처 조건은 적용 전에 확인한다.**

외부 링크만 붙인 단계는 **길찾기 연결 완료**이지, 자체 이동시간 계산·시니어 보행 제약 판정까지 완료한 것이 아니다. 반대로 경로 API 성공도 현장 접근성이나 실제 도착시각을 보장하지 않는다.

### 3.1 카카오맵: 공개 API와 제휴 API를 구분

**공개 API:** 공식 REST 문서에 `GET /v2/routing/walk`와 `GET /v2/routing/publictraffic`가 있다. REST API 키를 사용하며 시간·거리·경로 또는 대중교통 구간·요금·환승 정보가 문서화되어 있다. 공개 대중교통 요청 표에는 출발 날짜·시각 지정 필드가 보이지 않아, 미래 일정 계산에 그대로 사용 가능하다고 확정하지 않는다. [공식 REST API](https://developers.kakao.com/docs/en/kakaomap/rest-api)

2026-07-21 신규 API·이용절차 변경 공지가 있으므로 과거의 “카카오 도보·대중교통 API는 제공하지 않는다”는 설명을 기준으로 삼지 않는다. [카카오 공식 변경 공지](https://devtalk.kakao.com/t/api-notice-on-new-kakao-map-api-features-and-free-quota-policy/150222)

앱 등록·카카오맵 API 활성화·키 설정이 필요하다. 첫 활성화 앱인지에 따라 무료 쿼터 적용이 다르며, 추가 앱 또는 초과 사용에는 비즈월렛·유료 API 설정 조건이 있다. 계정 상태는 확인하지 않았고 결제 설정도 변경하지 않았다. [이용 절차·정책](https://developers.kakao.com/docs/en/kakaomap/common)

조회한 쿼터표는 공개 도보·대중교통 API 각각 **일 1,000건**, 유료 추가 사용은 각각 **건당 10원**을 안내한다. 모든 앱이 자동으로 무료 대상인 것은 아니다. 단가·정책은 변경될 수 있으므로 실제 사용 직전에 다시 확인한다. [공식 쿼터·단가](https://developers.kakao.com/docs/en/getting-started/quota)

**제휴 API:** 카카오모빌리티의 `/affiliate/` 제품군은 사전 제휴 계약이 필요하다. 통합 대중교통 문서에는 날짜·시각과 도보·버스·지하철 구간이 있지만 공개 Developers API와 접근 조건이 다르다. “카카오 대중교통은 모두 제휴 필수”로 묶지 않는다. [제휴 조건](https://developers.kakaomobility.com/affiliate/), [통합 대중교통 문서](https://developers.kakaomobility.com/affiliate/publictransit/multimodal.html)

**외부 링크:** `https://map.kakao.com/link/by/{mode}/{출발명},{위도},{경도}/{도착명},{위도},{경도}` 형태를 문서가 안내한다. 모드는 도보 `walk`, 대중교통 `traffic`이다. 대중교통은 경유지를 지정할 수 없어 문화코스는 장소 사이 구간별 연결을 제안한다. 이름은 URL 인코딩하고 앱 설치·미설치 시 동작은 기기에서 검증한다. [공식 지도 Web API 가이드](https://apis.map.kakao.com/web/guide/)

### 3.2 네이버지도: 외부 길찾기와 NCP API의 차이

공식 앱 연동 문서는 `nmap://` 스킴, 식별용 `appname`, 앱 미설치 대응을 설명한다. 대중교통 액션은 `/route/public`이며, 도보 `/route/walk`는 NAVER Cloud 공공기관용 공식 문서에서도 확인된다. 실제 시연 앱 버전과 모바일 브라우저에서 검증해야 한다. [일반 공식 가이드](https://guide.ncloud-docs.com/docs/maps-url-scheme), [공공기관용 공식 가이드](https://guide-gov.ncloud-docs.com/docs/ko/naveropenapiv3-maps-url-scheme-url-scheme)

앱 스킴이 실행되지 않으면 주소 복사·대체 지도 링크로 이어갈 수 있게 설계한다. 스토어 이동만으로 사용자 안내가 완료됐다고 보지 않는다. 출발지와 목적지를 전달하는 링크가 본 서비스의 날짜·개인 조건까지 모두 반영한다고 가정하지 않는다.

NCP Directions 5는 **자동차 경로·통행 정보 API**다. 이를 도보나 대중교통 이동시간으로 사용하지 않는다. 이번에 조사한 API의 범위에 관한 판단이며 네이버의 모든 제휴 상품 부재를 주장하는 것은 아니다. [Directions 5 공식 문서](https://api.ncloud-docs.com/docs/application-maps-directions5)

### 3.3 T map: 기존 도보 코드와 신규 대중교통 비교

보행자 API는 경로의 형상·거리·소요시간을 제공하는 후보다. 기존 코드에 사용된 경로는 `POST https://apis.openapi.sk.com/tmap/routes/pedestrian?version=1&format=json`이다. [TMAP 공식 경로 샘플](https://tmap-skopenapi.readme.io/reference/경로안내-샘플예제)

대중교통은 별도 `POST https://apis.openapi.sk.com/transit/routes/` API이며 앱 키가 필요하다. `searchDttm` 설명은 지정 시각의 **운행 여부**를 안내하는 기능이므로 정확한 배차·대기시간 보장으로 확대 해석하지 않는다. [공식 요청 명세](https://tmap-public-skopenapi.readme.io/reference/대중교통-api)

상세 문서에는 총 예상시간, 총 도보시간·거리, 환승횟수, 요금과 구간별 정보가 있다. 본문 오류 코드가 HTTP 200으로 오는 경우도 있어 HTTP 상태만으로 성공 판정하면 안 된다. [공식 응답·오류 명세](https://transit.tmapmobility.com/docs/routes)

사용 상품·요금·한도·발급된 키의 활성화 범위는 계정에서 확인해야 한다. 이번 조사에서는 정확한 적용 요금제를 확정하지 않았다. [공식 상품 안내](https://openapi.sk.com/products/detail?menuSeq=492&svcSeq=59)

### 3.4 구글맵: URL 지원과 한국 데이터 지원을 구분

Maps URLs는 API 키 없이 사용할 수 있으며 `api=1`, 출발지·목적지, `travelmode=walking|transit` 등을 받는다. 앱이 없으면 브라우저에서 여는 동작도 공식 안내에 있다. [공식 Maps URLs](https://developers.google.com/maps/documentation/urls/get-started)

그러나 조회 당시 공식 국가별 지원표의 한국 `KR` 도보 항목은 `—`다. 이 기호는 미제공 또는 낮은 품질·가용성을 뜻한다. 해당 표는 대중교통 전체 지원 여부를 포함하지 않으므로 도보 표기만으로 대중교통까지 불가라고 결론 내리지 않는다. [공식 국가별 지원표](https://developers.google.com/maps/coverage)

Routes API의 대중교통은 TRANSIT 모드, 구간 정보, 시간·선호 옵션을 제공하지만 중간 경유지는 지원하지 않는다. 한국의 특정 시각·장소·도보 구간 품질은 별도 실험 대상이며, 사용 시 API 인증·과금 설정도 확인한다. [공식 Transit Route 문서](https://developers.google.com/maps/documentation/routes/transit-route)

### 3.5 기타 대안: ODsay와 공공데이터

ODsay 공식 가이드는 `searchPubTransPathT` 경로 조회와 `loadLane` 노선 그래픽 조회를 분리하고 지도 위에 표시하는 예시를 제공한다. 요약 응답에 정보가 있다고 보행 경로선까지 확보됐다고 보지 않는다. `totalWalkTime=-1` 같은 예시값은 미확인으로 다루고 0분으로 바꾸지 않는다. 요금제·사용 한도·시간 지정 지원·사용 도메인/IP 조건은 실제 신청 범위에서 추가 확인한다. [ODsay 공식 가이드](https://lab.odsay.com/guide/guide?platform=web)

서울교통공사 최단경로 API는 역명/코드 기반의 최소시간·최단거리·최소환승과 날짜/시각 조건을 설명한다. 역간 이동 보완 후보이며 출발지→역, 버스, 역→문화장소의 전체 이동 안내를 단독 대체하지 않는다. [공공데이터포털 공식 안내](https://www.data.go.kr/data/15143842/openapi.do)

## 4. KONNECT에서 확인한 재사용 후보

기준 브랜치: `konnect`, 커밋 `932032bcc5462d5dda00985503d2e7b4e1ed32be`. 파일을 읽은 결과이며 이식·실행은 하지 않았다.

| 파일 | 확인한 역할 | 재사용 전 확인 |
|---|---|---|
| `backend/app/sources/tmap.py` | 서버에서 도보 API 호출, 거리·분 단위 예상시간·경로 좌표 변환 | 기존 설정 의존성, 오류 구분, 원본 초 단위 보존 |
| `frontend/js/components/directions-overlay.js` | 지도 개요와 외부 네이버 길찾기 연결, 위치 표시 | 한국어·시니어 UX, 외부 URL, 앱 복귀와 권한 처리 |
| `frontend/js/map.js` | 오버레이에서 호출하는 지도 렌더링 의존성 | 함수·좌표·지도 SDK·공통 상태 계약 대조 필요 |

도보 클라이언트는 여러 실패를 `None`으로 반환한다. 새 요구에서 **경로 없음 / 권한·키 문제 / 한도 / 통신 실패**를 구분하려면 보완이 필요하다. 현재 `round(초/60)`와 최소 1분 처리는 표시용으로만 보고 Hard 제한 비교에는 원본 초를 보존하는 안을 제안한다.

오버레이는 위치를 갱신하지만 이탈 때 경로를 재계산하지 않는 코드다. 이를 자체 내비게이션이 구현된 근거로 삼지 않는다. 기존 주석의 iframe 제한 설명도 이번 환경의 최신 검증 결과가 아니다. [기존 도보 소스](https://github.com/Lab678-Hackathon/lab678/blob/konnect/backend/app/sources/tmap.py), [기존 오버레이](https://github.com/Lab678-Hackathon/lab678/blob/konnect/frontend/js/components/directions-overlay.js)

## 5. 제품·데이터 설계 초안 [팀 확인 전 제안]

### 사용자 흐름

- S02에서 이동수단 선호와 도보·환승 제약을 직접 입력하거나 대화로 확인한다. 이 입력 UI는 Product/UX와 합의한다.
- S03/S04는 확보한 도보/대중교통 요약, 확인 필요 사항, 외부 상세 길찾기를 보여준다. 결과 화면에 별도 채팅창을 추가하지 않는다.
- S05 코스는 출발지→장소1→장소2(→장소3)의 **구간별** 이동수단·시각을 계산한다. 귀가 구간을 종료시간에 포함할지는 제품 결정이 필요하다.
- 외부 앱을 열기 전에 기존 조건·대화·선택을 보존하고 복귀 후 복구한다.

### 최소 내부 모델 — 실제 API 계약 아님

| 항목 | 초안 | 의미·검증 |
|---|---|---|
| 이동 유형 | `mode: walk\|transit` | 대중교통은 버스·지하철·접근/환승 도보로 나눔 |
| 출처·상태 | `provider`, `status`, `source_checked_at` | API 추정 응답, 외부 링크만 있음, 정상 경로 없음, 오류 구분 |
| 시각 | `requested_departure_at`, `time_basis`, `time_supported` | 요청 날짜·타임존과 실제 적용 여부 분리 |
| 전체 요약 | `duration_s`, `distance_m`, `fare_krw` | 결측은 null. 요금은 일반/우대 등 기준을 별도 표시 |
| 보행 부담 | `walk_duration_s`, `walk_distance_m`, `max_walk_leg_s` | 접근·환승·마지막 도보 포함. 일부 구간 누락 시 불완전 표시 |
| 환승 | `transfer_count`, `legs[]` | 버스/지하철 노선, 승하차, 각 구간 예상시간·도보 포함 |
| 지도 형상 | `geometry`와 `geometry_status` | 실제 응답이 없으면 경로선을 만들지 않음 |
| 외부 안내 | `directions_url` 또는 앱 연결 정보 | 구간 출발·도착과 모드를 일치시키되 날짜 전달 여부 별도 표시 |
| 미확인 | `checks_required[]`, `accessibility_status` | 보행 편의·시각·요금·운행 미확인 등 명시 |

서비스 내부 계산은 초·m, 좌표는 명시적 `lat`/`lng`로 통일하는 안을 제안한다. 제공사 응답의 분/초·좌표 순서·결측 코드는 어댑터에서 검증한다. GeoJSON 좌표는 `[lng, lat]`이며 지도 SDK 입력 순서와 혼동하지 않는다.

### 시니어 이동 조건 판정

1. 대중교통 총 소요시간뿐 아니라 **총 도보량·가장 긴 연속 도보·환승 부담**을 비교한다.
2. “가까운 곳 선호”와 “도보 10분 이내 필수”를 구분한다. 발화가 모호하면 확인하고 임의로 상한을 정하지 않는다.
3. 필수 제한을 비교할 근거가 없으면 조건 충족 후보로 통과시키지 않는다. 확인 필요로 분리하거나 제외할 정책은 Product와 합의한다.
4. 예상 이동시간을 개인의 실제 보행시간으로 보장하지 않는다. 임의의 시니어 배속 보정계수나 휴식 버퍼를 확정하지 않는다.
5. 계단·경사·엘리베이터·무장애 경로의 최신 근거가 없으면 접근성은 미확인이다. 짧은 경로나 환승 적음만으로 무장애라고 표시하지 않는다.
6. 일반 성인 운임을 시니어 실제 부담액으로 확정하지 않는다. 무료·우대 적용 여부는 확인값에 한해 안내한다.

## 7. 비용·구현 부담과 운영 확인

- 외부 링크 연결은 경로 API 서버 구현이 적지만 앱 전환·복귀·지원 브라우저 검증이 필요하다. 지도 표시 SDK나 내부 경로 API 사용료까지 무료라는 뜻은 아니다.
- 공개 Kakao는 문서상 두 이동수단을 같은 제공사로 검토할 수 있다. TMAP은 기존 도보 코드 활용 이점이 있다. 실제 키·상품·시각 지원 검증 결과로 선택한다.
- ODsay는 대중교통 대안이며, 노선 그래픽 별도 호출 등으로 호출 수가 늘 수 있다. 제공사별 정확한 요금·한도는 계정 확인이 끝나기 전 확정하지 않는다.
- REST 비밀 키는 서버에서 사용한다. 지도 표시용 공개 클라이언트 키와 서버 키를 구분하고 허용 도메인·IP 등 필요한 제한을 적용한다.
- 캐시·저장·타사 지도 위 표시·출처 로고 조건은 채택 제공사 약관에 맞춰 확인한다. 위치를 포함한 전체 요청 URL을 공개 로그·커밋에 남기지 않는다.
- 시간 제한·재시도 상한·동시 요청 상한을 두고, 사용자가 확정한 조건 변경에만 필요한 재조회 범위를 정한다. 구체 수치·캐시 기간은 미정이다.

## 키 없는 경로 방식 조사 후속

[상세 검토](keyless-routing-review.md). 현재 도보 공개 서버의 서울 두 시험지점 transit_available=false, multimodal 경로400. OSM+GTFS 엔진은 키 없는 자체 대중교통이 가능하나 데이터 준비가 필요하다. 하버사인+평균속도와 정적 근처역 안내는 실제 대중교통 경로를 대신하지 않는다. 제한 시연 구간/목적지 접근 안내는 출처·확인일·추정 구분을 전제로 제안하며 아직 적용하지 않았다.
