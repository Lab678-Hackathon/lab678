# 단일 나들이 진입·실제 마이크 입력 미터

최신 진행표와 미해결 문제는 [새 채팅 인계](next-chat-handoff.md)를 먼저 확인한다. 자동 대화의 중간 글자는 화면에서만 갱신하고, 확정된 전사만 AI에 보낸다. 단발 입력은 이전 최종 결과 방식으로 유지한다.

2026-10-31 사용자 지적: 기존8765에자동대화바로가기만붙여혼동, 실제음성결과없음, 입력신호미터필요, 자동대화/나들이메뉴분리불필요.

## 현재 진입과 실행

기본 **http://127.0.0.1:8765/** 는 준비된앱이 있으면 `/app/?#/home`으로 이동한다. 홈에서 말하기를 시작해도 직접입력을 골라도 **같은 S02 나들이 조건**에서 이어간다. 기존 행사/경로개발점검은 `/checks`에 유지했다. 기본홈에 별도 자동대화 이동메뉴를 추가하지 않는다.

로컬 실행(처음1회 준비):

```powershell
python utils/scripts/prepare_chat_handoff.py --ref 6accf0e0a779917fb16edda72f18ab9deb1c65bb --activate
python backend/preview.py
```

현재 선택은 `.local/chat-handoff-6accf0e-05d4299ba5/project/frontend` (9파일패치)다. 이미 준비·선택되어 있으면 서버만 실행한다. `--activate`는 `.local/active-team-frontend.json`에 상대경로를 기록한다. 실제키·복사본·선택파일은Git제외. 준비파일이없는환경은 기존점검홈으로 동작한다. 새 공유프론트적용은 담당검토와패치/재배포가필요하며 이 로컬복사본을배포했다고표시하지 않는다.

backend/team_app.py는 선택된 .local 인계패키지 frontend의 제한된정적확장자만 제공한다. 경로이탈/역슬래시/외부설정/비밀확장자/과대파일을 거절한다. `/app-config`는 사용가능여부만 반환하고 로컬경로/키는 반환하지 않는다. 같은origin의 `/preview/chat`을호출하며 별도5175서버가 없어도 된다. 5174/5175는 호환검사용으로 같은9파일을갱신했지만 기본안내주소로쓰지않는다.

## 입력 미터의 의미

backend/microphone_meter.js의 공통미터는 사용자클릭 후 getUserMedia로받은 실제기본마이크샘플을 Web Audio AnalyserNode로 읽는다. RMS→20log10→-60~0dBFS의상대레벨을0~100%로표시한다. 음량조절값/정확한음압/음성인식정확도가 아니다. 장치이름은 화면에서만보이며 저장/전송하지 않는다.

- ‘마이크 소리만 점검’은 AI/STT와분리해 신호만확인한다. 기본앱과 `/checks` 모두사용가능.
- 사용자 실제미터는움직이나STT실패 보고후 동시캡처가능성을제거했다. **미터는독립점검전용**, 음성인식시미터트랙/오디오컨텍스트를종료하고미터버튼을잠근다. 기기문제로확정한것이아니며 실제음성실패원인미정.
- 진단미터는echoCancellation/noiseSuppression/autoGainControl해제를요청한다. 장치가요청을실제로지원하는지와입력크기는별개다. ‘조용할때기준측정’2초중앙값과현재/최고/기준대비dB를표시하되말소리판정을하지않는다.
- 최근10초의실제RMS값최대100개를고정dB눈금의스크롤파형으로그린다. 중지시그림도멈추고새세션에서비운다. 잡음도그려지며무작위애니메이션/음성인식성공표시가아니다.
- 스피커출력으로연결하지 않고미터용원본음성을저장/서버전송하지 않는다. 별도브라우저SpeechRecognition의인식처리는해당브라우저정책을따른다.
- 권한이늦게와도 중지뒤트랙을종료하며 탭숨김/화면종료시마이크를해제한다.
- 사용자로그의speechstart/end만으로전사성공을표시하지 않는다. result없는end는설정무응답기한안에서재시도하고, 종료시직접입력대체를안내한다.
- 현재기본홈에 **‘한 번 말하기’**를상시표시한다. 최초단발방식처럼사용자클릭에서직접start(), ko-KR/continuous=false/interimResults=false, AI/TTS/미터없이종료결과를확인한다. 이버튼은자동AI전송하지않으며입력내용을확인후‘보내기’로구분한다. `/checks`의원래‘한번말하기’도원복해비교가능.
- **음성 이벤트·오류 로그**는접지않고실시간표시/자동스크롤한다. start/audio/sound/speech/result/error/end·user_activation·APIHTTP·권한/환경을기록하고내용은제외,200줄메모리에만유지. 복사버튼제공. 실제OS/브라우저는힌트기반추정이고입력목록은기기ID없이조회; ASR이내부선택한정확한장치/PC모델을확정하지않는다.
- **미터가안움직이면** OS/브라우저장치·음소거·권한을확인한다. **미터가움직여도전사가없으면** 음성인식서비스/언어/연결을따로검사한다. 브라우저STT와분석미터가항상동일장치를쓴다고보장하지않는다.

## 검증과 한계

- 실제AI: 화면에서음악→국악2턴/HTTP200/후속질문/분류필드반영 PASS. 직접API2호출도HTTP200확인. 음성성공으로계산하지않는다.
- 미터6구간: 합성440Hz입력→**실제Web Audio분석기**→약72%/-17dBFS, 무음0%, 배경기준대비8dB증가, 중지트랙해제, 인식과미터동시캡처없음, 권한거절, 늦은허용차단 PASS. 물리마이크성공을검증한것은아니다.
- 단발/로그/중간 글자6구간: 최초/checks버튼·새단발버튼 직접입력,진행중이벤트즉시표시,무결과end오류,noTTS/AI호출/본문노출없음,network로그보존·중간글자갱신/확정만전송/중지후늦은결과차단 PASS(모의인식).
- 음성상태16구간은 모의인식/TTS/AI로검사. 입력미터실측과문장인식을섞어PASS로표시하지않는다.
- 화면진입/실제텍스트AI2턴/결과없는end→재시도→전사1회전송, 배포환경/기존기록추천·선택·개인파일차단 확인.
- 백엔드87개 PASS(정적앱경로제한3개/기본홈이동1개추가). `/checks`로바뀐개발화면검사URL을관련스크립트에서갱신했다.

사용자는Windows녹음기입력정상/작지만변화함을확인했다. 브라우저미터변화와실제전사실패는아직원인확정전이며최신단발로그를요청한상태다. MacBook/휴대폰실기기미검증. 미터추가나UA식별이인식서비스실패자체를고쳤다고주장하지않는다. 서버STT미구현. 공개팀프론트/Render키설정/재배포는별도다.
