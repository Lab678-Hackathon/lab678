## 재현과 인계

1. 저장소 루트에서 `python backend/preview.py`로 시작하고 [점검 화면](http://127.0.0.1:8765/)을 연다. 대표 입력을 제출하거나 출발 좌표·시간·분류를 바꾼다.
2. 개인 검증용 `POST /preview/recommend`는 JSON [대표 요청](examples/outing-request.json)을 받는다. `mode`는 기본 live이며 recorded를 지정하면 보관한 응답을 사용한다. [기록 재생 결과](examples/outing-response.json)의 candidates에서 id로 선택을 유지한다.
3. HTTP 200의 ready 또는 no_results, 잘못된 입력 HTTP 400의 need_input, 공급자 오류 HTTP 502의 error를 구분한다. 예시는 `{"status":"no_results","candidates":[]}` (200, 필드 발췌), `{"status":"error","message":"문화정보 조회에 실패했습니다. 같은 조건으로 다시 시도해 주세요."}` (502)다.
4. Edge 모바일 화면 크기에서 실시간 조회·기록 재생·선택·입력 보존·분류 변경·모의 통신 장애 표시를 확인했다. [백엔드 테스트](../../backend/test_outing.py)와 [화면 점검 도구](../../utils/scripts/check_outing_ui.cjs)로 반복할 수 있다. 실제 모바일 기기와 팀 최종 UI는 별도 검증한다.

## 지도 시연

개인 점검 화면은 [Leaflet](https://leafletjs.com/examples/quick-start/)과 [OpenStreetMap 배경지도](https://operations.osmfoundation.org/policies/tiles/)를 쓴다. 팀 지도 제공사 선택은 열어 둔다. 카드·핀은 같은 행사 ID로 강조하며 숫자는 거리순 카드 번호다. 위치가 없는 항목은 카드로만 표시한다. 지도 스크립트를 차단한 Edge에서도 카드 선택이 유지되는지 점검한다.

## UI 담당자 검토 항목

개인 검증용 요청은 출발지 이름·확인한 좌표, 날짜를 포함한 시작·종료 시각, 분류를 받는다. 장소 ID·이름·위경도·행사시간 원문·요금 분류·요금 상세·공식 URL·조회시각을 카드와 지도에서 함께 사용한다. 결측은 null로 표시한다. 형식과 상태는 첫 UI 연결 전에 민규·희영과 확인한다.

제공자 응답에서 INFO-000과 INFO-200(검색 결과 없음)을 구분하고 그 밖의 오류는 재시도로 안내한다. 날짜·분류 필터와 실제 이동시간 검증을 분리한다. 서버·화면에서 기록 재생 여부와 조회 범위를 표시한다.

## 선택에서 경로안내까지

카드의 ‘경로안내’를 누르면 해당 행사가 선택되고 경로안내 영역으로 이동한다. 도보·대중교통 길찾기는 입력 출발지에서 선택 행사장까지 카카오맵을 새 탭으로 연다. 두 곳 코스 위에는 출발지→첫 행사, 첫 행사→두 번째 행사를 각각 표시한다. 아래 두 행사 선택기를 바꾸면 해당 구간 링크도 바뀐다.

데스크톱 Edge에서 카카오맵 목적지 입력, 출발명·도착명·이동수단 전달과 새 탭을 닫은 뒤 선택·입력 유지를 확인했다. 모바일 앱 전환과 기기 메모리 회수 후 복원은 미검증이다. 날짜·출발시각은 카카오맵에서 다시 확인한다. 대중교통 시간은 현재 코스 계산에 반영하지 않는다.

## 내부 텍스트 경로안내

카드의 경로안내는 앱 안의 창을 열고 예상 도보 분·km와 한국어 이동 순서를 먼저 표시한다. 지도 보기는 동일 응답의 polyline6 좌표를 해독한 경로선이며, 단계별 버튼은 해당 단계의 begin/end 인덱스로 위치를 강조한다. 텍스트 안내로 돌아가거나 닫으면 원래 선택을 이어갈 수 있다. 코스 구간의 도보 안내 보기에도 같은 창을 사용한다. 외부 길찾기는 접힌 메뉴에 남아 있다.

청량리역→도암갤러리 실제 응답은 한국어 41단계, 354개 좌표, 7611.718초, 9.765km였다. 지도를 불러오지 못하면 텍스트를 유지하며 조회 실패 시 다시 조회할 수 있다. 창을 닫을 때 진행 중 요청과 이전 경로 데이터를 정리한다. 대중교통 상세 단계는 외부 지도에서 확인한다.

## 시간 부족 후 대안 선택

시간 충돌 결과에 “대안을 찾아드릴까요?”를 표시한다. 동의 전 추가 조회가 없고 동의 후 개인 /preview/recommend에 alternatives:true를 보내 같은 분류·출발지·종료·체류 조건으로 계산한다. 한 곳 관람, 또는 출발을 30분 단위 최대 2시간 앞당긴 두 곳 중 검증 가능한 일정만 최대 2개를 준다. 후보/경로를 새로 조회하지만 운영시간 미상은 가능 판정에서 제외한다.

대안의 시작·종료·총 도보·행사별 시각을 보고 선택하면 해당 응답의 검증된 일정·카드·지도·경로를 적용한다. 한 곳 선택 시 다음 요청 종류는 행사 찾기로 바뀐다. 단순 조회·취소·실패는 입력을 변경하지 않는다. 날짜를 넘겨 출발하지 않으며 더 많은 행사·대중교통·귀가·보행 상한은 이 계산 밖이다. 시연 중 새로고침 후 전시/두 곳/14~17시로 확인할 수 있다.

## 대중교통 내부 안내 연결 준비

개인 `/preview/transit`는 `{points:[{lat,lng},{lat,lng}]}`만 받아 카카오 서버 API를 호출한다. 성공 응답은 `status, routes, checked_at, time_basis`이며 각 경로는 초/m·환승·요금(null 허용)·도보량·단계 배열이다. 날짜/시각을 입력받지 않는다. 503 미설정/인증, 429 한도, 504 지연, 502 실패, 200 no_results를 구분한다.

경로안내 창의 도보/대중교통으로 전환한다. 선택 행사·코스 구간에도 대중교통 안내 보기를 추가했다. 텍스트 우선이며 경로선은 카카오맵의 외부 지도에서 선택적으로 본다. 키 없이 가상 데이터를 정상 경로로 내보내지 않는다. **현재 실제 키가 없어 정상 노선은 모의 검증만 완료**했다. [설정과 검증 기록](transit-progress.md).

### 대중교통 실연결 후 정정

10/31 11:03 KST 사용자 키 연결 후 공개 장소2구간 실조회 및 개인 브라우저 경로 선택 검증 완료. 이전 키 없음 문단은 당시 상태다. 카카오 응답의 steps에는 출발/도착 도보가 누락될 수 있다. `walk_duration_s`, `walk_distance_m`는 null을 유지하고 `listed_walk_duration_s`, `listed_walk_distance_m`만 WALKING 단계 합(없으면 null)으로 제공한다. 화면은 총 도보 확인 필요를 표시하며 필수 보행조건 판정에 쓰지 않는다.


### 대중교통 내부 지도 (2026-10-31 추가)

대중교통 안내에서도 `텍스트 안내` / `지도 보기`를 전환한다. 텍스트 단계의 `지도에서 구간 보기`를 누르면 해당 구간을 확대한다. 다른 경로를 선택하면 선과 구간 강조를 새 응답으로 교체하며, 선택한 행사와 입력 조건은 유지한다. 외부 카카오맵은 접힌 선택 항목으로 남긴다.

`POST /preview/transit`의 기존 필드는 유지하고 `routes[].steps[].path`를 추가했다. 카카오 `steps[].path.points`의 WGS84 `[경도, 위도]`를 Leaflet `[위도, 경도]` 배열로 검증·변환한다. 누락·잘못된 좌표는 빈 배열이며 해당 단계 텍스트는 유지한다. 수단별 구간을 따로 그려 누락된 접근/환승/마지막 도보를 임의로 연결하지 않는다. 좌표가 전부 없으면 출발지·목적지 표시와 안내 문구만 제공한다. 지도는 기존 Leaflet/OSM을 사용하고 경로 출처는 카카오맵으로 표시한다. [공식 경로 명세](https://developers.kakao.com/docs/ko/kakaomap/rest-api).

실제 청량리역→도암갤러리 3개 경로의 선·지도 타일을 모바일 크기 390×844 브라우저에서 확인했다. 모의 경로로 단계 확대, 경로 변경, 좌표 없는 경로로 전환할 때 이전 선 제거, 텍스트 복귀, 도보 전환, 오류·재시도·0건·창 닫기를 검사했다. 백엔드 20개 테스트 PASS. 미래 출발시각/전체 도보량/무장애 검증과 팀 최종 UI 통합은 별개다.
