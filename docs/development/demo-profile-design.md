# 인증 없는 이용·체험 프로필·로컬 저장 설계안

2026-10-31 · 김동조 개발 검토 · **설계 제안, 서비스 미구현**

## 1. 최신 사용자 방향과 추천안

사용자는 처음에 `test1`, `test2`처럼 test로 시작하는 ID를 넣어 Google 가입·승인 없이 이용하고, 샘플은 JSON·새 데이터는 로컬에 저장하는 방안을 제안했다. 이어 **복잡하면 로그인·Google 등 인증 자체를 채택하지 않아도 되고 Supabase도 불필요하면 사용하지 않아도 된다**고 명시했다.

이에 따라 **기본은 인증 없는 이용 + 이 브라우저 저장**, 필요할 때만 **선택형 체험 프로필**을 두는 안을 우선 제안한다. `test…`를 입력해야 추천을 쓸 수 있는 새 장벽을 만들지 않는다. Google OAuth·Supabase는 현 단계의 필수 의존성으로 삼지 않는다. 팀 공통 화면/API 계약 확정과 구현 승인은 별도다.

| 안 | 구성 | 판단 |
|---|---|---|
| A. 인증 없음 | 바로 추천·코스 사용, 현재 브라우저에 선택·선호 저장 | **기본 후보**. 시연 흐름이 가장 짧음 |
| B. 체험 프로필 | A에 test1/test2 선택·새 test 프로필 생성 추가 | 여러 시연 사례를 구분할 때 선택적으로 사용 |
| C. 실제 계정 | OAuth·서버 계정·기기 간 저장 | 필요성이 확인될 때 별도 결정. 현재 필수 아님 |

실제 로그인·계정 장기 저장을 전제한 v0.4와 데모 상태를 설명하는 후속 착수패키지의 차이는 이 최신 사용자 방향과 함께 기록한다. 원문을 확인하지 못한 v0.5 정책을 임의로 확정하지 않는다.

## 2. 체험 프로필을 쓸 경우의 동작 초안

1. 인증 없이 핵심 기능을 시작할 수 있다.
2. 선택형 `체험 프로필`에서 `test1`, `test2`의 샘플을 불러오거나 test로 시작하는 새 ID를 만든다. 외부 로그인 화면으로 이동하지 않는다.
3. 신규 프로필은 기본값으로 생성하고 현재 브라우저에 저장한다. 저장소 안의 샘플 JSON 파일을 다시 쓰지 않는다.
4. 같은 ID 재선택은 해당 브라우저의 기존 프로필을 복구한다. 프로필마다 선호·저장 장소·저장 코스를 구분한다.
5. `체험 종료`는 활성 프로필만 해제하고, `이 기기 데이터 초기화`는 명시 확인 후 저장 데이터를 삭제하는 안을 제안한다. 정확한 문구와 활성 프로필 재방문 복원은 UX와 확인한다.

ID 정규화·문자·길이는 아직 확정 API 규칙이 아니다. 예를 들어 공백 제거·소문자 변환 후 `test` 접두어와 영문 소문자/숫자/`_`/`-`만 허용하고 길이를 제한할 수 있다. 충돌·빈 입력·잘못된 문자는 안내하며 기존 데이터를 덮어쓰지 않는다.

**이 ID는 인증 수단이 아니다.** 같은 기기에서 다른 체험 프로필을 열 수 있고 브라우저 데이터도 수정 가능하다. 실제 신원·비밀번호·보호 API 접근 권한이나 기기 간 계정 격리를 보장한다고 설명하지 않는다.

## 3. 샘플 JSON과 데이터 수명

[demo-users.sample.json](examples/demo-users.sample.json)은 개인정보 없는 **형태 예시**다. 필드명·관심사 코드는 실제 공통 API 계약 확정값이 아니며 장소·가격·시간·좌표를 만들어 넣지 않았다. 로그인 기능이나 저장 로직은 포함하지 않는다.

| 데이터 | 보관 제안 | 의미 |
|---|---|---|
| 샘플 프로필 | 배포 시 읽는 정적 JSON | 최초 초기값. 사실·추천 결과 데이터가 아님 |
| 새 프로필·선호·명시 저장 결과 | 버전이 있는 브라우저 저장소 | 이 기기·브라우저·배포 origin 범위. 계정 서버 아님 |
| 현재 조건·대화·임시 결과 | 화면 상태와 필요한 세션 범위 | 조건 바꾸기·외부 지도 복귀 때 보존. 자동 장기 저장과 구분 |
| 저장한 장소/코스의 사실 | 출처 ID·사용자 선택을 보존하고 재접근 시 재조회 | 과거 가격·운영시간이 현재 사실처럼 고정되지 않게 함 |
| 원본 음성·실제 개인정보 | 기본 장기 보관하지 않음 | 샘플 사용자와 서버 업로드에 포함하지 않음 |

`localStorage`는 origin별이며 브라우저 세션을 넘어 남지만, 사용자 삭제·시크릿 모드·보안 정책 등에 따라 보존이 달라질 수 있다. 파일을 더블클릭하는 `file:` 환경의 동작도 배포 HTTP(S)와 동일하다고 가정하지 않는다. **저장은 영구 백업·기기 간 동기화가 아니다.** [브라우저 저장 공식 참고](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)

구현 시 JSON 파싱·스키마 버전·저장 실패/차단·용량 초과·프로필 전환·중복 ID를 처리한다. 실패했다고 현재 입력·선택을 조용히 지우지 않는다. 새 탭 충돌은 덮어쓰기 정책을 정하고 복구 안내를 제공한다.

## 4. 기존 KONNECT 재사용 시 확인한 결합

기준: `konnect` 커밋 `932032bcc5462d5dda00985503d2e7b4e1ed32be`. [study 읽기·경량화 가이드](konnect-reuse-reading-guide.md)를 먼저 따른다.

- `frontend/js/auth.js`는 Google뿐 아니라 Supabase 익명 세션 발급·세션 구독·토큰·로그아웃에도 관여한다.
- `backend/app/core/auth.py`는 JWT를 검증한다. `test` 접두어를 유효 JWT처럼 취급하는 분기를 추가하지 않는다.
- `api/session.py`, `api/preferences.py`, 대화 이력 API는 인증 의존성이 있다. 로그인 없는 저장을 택하면 사용자의 선택·선호를 브라우저 저장으로 연결하는 범위를 정의한다.
- 추천·코스·대화 진입은 선택적 신원 경로가 있지만 추천·대화 코드에 DB 선호 import가 남아 있다. 단순히 버튼을 숨기거나 SUPABASE 환경변수만 지운다고 의존성이 사라지는 것은 아니다.
- Supabase를 빼는 경우 `db/`, RAG/pgvector, 설정의 필수 키 검사, requirements, 프론트 CDN import, 부트스트랩 대기까지 실제 호출·import 단위로 확인한다. 기존 브랜치 원본은 수정하지 않고 필요한 부분만 새 경로에 구성한다.

## 5. 서버·AI와의 경계

인증 없이 공개 문화정보 추천을 제공하는 백엔드를 설계할 수 있다. 이 경우 모든 클라이언트 입력을 검증하고 요청 한도·타임아웃·비용 상한을 별도 다룬다. 클라이언트의 demo ID를 서버 사용자 권한으로 신뢰하지 않는다. 외부 문화·지도·LLM API 키는 서버 설정에 둔다.

대화 조건은 요청마다 필요한 맥락을 전달하는 안으로 검토하고, Supabase 없이도 브라우저 상태와 응답 계약으로 이어갈 수 있게 한다. 한국어 대화·코스 요구를 없애는 것은 아니며 실제 저장·대화 이력 전송 범위는 Product와 확인한다.

## 6. 구현 전에 짧게 확인할 사항과 검증

- 프로필 UI 없이 A만 제공할지, B를 시연 옵션으로 둘지.
- 저장·선호·대화의 수명, 재방문 활성 상태, 초기화·삭제 문구.
- Google·Supabase를 도입하지 않는 이번 구현 범위의 팀 공유와 영향 파일.
- 실제 브라우저에서 인증 없이 반복 추천/코스, test1/test2 분리, 신규 생성·재선택·새로고침·초기화, 저장 차단·손상 JSON·외부 지도 복귀를 확인한다.
- 샘플 JSON 확인은 서비스 로그인 성공 테스트가 아니다. **현재는 설계와 샘플 작성만 완료하며 실제 로그인·브라우저 저장 코드는 작성하지 않았다.**
