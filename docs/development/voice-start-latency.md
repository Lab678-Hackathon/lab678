# 자동 대화 시작 지연 · 사용자 로그 분석

2026-10-31. 사용자는 자동 대화 버튼을 누른 뒤 5초 이상 지나 듣기가 시작된다고 보고했고, 이어 스피커가 꺼져 있었음을 확인했다. 첨부 원문·장치명은 개인 첨부에 유지하고 이 문서에는 내용 없는 이벤트와 시간 차이만 기록한다.

## 실제 사용자 증거

| 구간 | 로그 시각(ms) | 차이 | 해석 |
|---|---|---|---|
| 자동 #6 시작 → 낭독 단계 | 55728 → 55732 | 4ms | AI 첫 안내 읽기 시작 요청 경로 |
| 낭독 단계 → 인식 start() | 55732 → 65940 | 10208ms | 첫 낭독 완료를 기다린 구간 |
| 인식 start() → audiostart | 65940 → 66072 | 132ms | 실제 오디오 수집 시작 |
| 단발 #4 start() → audiostart | 33818 → 33981 | 163ms | 직접 클릭 인식도 빠르게 오디오 시작 |

고정 10초 대기 타이머는 없다. `VoiceSession.start()`가 `await readVoiceReply(initialPrompt, ...)` 뒤 인식을 시작하는 순서였다. 사용자는 스피커 꺼짐으로 안내가 들리지 않았다고 정정했다. 음소거가 낭독 자체를 느리게 했다고 단정하지 않는다. 이전 로그에는 TTS 출력 시작 이벤트가 없어 10.2초 중 출력 준비와 실제 읽기의 비율은 알 수 없다.

단발 #1·#4에 최종 전사와 정상 종료가 있다. 자동 #6은 임시 글자→최종 전사→chat HTTP200을 5번 반복하고 최대 5회 종료했다. 따라서 이전 인계의 ‘Windows 실제 음성 성공 미확인’은 이 로그 범위에서 갱신한다. 발화 내용·조건의 정확성, 추천/상세까지의 성공이나 다른 기기 호환을 입증하지 않는다. 과거 no-result/network 실패 원인이 해결됐다는 뜻도 아니다.

## 현재 구현과 사용자 확정

기본은 첫 안내 읽기다. 다만 시작 발화는 **“안녕하세요.”**뿐이며 메뉴/사용법을 나열하지 않는다. 첫 듣기에서 3초 동안 발화/인식 결과가 없을 때만 **“어떤 나들이를 원하세요?”**라고 한 번 묻는다. 사용자가 이미 말하기 시작했거나 결과가 오면 유도 질문 타이머를 취소한다. 유도 낭독은 무응답 시간과 대화 횟수에 포함하지 않으며, 듣는 시간은 처음 3초와 나머지 설정 시간으로 나눈다. 예: 무응답5초는 3초+유도낭독+2초이며 낭독을 제외한 총 듣기5초다.

홈에서 활동이 불분명하면 대화를 이어간다. 서버 초안에 전체 이외의 분류/관심어가 있고 음악 후속 질문·미지원 필수 조건·충돌이 없으면 니즈가 확인된 것으로 처리한다. 그때만 같은 서버의 **최초 개인 설정 메뉴 `/checks?from=conversation`**로 이동한다. sessionStorage로 초안을 한 번 전달하고 읽은 후 제거한다. 미확정 출발 좌표·시각을 예제 값으로 채우지 않으며 추천은 사용자 확인 후 별도 실행한다. 직접 설정하기도 이 메뉴를 연다. 팀 원본 화면/공유 API 계약은 변경하지 않았다.

기본 대화 패널은 입력/시작·중지/보내기/답변 중심으로 줄였다. 기기 정보·단발·미터·로그는 ‘마이크 점검·로그’에, 낭독 도구는 설정에 접어 둔다. 최초 설정 메뉴의 미터/로그도 접었다. 진단 메뉴를 닫아도 최근200줄을 메모리에 계속 기록하며 복사·텍스트 다운로드·로그 PNG 다운로드를 지원한다. PNG는 로그를 그린 이미지이고 전체 화면 캡처나 녹음 파일이 아니다. 전사/AI 본문을 추가하지 않고 외부로 업로드하지 않는다.

AI 낭독은 스피커 아이콘/말하는 중, 듣기는 마이크 아이콘/듣는 중과 파동, 연결/처리는 대기 아이콘/상태 글자, 꺼짐은 사선 마이크로 표시한다. 중간 글자는 결과가 있을 때만 나타난다. 스피커 음소거는 페이지가 판별할 수 없다. 낭독 중 자동 끼어들기는 아직 구현하지 않았고, 마이크/낭독 동시 캡처 방지를 유지한다.

인식 요청→오디오 시작과 TTS 요청→출력 시작→종료 시간을 본문 없이 기록한다. 설정의 ‘시작할 때 인사 먼저 듣기’를 끄면 직접 클릭 안에서 듣기를 요청한다. 기본 인사/횟수/무응답 선택만 세션에 저장하며 새로고침으로 마이크를 자동 재개하지 않는다.

## 검증과 한계

최종 검사 결과는 같은 폴더 `qa-voice-start/`에 저장한다. 사용자 원문·장치명은 저장하지 않는다. 수정 후 실제 마이크 체감 시간·스피커 출력·추천/상세 전체 성공은 아직 재측정하지 않았다. 기존 사용자 로그의 실제5턴과 이번 모의 검사를 구분한다. 기본 주소는 http://127.0.0.1:8765/ 이고 팀 원본·공개 배포 반영은 별도다.

최종: 음성24·화면이동6·진단8·합성미터6 = **44구간 PASS**, 기존백엔드 **87개 PASS**. 로그 TXT/PNG 파일 다운로드와320/390px 기본패널700px미만·가로넘침없음을 확인했다. 니즈 전 홈 유지→니즈 후 최초메뉴, 미확정 좌표/시간 비움, 수동 분류 변경·예산/무료 조건 전달도 검사했다. [검증 요약](qa-voice-start/summary.json).
