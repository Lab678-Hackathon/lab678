## 현재 문제 리포트

### 시작 지연 · 최신 증거와 이전 실패 구분

**최신 실제 증거:** 10/31 11:14~11:16 UTC 사용자 로그에서 단발 최종 전사·자동 5턴 전사와 AI 응답을 확인했다. 자동 #6의 시작→인식 요청은 10212ms, 인식 요청→오디오 시작은 132ms다. 첫 안내 낭독 대기가 주 지연 구간이다. 사용자가 스피커가 꺼져 있었다고 확인했다.

**이전 증거:** 전사 없는 end와 별도 network 오류도 있었다. 이번 성공 로그만으로 과거 실패의 원인을 확정하지 않는다. 첨부 원문·장치명은 공개 기록에 복사하지 않는다.

**조치:** 기본은 “안녕하세요.”만 읽고 기다리기다. 첫 3초 무응답에만 짧은 질문 한 번, 니즈 확인 후 `/checks?from=conversation` 최초 메뉴, 스피커/마이크 상태 아이콘, 접힌 진단과 복사·텍스트/PNG 저장을 추가했다. 미터 동시 캡처 방지·중지·늦은 결과 차단은 유지한다. 스피커 음소거를 페이지가 확정할 수는 없다.

**다음 확인:** 스피커를 켠 상태로 짧은 인사→무응답 유도/자동 대화→니즈 확인→최초 설정 메뉴→추천·상세를 묶어 확인한다. 수정 후 실기기 결과와 기존 실제 5턴 로그, 이번 모의 검사를 섞어 완료 처리하지 않는다.

### P0 · 실행 화면과 반영 범위 혼동

예전에는 8765 개인 점검 / 5175 자동 대화 / 공개 팀 앱을 혼용해 사용자가 새 기능을 찾지 못했다. 이제 기본 안내는 8765 한 곳이다. `/checks`는 개발 점검이며 공개 서비스가 아니다. 팀 UI 원본에 이 기능을 반영하고 재배포하는 작업은 아직 남아 있다.

### P1 · 중간 인식 결과와 최종 전사 구분

자동 대화는 `interimResults=true`로 중간 문장을 화면에 표시한다. 브라우저가 결과를 보내야 갱신되므로 일정한 단어 간격이나 기기별 성공을 보장하지 않는다. 최종 전사 후 AI 요청을 보내며, 연속 오디오를 AI로 스트리밍하는 구현은 아니다. ‘한 번 말하기’는 이전 동작 비교를 위해 단발·최종 결과 방식이다.

### P1 · 통합·호환성·저장 기능이 남음

- 최신 패치를 희영님 프론트와 합의 후 연결하고 기존 Render/Vercel에 재배포해야 한다.
- 팀 최종 코스/경로 UI, 저장/프로필 관련 화면을 실제 코드와 다시 대조해야 한다.
- MacBook Chrome/Safari, Android Chrome, iPhone Safari 실기기 음성은 미검증이다.
- 서버 STT는 구현하지 않았다. Naito에서 확인한 채팅/TTS 경로를 STT 경로로 간주하지 않는다.
