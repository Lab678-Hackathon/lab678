## 현재 문제 리포트

### P0 · 브라우저에서 음성 전사 결과가 나오지 않음

**실제 사용자 증거:** Windows 녹음기는 입력이 작지만 소리에 맞춰 변한다. 이전 브라우저 로그에는 `start → audiostart → soundstart → speechstart → speechend → audioend → end`가 있으나 `result`가 없다. 과거 별도 시도에서는 `network` 오류가 있었다. 두 증상을 같은 원인으로 확정하지 않는다.

**현재 판단:** 물리 마이크가 전혀 동작하지 않는 상태는 아니다. 브라우저가 사용하는 입력 장치·인식 서비스·음량·환경 문제는 아직 구분하지 못했다. UA가 Chrome으로 표시되어도 앱 내 브라우저 여부나 인식 서비스 정상 연결을 확정할 수 없다. AI 텍스트 요청 성공은 STT 성공과 별개다.

**조치:** 원래 단발 버튼 복원, 상시 실시간 이벤트/오류 로그, OS·API·권한·입력 장치명 조회, 직접 클릭 `start()` 기록. 미터의 별도 캡처를 음성 인식 전에 종료한다. 동시 캡처가 원인이었다고 확인된 것은 아니다.

**다음 확인:** 외부 Windows Chrome에서 기본 주소를 새로고침하고 ‘한 번 말하기’ 1회 → 로그 복사. 새 로그가 없으므로 반복 추측 수정하지 않는다. `result` 수신 여부, 오류, 장치명과 사용자 동작 여부부터 비교한다. 그 다음 같은 환경에서 자동 대화 2턴을 검사한다.

### P0 · 실행 화면과 반영 범위 혼동

예전에는 8765 개인 점검 / 5175 자동 대화 / 공개 팀 앱을 혼용해 사용자가 새 기능을 찾지 못했다. 이제 기본 안내는 8765 한 곳이다. `/checks`는 개발 점검이며 공개 서비스가 아니다. 팀 UI 원본에 이 기능을 반영하고 재배포하는 작업은 아직 남아 있다.

### P1 · 중간 인식 결과와 최종 전사 구분

자동 대화는 `interimResults=true`로 중간 문장을 화면에 표시한다. 브라우저가 결과를 보내야 갱신되므로 일정한 단어 간격이나 기기별 성공을 보장하지 않는다. 최종 전사 후 AI 요청을 보내며, 연속 오디오를 AI로 스트리밍하는 구현은 아니다. ‘한 번 말하기’는 이전 동작 비교를 위해 단발·최종 결과 방식이다.

### P1 · 통합·호환성·저장 기능이 남음

- 최신 패치를 희영님 프론트와 합의 후 연결하고 기존 Render/Vercel에 재배포해야 한다.
- 팀 최종 코스/경로 UI, 저장/프로필 관련 화면을 실제 코드와 다시 대조해야 한다.
- MacBook Chrome/Safari, Android Chrome, iPhone Safari 실기기 음성은 미검증이다.
- 서버 STT는 구현하지 않았다. Naito에서 확인한 채팅/TTS 경로를 STT 경로로 간주하지 않는다.
