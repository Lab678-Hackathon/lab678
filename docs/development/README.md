[도구·루프 운영](engineering-loop.md), [도구 진행 체크표](tooling-progress.md), [기획 정본 갱신 체크표](planning-doc-refresh-progress.md), [utils 사용법](../../utils/README.md)을 필요한 범위에서 확인한다.

## 사용자와 현재 작업 방식 [사용자 확인]

- 사용자: **김동조**. LAB678 팀의 **개발 담당**이다. 데이터/API 연결, 추천 결과 구조, STT/TTS 기술 검증이 전달받은 우선 업무 분장안에 포함된다.
- 팀명: **LAB678**. 프로젝트의 최종 브랜드명은 확인되지 않았다. `나들이 찾기`는 PRD v0.4의 임시 서비스 메뉴명이다.
- 개인 작업 브랜치: **`dj/develop`**. `develop`의 `c021a308ae3679cd342c9af9e2a2f11ac06b96c2`에서 생성했다. GitHub의 develop 최신 상태와 일치함을 생성 전에 확인했다.
- **지금은 대화·설계와 기록을 우선한다.** 구현 착수를 별도로 요청하기 전까지 서비스 코드 이식·수정은 진행하지 않는다. 요청받은 문서 복사와 기록 정리는 수행한다.
- 대화의 요구·결정·제안·미정·실행 결과를 적절한 파일에 지속 기록한다. 요약은 이 파일, 경위는 `discussion-log.md`, 구체 설계는 필요할 때 별도 문서로 연결한다. 사용자 승인 없이 제안을 확정으로 바꾸지 않는다.
- Discord 연동은 **나중으로 보류**했다.
- [2026-10-31 사용자 추가 지시] **완료한 작업은 항상 작업 단위로 커밋한다.** 기존 명시 요청 원칙에 대한 상시 커밋 요청이다. push·PR·병합·배포는 별도 요청 범위에 따르고, 제출 마감 뒤에는 커밋하지 않는다. 기존 저장소 Git 사용자 설정을 사용하며 AI 공동작성 표시는 넣지 않는다.
- [후속 사용자 지시] 커밋 메시지는 **작업 완료 후 출력하는 보고문 전체를 그대로** 넣는다. 요약·재작성하지 않는다. 짧은 한국어 커밋 메시지 권장보다 이 최신 지시를 우선한다. 보고문 파일을 준비해 커밋 메시지로 사용하고 실제 출력과 일치하는지 확인한다.
- [후속 지시] 모든 새 작업의 파일·기능·함수 색인을 지속 갱신하고, 대화가 길어지면 현재 상태·다음 행동을 짧게 유지한다. 작업마다 세부 계획·체크표를 만들고 실행 전·후와 커밋할 때마다 진행·변경·검증을 보고한다.

## 제품과 개발 방향

- [사용자 제시 최신 기준] **독립형 PRD v0.5**. 다만 원문은 첨부되지 않았고, 조회 당시 GitHub 6개 브랜치의 파일 목록에서도 찾지 못했다. v0.4를 최신 확정본으로 대체하지 않는다.
- [사용자 제시 흐름] `나들이 찾기 → 위치·시간 입력 + AI 음성 대화 → 추천 → 지도·카드 결과 → 선택/조건 변경`. 같은 입력 화면에서 문화코스 요청도 지원한다.
- [사용자 제시 목표] 실제 사용자 조건을 받아 문화활동 추천 결과를 지도·카드로 보여주는 흐름이 첫 통합 목표다. 전체 화면명세를 기다리지 않고 합의된 범위부터 진행하며, 음성과 코스도 병렬 추진하고 실제 작동 여부를 구분한다.
- [사용자 의향] **KONNECT의 많은 부분을 재활용할 가능성이 높다.** 구체 재사용 파일과 변경 범위는 아직 정하지 않았다. `framework`는 기존 프로젝트 기반을 범용화한 브랜치다.
- [AI 제안·미승인] 필요한 기반 선별 → 최소 데이터 계약 → 직접 입력으로 실제 추천 연결 → 같은 조건 처리에 AI 대화·STT/TTS 연결 → 코스·저장 → 통합 검증 순서. 개발 순서 제안이며 제품 기능 삭제나 기술 스택 확정이 아니다.
- 기술 통합 담당·실제 배포 담당을 김동조로 자동 확정하지 않는다.
- [새 의견·검토 요청] 도보·대중교통 이동 안내를 추가 검토한다. [기술검토서](mobility-routing-review.md)에 카카오맵·네이버지도·TMAP·구글맵·ODsay·공공데이터를 비교했고, [김동조 개발 할 일](tasks.md)에 MOB-01~10으로 추가했다. 문서 조사만 완료했으며 제공사·제품 범위 확정, 실제 키 호출·모바일 검증·구현은 아직 아니다.
- [최신 사용자 지시] 복잡하면 Google 등 로그인/인증 자체와 Supabase를 채택하지 않아도 된다. [무인증·로컬 저장을 기본 후보, test 프로필을 선택 후보](demo-profile-design.md)로 검토하고 개인정보 없는 샘플 JSON을 작성했다. 실제 서비스 구현은 아니다.
- [참조 방향] framework는 사용자가 최대한 범용·경량화한 기반, konnect는 이전 완성 기능이다. PRD의 KONNECT 기능 기반 가능성을 참고하되 최신 요구로 대조한다. **framework_doc와 konnect/study의 분석·색인을 먼저 읽고 필요한 코드/테스트를 선별**한다. [재사용 가이드](konnect-reuse-reading-guide.md)에 실제 읽기 범위와 중복 LLM·인증·DB 결합을 기록했다.
- [제공 서버] GPU/서버 매뉴얼 23쪽을 읽고 원본을 `.local/reference/`에 보관했다. [보관 기록](../reference/hackathon-server/README.md)·[활용 검토](hackathon-server-usage-review.md)를 남겼다. VPN 전용 사설망·11/1 13:00 삭제 예정·예시 GPU 사양에 주의하며 STT/오프라인 평가 우선안이다. 접속·설치·실측은 하지 않았다.
