## 음성 요구와 실제의 차이

- 현재 STT `onresult`는 note에 전사를 붙이고 **applyNote를 자동 호출**한다. 직접 텍스트 편집도 oninput으로 같은 처리를 한다. 별도 `분류 반영` 버튼도 있지만 매번 반드시 눌러야만 반영되는 것은 아니다.
- applyNote는 분류 키워드와 두 곳 코스 정규식 처리다. 조건 해석 LLM 호출, 말한 위치/날짜/시각 추출·좌표 확정, 필요한 추가 질문, AI 응답 대화는 없음.
- 기존 분류와 다른 명확한 키워드는 사용자 충돌 동의 없이 바뀔 수 있다. 기존 전사를 누적하므로 복수 분류가 남으면 직접 선택 안내로 간다. 이는 기획의 정정·충돌 동의 흐름을 충족하지 못한다.
- 최신 요구는 **발화 종료→자동 조건 해석/질문→초안과 필드 동기화→충돌 시 동의/거절→S02 내부 조건 확인→추천**이다. 자동 추천 실행이나 상시 청취를 요구하는 것은 아니다.
- 기획 S06/S07은 명시 저장 요청 후 데모 로그인 완료 시 저장 자동 이어짐, 체험 종료 확인 후 전체 삭제다. 구 v0.1 기록의 추가 저장 버튼/로그아웃 미정은 최신 요구로 쓰지 않는다.

## 전달해야 할 정보

희영님 프론트 브랜치/커밋, 실행 명령·포트, 배포 origin, 사용하는 요청/응답 형태. 비밀키는 공유 글에 넣지 않는다. 서로 다른 PC라면 localhost를 공용 API 주소로 전달하지 않는다. CORS는 서버 접근 가능성과 별개 문제다.
