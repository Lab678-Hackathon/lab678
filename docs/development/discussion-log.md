## 1. 저장소 확인과 초기 계획 논의

### 사용자 요청

- 해커톤 저장소 `Lab678-Hackathon/lab678`의 브랜치와 PRD 존재 여부를 확인하고 새 브랜치 이름·기본/상세/세부 계획에 관한 의견을 먼저 요청했다. 이 시점에는 실행하지 말라고 명시했다.
- `konnect`는 이전 프로젝트 활용을 위해 준비했고, `framework`는 이를 더 범용으로 다듬은 브랜치라고 설명했다.
- 최신 기준은 독립형 PRD v0.5라고 제시했다. 단일 나들이 진입, 위치·시간과 음성 대화, 추천, 지도·카드, 선택/조건 변경, 같은 입력에서의 코스 요청을 설명했다.
- 우선 업무 분장안: 민규는 사용자 흐름·화면명세·입력/상태/예외, 희영은 홈·통합 입력·결과 Figma와 공통 컴포넌트, 동조는 데이터/API·결과 구조·STT/TTS 검증.
- 화면명세 전체 완료를 기다리지 않고 합의된 범위부터 병렬 착수하며, 첫 통합 목표는 실제 조건을 받아 지도·카드 결과를 보여주는 흐름이다.

### 확인한 사실

- GitHub 브랜치: `TEAM_WORKFLOW`, `develop`, `docs/align-team-workflow`, `framework`, `konnect`, `main`.
- `develop`은 기본 디렉터리·협업 문서 상태, `framework`는 범용 RAG 앱과 공통 기반, `konnect`는 기존 문화추천·코스·지도 등 구현을 담고 있다.
- 루트 `TEAM_WORKFLOW.md`는 `develop`·`framework`·`konnect`·`TEAM_WORKFLOW`에서 동일했다.
- 최신 v0.5 원문은 조회 당시 브랜치 파일 목록과 사용자 첨부에서 찾지 못했다. 후속 착수 문서들은 v0.5를 참조한다.
- `konnect/PRD.md`는 외국인 여행자 대상의 이전 제품 문서다. 첨부 v0.1은 생활지원 추천 중심의 과거 기획이므로 최신 문화외출 정책과 혼합하지 않는다.
- `framework` 첫 화면은 문서 질문용이다. 각 질문은 독립적으로 처리되어, 조건 누적 대화·입력 필드 동기화는 이번 제품에 맞춘 추가 구현이 필요하다.

### AI 제안 — 아직 구현 승인 아님

- 최신 `develop`에서 시작하고 필요한 기반을 선택적으로 재사용한다.
- 최초 브랜치명 제안 `codex/senior-outing-foundation`은 이후 사용자 지정 `dj/develop`으로 대체되었다.
- 개발 순서: 기준/기반 정리 → 최소 데이터 계약 → 직접 입력으로 실제 추천/지도/카드 → AI 대화/음성 → 코스/저장 → 모바일·오류·통합 검증.
- 상태는 입력 초안/확인값, 현재 조건/결과, 임시 선택/저장을 구분한다. 늦은 이전 응답이 최신 조건을 덮어쓰지 않게 한다.
- 설명·해석과 사실 판정의 역할을 나눈다. 확인되지 않은 가격·운영·예약·이동 정보를 충족 사실로 바꾸지 않는다.
- 10/31 첫 실제 흐름 통합, 11/1 오전 안정화를 제안했지만 팀 확정 일정은 아니다. 제출 마감은 11/1 13:00이다.
- v0.5 로그인/저장 정책, 재사용 범위, 실제 API/음성 접근, 최소시간 30분/60분 충돌은 미정으로 남겼다.

- **확인 결과:** `docs/align-team-workflow`는 TEAM_WORKFLOW 브랜치 이후의 협업 문서 정리본이다. `TEAM_WORKFLOW.md` 본문은 같으며, README·AGENTS·CLAUDE·GEMINI·design/README·frontend/README의 6개 파일을 현재 규칙에 맞게 정리했다.
- 핵심 정리: 최신 develop에서 개인 브랜치 생성, 개인 기능 PR 후 셀프 Merge 가능, 공식 Approve 비필수, main 반영은 희영 최종 승인, AI 지침은 TEAM_WORKFLOW 참조, Figma 4페이지 구조 반영.

## 7. 이동 안내 기술검토 요청과 작업별 커밋 방침

- 사용자는 도보·대중교통 이동 안내 의견이 나왔다고 설명하고 카카오맵·네이버지도·T map·구글맵과 기타 대안의 기술검토 문서 작성 및 김동조 할 일 추가를 요청했다. 기술검토·작업 목록 작성은 승인되었으며 제공사 선정·서비스 구현 범위는 아직 확정되지 않았다.
- 조사 중 사용자가 **항상 작업별로 커밋하자**고 추가 지시했다. 이후 완료한 작업별 커밋은 상시 승인된 것으로 기록한다. push는 별도 요청 때 진행한다. 기존 한국어 커밋·사용자 명의·마감 이후 커밋 금지 원칙은 유지한다.
- 앞서 정리한 기획 파일 6개, 워크플로우 원본 15개와 안내, 개인 개발 맥락·대화·AGENTS 링크를 세 작업으로 나눠 커밋할 예정이다. 이동 안내 검토와 할 일 추가는 별도 작업으로 마무리한다.
