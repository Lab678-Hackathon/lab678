### 확인한 사실

- GitHub 브랜치: `TEAM_WORKFLOW`, `develop`, `docs/align-team-workflow`, `framework`, `konnect`, `main`.
- `develop`은 기본 디렉터리·협업 문서 상태, `framework`는 범용 RAG 앱과 공통 기반, `konnect`는 기존 문화추천·코스·지도 등 구현을 담고 있다.
- 루트 `TEAM_WORKFLOW.md`는 `develop`·`framework`·`konnect`·`TEAM_WORKFLOW`에서 동일했다.
- 최신 v0.5 원문은 조회 당시 브랜치 파일 목록과 사용자 첨부에서 찾지 못했다. 후속 착수 문서들은 v0.5를 참조한다.

## 7. 이동 안내 기술검토 요청과 작업별 커밋 방침

- 사용자는 도보·대중교통 이동 안내 의견이 나왔다고 설명하고 카카오맵·네이버지도·T map·구글맵과 기타 대안의 기술검토 문서 작성 및 김동조 할 일 추가를 요청했다. 기술검토·작업 목록 작성은 승인되었으며 제공사 선정·서비스 구현 범위는 아직 확정되지 않았다.

- 앞서 정리한 기획 파일 6개, 워크플로우 원본 15개와 안내, 개인 개발 맥락·대화·AGENTS 링크를 세 작업으로 나눠 커밋할 예정이다. 이동 안내 검토와 할 일 추가는 별도 작업으로 마무리한다.

## 9. utils·자동 색인·하네스·대화 압축·단계별 보고

- 사용자가 반복 개발 코드를 utils에 개요·docstring과 저장하고 index/reverse index로 재사용하며, 토큰 절약·하네스·루프를 폴더별로 구성하도록 요청했다. 기존 TEAM_WORKFLOW에 있는 내용부터 확인했다.
- 기존 framework utils 일부는 미치환 문법·현재 없는 backend/LLM 의존성이 있어 즉시 실행할 수 없었다. 반복 사용한 복사/해시/전체 보고문 검증 등을 표준 라이브러리 개발 도구로 정리하는 방향을 공유했다.
- 후속 요청으로 긴 대화의 중요한 요구·결정·상태를 기록하고 현재 상태·다음 할 일을 압축한다. state.json을 편집 원본으로, current-state.md를 짧은 재개 문서로 두며 자동으로 채팅 원문을 수집한다고 주장하지 않는다.
- 후속 요청으로 새 작업 파일·기능·함수를 저장소 전체 색인(repo_index/repo_reverse_index/repo_tree)에 계속 기록하고 실시간 갱신·재사용 규칙을 남긴다. 기본 2초 폴링 감시를 구성하고 지원 언어·제외 범위·자동 분류 한계를 명시한다.
- 사용자가 진행 상황과 매 커밋 보고를 요청해, 아직 도구 초안·검증 전이며 이번 작업은 미커밋이라고 중간 보고했다. 감시기는 자동 커밋하지 않는다고 안내했다.
- 추가로 세부 계획·모든 단계 체크표 작성, 체크하면서 실행 전후 출력, 상세 커밋을 요청했다. [진행 체크표](tooling-progress.md)를 만들고 기존 단계와 남은 검증·감시·커밋 순서를 사용자에게 표로 출력했다.

### 실행 결과와 검증

- 표준 라이브러리 도구 8개(색인·현재 상태·복사/해시·검증·루프·전체 보고문 커밋·감시·감시 실검증), 코드/작업 템플릿, 주요 폴더별 짧은 AGENTS를 구성했다. 루트 TEAM_WORKFLOW 본문은 변경하지 않았다.
- 저장소 전체 파일의 개요·해시·기능 매핑·지원 언어 심볼을 repo_index/repo_reverse_index/repo_tree에, 실행 코드 개요·심볼을 utils/index와 reverse_index에 자동 생성한다. 비밀값·의존성·런타임 제외와 생성물 재귀 해시 방지를 구현했다.
- Python AST 추출은 제어문 안의 함수도 포함한다. JS/TS는 정규식 후보이므로 전체 메서드·익명함수의 완전성이나 문법검증을 보장하지 않는다고 명시했다. 현재 생성한 실행 코드는 Python이다.
- state.json을 사람이/AI가 대화 근거로 갱신하고 context.py가 짧은 current-state를 렌더링한다. 상세 경위·전체 완료 보고문은 별도 보존하며, 채팅 원문 자동수집·의미 자동압축을 했다고 주장하지 않는다.
- 첫 일반 권한 테스트는 임시 폴더 접근 제한으로 실행되지 않아 권한을 받아 재실행했다. 최초 기능 테스트 20개 중 17개 통과, 생성물 자기 해시 2건·기대 줄 번호 1건 실패를 최소 수정으로 보완했다. 최종 회귀 4개를 추가해 24개 전부 통과했다.
- 감시기는 숨김 프로세스로 실행했다. 예약 임시 Python 파일의 생성·함수/개요 수정·삭제가 실제 색인에 반영됨을 확인했다. 최신 코드로 정상 재시작한 뒤 다시 통과했다. 자동 커밋·push·네트워크 호출은 없다.
- 각 주요 단계 전후에 상태·실패·보완·검증 수치를 사용자에게 출력했다. 체크표·루프 증거·현재 상태·다음 행동에 기록했다. 최종 보고문을 작업 커밋 메시지로 그대로 사용하고 일치 검증 후 같은 내용을 출력한다.

## 10. 무인증·체험 프로필·제공 서버·두 브랜치 참조

- 사용자는 test1/test2 같은 test 접두어 ID로 Google 가입/승인 없이 이용하고, 샘플을 JSON으로 두고 새 사용자를 로컬에 저장하는 안을 질문했다. 해커톤 제공 서버 매뉴얼 보관·활용안 기록도 요청했다.

- 사용자가 konnect/study와 framework의 기존 분석을 먼저 활용하라고 요청했다. framework는 최대한 가볍고 범용적인 기반, konnect는 이전 프로젝트 완성 브랜치라는 설명과 PRD가 KONNECT 기능 기반일 가능성을 기록했다. 최신 요구를 과거 문서로 덮어쓰지 않는다.

- [양쪽 재사용 가이드](konnect-reuse-reading-guide.md)에 공통 골격은 framework, 실제 사용자 기능·테스트는 KONNECT에서 필요한 부분을 찾는 순서를 기록했다. 예전 로그인 게이트·장기 DB·다중 LLM·RAG를 자동 승계하지 않고 import·스키마·실패 의미를 대조한다.
