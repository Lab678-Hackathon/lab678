**첫 통합 목표**는 한 사람이 실제 위치와 시간을 입력해 문화활동을 추천받고 지도·카드에서 선택한 뒤, 조건 하나를 바꿔 다시 추천받는 것이다. 음성 대화와 2~3곳 코스도 같은 입력에서 시작한다. 기준 버전은 디스코드 공지의 독립형 PRD v0.5다. 저장소에서 확인한 세부 근거는 [개발 착수 패키지](../planning/Lab_678_개발_착수패키지_김동조_20261030.md)와 [공동설계안](../planning/Lab_678_공동설계_병렬착수_공통합의안_20261030.md)이다. v0.5 전문 확보 시 차이만 대조한다.

## 대표 요청 한 건으로 점검하기

“청량리역에서 오후 2시부터 5시까지 전시를 보고 싶어요. 가까운 곳이면 좋겠어요.” 시연일의 날짜와 한국 시각을 명시하고 출발 좌표를 확인한다. 요청과 응답은 착수 패키지의 예시를 재사용한다. 장소 수와 특정 상호를 고정하지 않는다.

| 바꿔 볼 입력·상황 | 기대 동작 |
|---|---|
| 출발지 누락 또는 종료가 시작보다 빠름 | S02에서 해당 필드를 요청한다. 잘못된 조건으로 검색하지 않는다. |
| 운영·가격 미공개, “가까우면 좋겠다” | 결측은 확인 필요로 표시한다. 가까움은 선호로 취급한다. 명시한 도보 상한은 실제 경로 근거로만 충족 판정한다. |
| 조건 변경으로 후보 0건 / 공급자 응답 실패 | 전자는 조건을 조정할 수 있고 후자는 같은 입력으로 재시도할 수 있다. 실패를 0건으로 집계하지 않는다. |
| “전시 말고 공연”으로 변경 / 같은 화면에서 “두 곳 코스로” 요청 | 적용할 조건을 확인한 뒤 각각 장소·코스 요청으로 전달한다. 결과에 새 채팅 화면을 추가하지 않는다. |
| 모바일에서 마이크 거부 / 저장 후 재접속 / 코스 변경 실패 | 텍스트 추천 계속 / 저장 목록 복원 / 이전 코스 보존을 각각 재현한다. |

## 최소 구현과 결정 범위

- **구성 제안.** 백엔드 한 개에 외부 문화정보 조회와 조건 판정을 두고, UI는 동일 응답을 읽는다. 조건→판정은 저장된 입력·응답으로 재현하고, 외부 API·음성·지도는 시연 기기에서 별도 실검증한다. 테스트용 텍스트 화면에는 디자인을 입히지 않는다.
- **재사용.** [두 브랜치 읽기 가이드](konnect-reuse-reading-guide.md)에서 KONNECT 추천·지도·카드의 소스와 테스트, framework의 실행 골격 순으로 필요한 부분만 찾는다. 착수 자료상 직접 이식은 운영진 허용 범위 확인 뒤 진행한다. 그전에도 실제 데이터 조회·독립 구현은 진행 가능하다.
- **동조 결정.** 파일 배치, 공급자 호출 방식, 내부 함수, 재현 테스트는 개발 판단으로 정한다. 로그인 없는 추천과 로컬 저장을 기본으로 한다. 대화가 필요할 때만 AI로 조건을 해석하며 장소·가격·시간은 원천 데이터로 판정한다.
- **팀 확인.** 최소 시간 30/60분과 귀가 포함 여부는 정책 경계값을 고정할 때 민규와 확인한다. 화면 상태·공유 필드는 희영·민규와 첫 연결 전 확인한다. 대표 3시간 요청과 결측 검증은 바로 설계할 수 있다.
- **시간 부족 시.** 첫 통합과 실제 동작 증거를 먼저 확보한다. 도보·대중교통 안내는 외부 지도 연결부터 실기기에서 검증하고, 내부 경로 표시·GPU 사용·계정 연동은 우선순위를 낮춘다. 음성·코스에서 끝내 검증하지 못한 항목은 시연 인계표에 개별 표시한다.

각 단계가 끝날 때 해당 행에 결과와 증거 경로를 기록한다. 작업별 검증·커밋 보고와 팀 통합 절차는 [작업 목록](tasks.md) 및 [공통 워크플로우](../../TEAM_WORKFLOW.md)를 따른다.
