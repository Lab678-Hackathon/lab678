## 결론 (한 줄)

**"데모는 가능, 플랫폼 확장은 어렵다."**
서울 문화경험 추천에 특화된 완성된 서비스. 코딩팀 없이 기존 기능 시연은 가능하지만, 다른 도메인·도시로 확장하려면 핵심 데이터 레이어를 전면 교체해야 한다.

## 1. 완성도 평가 (7개 영역)

### ✅ A 즉시추천 (완성)
- 입력 폼 → 조건 구조화 → TourAPI 조회 → 운영시간·예산 판정 → 결과 3상태 표시
- 244개 이상 테스트, 2026-10-09 기준 268 테스트 그린
- 실내외·배제·0건세이프·시맨틱 랭킹·반경 확장 모두 구현

### ✅ B 문화루트 챗봇 (완성, 로그인 필요)
- 자연어 → 2~3 스톱 루트 구성 → Tmap 도보 경로선 → 타임라인 표시
- Long-term memory (정식 로그인 사용자 대화 영속)
- 멀티인텐트 지원 (FAQ + 추천 동시)

### ✅ 인증·세션 (완성)
- Supabase Anonymous Sign-in → Google OAuth identity linking
- 비회원 첫 추천 1회 허용, 이후 로그인 유도 (FR-L1)
- 비회원→로그인 데이터 마이그레이션 (FR-L2)

### ✅ RAG FAQ (완성, pgvector 적재 필요)
- 6개 지식 문서 → pgvector → 유사도 검색 → 근거 있을 때만 LLM 답변
- 근거 없으면 refuse (사실 생성 안 함)

### ✅ 지도 (완성, Naver Maps 도메인 등록 필요)
- Naver Maps SDK 핀·경로선·카메라 pan
- 임의 직선 금지 (Tmap 실제 경로만)
- prefers-reduced-motion 대응

### ⚠️ My Page / 온보딩 (완성, UX 이슈 1건)
- 관심사·걷기 선호 설정·저장·재추천 반영
- 2026-10-18 QA에서 B 자연어 출발지 UI 불일치 미결

### ⚠️ 평가 시스템 (부분 완성)
- eval CLI 있음 (`python -m app.eval.run_eval`)
- golden_set.json이 쿼리 3개뿐 (소량)

## 2. 해커톤 관점 위험요소

### 🔴 HIGH — 즉시 확인 필요

| 위험 | 내용 | 확인 방법 |
|------|------|-----------|
| **A 추천 5회 실패 (미결)** | 2026-10-18 QA에서 정상 조건에서 5회 연속 실패. 원인 미파악. | Render 로그 확인. `GET /health` 응답 여부 먼저 체크. |
| **Render free tier cold start** | 첫 요청 ~30초 지연. 해커톤 데모에서 치명적. | 미리 warm-up request 1회 전송하거나 유료 플랜 업그레이드 ($7/월). |
| **RAG pgvector 미적재 여부** | `SUPABASE_DB_URL` 없거나 `ingest.py` 미실행 시 `/api/ask` 503. | `python -m app.rag.ingest` 실행 이력 확인. |
| **API 키 8종 현재 유효 여부** | 마지막 커밋이 2026-10-27 기준 몇 주 전. OpenAI 키 잔액·TourAPI 할당량 확인 필요. | OpenAI usage dashboard, data.go.kr 마이페이지. |

### 🟡 MEDIUM — 데모 전 점검

| 위험 | 내용 |
|------|------|
| **Naver Maps 도메인 등록** | NCP 콘솔에서 실제 Vercel URL이 등록돼 있어야 지도 로드. 새 도메인 사용 시 재등록 필요. |
| **B 루트 자연어 출발지 불일치** | 자연어로 말한 출발지가 UI 하단 'Start from' 버튼과 다를 수 있음. 광화문·경복궁 같은 지원 지역으로만 데모하면 회피 가능. |
| **뮤지엄김치간 운영시간 충돌** | 특정 장소 방문시간이 입장마감 이후로 배정될 수 있음. 데모 시 시간대를 14:00~17:00 창으로 사용하면 위험 줄어듦. |
| **esm.sh Supabase 버전** | `auth.js`가 `esm.sh/@supabase/supabase-js@2`를 동적 import — semver minor 업데이트 시 breaking change 가능성. |

### 🟢 LOW — 허용 가능한 제약

| 제약 | 내용 |
|------|------|
| 서울 전용 | TourAPI가 서울·한국 관광지만 커버. 서울 데모에는 문제 없음. |
| 코딩팀 부재 | 기존 기능 시연은 코드 변경 없이 가능. |
| AGENT_LOOP 기본값 불일치 | `.env` 없이 돌리면 `True` (루프 켜짐) — 오히려 더 좋은 동작. |

## 3. 해커톤 플랫폼 확장 가능성

### 3-1. 다른 도시로 확장

**가능하지만 큰 공수** 필요:
- `sources/tourapi.py` 전면 교체 (한국 전용 API)
- `sources/seoulculture.py` 교체 (서울 전용 API)
- `rag/knowledge/*.md` 내용 교체 (서울 여행 정보)
- Naver Maps → Google Maps 또는 로컬 지도 서비스 교체
- Tmap → 현지 경로 API 교체

**재사용 가능한 것:**
- 전체 아키텍처 (FastAPI + LangChain + Supabase)
- domain/ 판정 로직 (정규화·타이밍·예산·랭킹 패턴)
- 프론트엔드 UI 컴포넌트 전체
- agent/ 파이프라인 구조
- 인증·세션 체계

### 3-2. 다른 도메인으로 확장 (맛집·숙소·쇼핑 등)

**상당한 공수** 필요:
- 데이터 소스 교체
- 판정 로직 도메인 적용 (다른 필드명, 다른 제약)
- 프롬프트 수정
- RAG 지식베이스 재작성

## 5. 약점 (플랫폼 한계)

| 약점 | 설명 |
|------|------|
| **서울 문화경험 전용** | TourAPI가 핵심 — 다른 지역/도메인 전환에 큰 공수 |
| **8종 외부 API 의존** | 키 관리·할당량·장애 시 연쇄 실패 가능 |
| **Render free cold start** | 30초 지연 — 데모 흐름을 끊음 (유료 $7/월로 해결 가능) |
| **코딩팀 부재** | orchestrator.py 870줄 등 복잡한 파일 즉시 수정 어려움 |
| **미결 이슈 3건** | A 추천 간헐 실패, 출발지 불일치, 운영시간 충돌 |
| **RAG 적재 상태 불명** | pgvector DB URL + ingest 실행 여부 확인 필요 |

## 6. 해커톤 데모 시나리오 권장

### 시나리오 A (안전, 15분 데모)
```
출발지: 경복궁역 (서울 중심, 데이터 밀집)
시간: 오늘 오후 2시 ~ 오후 5시 (3시간)
note: "I love traditional culture, no museums please"
기대: 4개 후보 (전통 문화 우선, 박물관 제외)
지도 핀·3D 아이콘·Reason 칩 표시
Select → My Pick 저장
```

### 시나리오 B (챗봇, 10분 데모)
```
Google 로그인 → Plan a Route 진입
"Plan a 3-stop culture walk starting from Gyeongbokgung"
→ 루트 2~3 스톱 + 도보 경로선 + 타임라인
"I'd prefer indoor places"
→ 실내 선호 반영 재구성 or 충돌 안내
```

### 시나리오 C (FAQ, 5분 데모)
```
챗봇에서 "Do I need to tip in Seoul?"
→ RAG 답변 (grounded=true)
"What's the best way to use public transport?"
→ RAG 답변 + 공식 경로 안내
```

**⚠️ 데모 전 필수 체크:**
1. `GET https://codyssey-konnect.onrender.com/health` → `{"status":"ok"}` 확인
2. 경복궁역 출발 추천 1회 테스트 실행
3. Render 대시보드에서 최근 에러 로그 확인
