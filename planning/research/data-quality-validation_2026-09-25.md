## 2. Product 직접 실측 — 서울문화포털 문화행사 API 200건

대상: 서울문화포털 문화행사 API(`culturalEventInfo`) 응답 **200건**

### 가격 표현 확인

| 표본 | 유료 + USE_FEE 빈값 | 유료 + 숫자 금액 자동추출 어려움 | 복수 숫자/가격 표현 후보 |
|---|---:|---:|---:|
| 1–100 | 0 | 0 | 13 |
| 101–200 | 0 | 4 | 13 |
| **합계** | **0** | **4** | **26** |

### 관찰

복수 숫자/가격 표현 후보 26건에는 단순 좌석가격 외에도 다음이 섞여 있었다.

- 할인율
- 인원수
- 조건부 가격
- 좌석 등급별 복수 가격

실제 응답에서는 다음과 같은 비정형 가격 표현도 확인됐다.

- `프로그램별 상이 (상세 내용 참조)`
- `프로그램별 상이`
- `상세정보 참조`
- `일부 체험 유료`

### Product 영향

- 숫자가 여러 개 있다고 최저 숫자 하나를 대표가격으로 쓰지 않는다.
- 일반 판매가격과 조건부 할인은 분리한다.
- 유료이지만 금액을 확정할 수 없는 상태를 허용한다.
- 일부 프로그램만 유료인 경우 `부분 유료 · 세부 금액 확인 필요`로 구분한다.
- 명시적 예산 상한 판정에는 **확인된 일반 이용 가능 가격**만 사용한다.

> 주의: 이번 200건에서는 `유료 + USE_FEE 빈값`이 관찰되지 않았다는 뜻이지, 전체 데이터에서 그런 사례가 없음을 의미하지 않는다.

## 3. Tech 실측 — 종로구·중구 6,832건

9/25 Tech 1차 회신에서 공유된 **6,832건** 기준 데이터 품질 요약이다.

| 항목 | 실측 결과 | 해석 |
|---|---:|---|
| 좌표(LAT/LOT) | 98% | 활용성 높음. 이상치 검증 필요 |
| 좌표 이상치 | 122건 (1.8%) | range 검증 후 drop 처리 |
| 무료 여부(IS_FREE) | 99% | 무료/유료 상태는 비교적 활용 가능 |
| 상세 금액(USE_FEE) | 50% | 상세 금액을 항상 제공한다고 전제할 수 없음 |
| PRO_TIME | 100% | 값은 있으나 포맷 혼재로 파싱 검증 필요 |
| ORG_LINK / HMPG_ADDR / MAIN_IMG / USE_TRGT | 98–100% | 링크·이미지·대상 정보 활용성 높음 |
| PROGRAM | 9% | 필수 정보로 전제하기 어려움 |

### 소스 간 중복 매칭 소표본

- TourAPI와 공식 보완 소스 간 완전+부분 일치: **8/11 (73%)**
- 의미: 소스 간 중복 제거를 100% 자동 매칭으로 가정하지 않는다.

### 남은 검증

- `PRO_TIME`, `USE_FEE` 등 자유기술 필드의 실제 파싱 품질
- 동일 콘텐츠 매칭의 더 넓은 범위 정확도
- 구현 중 발견되는 결측·충돌·placeholder 처리

## 4. Product 판단에 미친 영향

- 좌표·무료 여부·공식 링크는 활용성이 높지만 **범위검증·결측처리**를 전제로 사용한다.
- 상세 금액·PROGRAM·자유기술 파싱은 항상 존재하거나 안정적이라고 약속하지 않는다.
- 정보 부족은 오류가 아니라 `추가 확인 필요` 또는 추천 제외 판단에 쓰이는 정상 상태다.
- 가격·예약·시간 등 실행 가능성 관련 정보는 한 개 필드만으로 단정하지 않는다.
- 여러 공식 소스를 결합하되 중복 매칭의 불확실성을 보존한다.
