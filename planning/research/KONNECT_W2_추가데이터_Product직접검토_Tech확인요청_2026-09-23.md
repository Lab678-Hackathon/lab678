# 1. 왜 추가 데이터 소스를 다시 봤는가

KONNECT의 목표는 문화장소를 많이 보여주는 것이 아니라, 외국인 자유여행자가 서울에서 **“지금 또는 특정 날짜에 실제로 선택하기 좋은 문화경험”**을 빠르게 결정하도록 돕는 것이다.

기존 TourAPI는 기본 후보군으로 충분한 가치가 있지만, 앞선 Tech 실측에서 다음 한계가 확인됐다.

| TourAPI에서 확인된 한계 | Product에 미치는 영향 |
|---|---|
| 가격이 비거나 자유기술값인 경우 존재 | 예산 필터 신뢰도 저하 |
| 예약 필드가 명확하지 않음 | `예약 필요/불필요` 판정 곤란 |
| 사전예약 필수 여부를 응답만으로 구분하기 어려움 | 실제 참여 가능성 판단 곤란 |
| 소요시간이 없거나 불균일 | 하루 일정 조합 정확도 저하 |
| 행사별 응답 구조 편차 | 단일 로직으로 정규화하기 어려움 |

따라서 W2의 목적은 **TourAPI를 대체할 소스를 찾는 것**이 아니라 다음 역할을 보완할 수 있는 공식 소스를 찾는 것이었다.

> **후보 발견 → 실행조건 보완 → 공식 확인/예매경로 연결 → 환경 Context 보정**

# 2. Product 직접검토 방식

이번 검토에서는 공식 문서만 읽고 판단하지 않았다.

실제 사이트를 사용자처럼 직접 들어가 **행사·공연·체험 상세페이지를 열어보고**, 다음 기준으로 확인했다.

### 검토 기준

1. 상단의 요약정보만으로 실제 추천이 가능한가
2. 상세본문까지 내려가야 실제 조건이 보이는가
3. 핵심 정보가 이미지 안에만 있는가
4. 같은 프로그램 안에서 가격·시간·대상이 달라지는가
5. 구조화 필드와 상세본문이 충돌하는가
6. 외국인 FIT가 참여할 수 있는지 바로 판단 가능한가
7. 사용자가 실제 다음 행동으로 이어갈 공식 경로가 있는가

별도의 심층 리서치는 **이 직접검토 결과를 교차확인하는 참고자료**로 사용했다.  
최종 Product 판단은 아래의 실제 페이지 확인 결과를 기준으로 정리했다.

**Product 역할:** 서울 문화행사의 기본 이벤트 피드

- 공식 데이터셋: https://data.seoul.go.kr/dataList/OA-15486/S/1/datasetView.do
- 원천: 서울문화포털

### 직접 확인한 샘플

| 샘플 | 직접 본 내용 | Product 관찰 |
|---|---|---|
| `[아케이드서울] 서문들 Texts after the Exhibition` | 기간·시간·장소·대상·무료 여부·공식 경로 | 기본 실행정보는 비교적 명확 |
| 복합 프로그램형 행사 | 전체 시간/유무료 외에 프로그램별 회차·가격·예약·인원제한·날짜별 예외 존재 | 상단 구조필드만으로는 부족 |

### 직접 확인한 핵심 포인트

- 기간·장소·가격·행사시간 같은 **기본 메타데이터는 활용가치가 높음**
- 상세 행사에서는 다음 정보가 별도로 존재할 수 있음
  - 프로그램별 시간
  - 프로그램별 가격
  - 회차
  - 예약
  - 정원
  - 날짜별 예외
- 일부 핵심 실행조건이 **이미지 안에만 존재하는 사례**도 확인

### Product 판단

> **OA-15486은 서울 문화행사의 기본 후보 피드로 활용가치가 높다.**  
> 다만 복합 프로그램의 실제 실행조건까지 자동 확정하기에는 부족할 수 있으므로, 상세페이지/공식 원문을 보완 경로로 둔다.

### Tech 확인 요청

| 확인사항 | 보고 싶은 결과 |
|---|---|
| 실제 API 10~30건 샘플 | 현재 production 필드명 |
| 가격·시간·좌표·URL 채움률 | 실제 사용 가능 수준 |
| null / 자유기술값 비율 | 자동판정 위험도 |
| TourAPI 중복 | 동일 행사 매칭 가능성 |

## 3.5 KOPIS

- 공식 사이트: https://kopis.or.kr/

**Product 역할:** Performance 전문 상세화

### 직접 비교 방식

중구문화재단에서 확인했던 동일 공연을 KOPIS에서도 찾아 비교했다.

### 직접 확인한 강점

| 항목 | Product 확인 |
|---|---|
| 공연기간 | 확인 가능 |
| 공연장 | 확인 가능 |
| 공연시간/회차 | 확인 가능 |
| 관람연령 | 확인 가능 |
| 가격 | 확인 가능 |
| 예매경로 | 확인 가능 |

특히 중요한 차이는 **예매경로**였다.

중구문화재단의 `예매하기`는 자체 회원/로그인 흐름으로 들어갔지만, KOPIS는 **여러 민간 예매사이트 중 선택해 이동할 수 있는 구조**를 확인했다.

외국인 FIT 입장에서는 특정 기관의 회원체계 하나에만 의존하지 않고 여러 예매경로를 제공할 수 있다는 점에서 가치가 있다.

### Product 원칙

> **예매 URL 존재 ≠ 외국인 예매 가능 ≠ 현재 잔여좌석 존재**

따라서 예매경로는 `다음 행동` 정보로 활용하고, availability는 별도로 취급한다.

### 공연상태

웹 UI에서 공연상태가 눈에 띄게 표시되지는 않았으나, 공식 OpenAPI에는 공연상태 필드가 존재하는 것으로 확인했다.

→ 실제 API 응답에서 Tech 확인 필요.

### Product 판단

# 4. 환경 Context — 왜 Product 범위에 포함했는가

## 4.1 검토 계기

추가 데이터 소스를 살펴보면서 Product 관점에서 다음 질문을 확인했다.

> **“KONNECT가 ‘지금 할 문화경험’을 추천할 때, 장소가 운영 중이라는 사실만으로 실제로 좋은 추천이라고 볼 수 있는가?”**

현재 KONNECT의 차별가치는 단순 검색이 아니라:

> **현재 위치 + 현재 시각 + 사용 가능한 시간 + 관심사 + 실제 실행조건**

을 함께 고려해 **지금 선택하기 좋은 소수 후보**를 제시하는 것이다.

여기에 야외/실내 경험의 실제 부담을 바꾸는 **현재 환경**도 자연스럽게 연결된다.

---

## 4.2 추천 가치가 생기는 상황

예를 들어 두 후보가 모두 정상 운영 중이라도:

| 현재 상황 | 야외 경험 | 실내 경험 |
|---|---|---|
| 강한 비 | 실행부담 상승 | 영향 적음 |
| 눈 | 사용자 선호에 따라 변동 | 영향 적음 |
| 폭염/한파 | 체류 부담 상승 | 상대적으로 유리 |
| 미세먼지 높음 | 야외 부담 상승 | 상대적으로 유리 |

즉 환경 데이터는 문화 콘텐츠 자체는 아니지만 **“왜 지금 이 후보를 추천하는가”를 더 설명력 있게 만드는 Context**다.

---

## 4.3 범위는 작게 가져간다

별도의 날씨 서비스나 날씨 메뉴를 만드는 것이 아니다.

환경 데이터는 다음 역할만 한다.

> **기존 후보의 재랭킹 + 주의정보 + 추천 이유 보강**

### 우선 사용할 최소값

| 소스 | 우선 후보 |
|---|---|
| 기상청 | 비/눈 여부, 강수확률, 기온, 하늘상태 |
| AirKorea | PM10, PM2.5 |

풍속·습도·체감온도·오존 등은 Tech 확인 후 필요할 경우 확장한다.

---

## 4.4 Product 원칙

- 비가 온다고 공식 취소를 추론하지 않음
- 날씨는 hard exclusion보다 **reranking/context** 중심
- 공식 취소/휴관이 확인되면 그때 추천 제외
- 사용자가 명시적으로 “눈 오는 야외 경험” 등을 선호하면 soft preference로 반영
- 국적 등으로 날씨 선호를 추론하지 않음
- 예보범위를 벗어나는 날짜는 **UNKNOWN**

---

## 4.5 Tech 확인 요청 — 기상청

| 확인사항 | 요청 |
|---|---|
| 위치 매핑 | 이벤트 lat/lon → KMA `nx/ny` 변환 |
| 최소 필드 | 비/눈, 강수확률, 기온, 하늘상태 |
| 캐시 | 사용자별 호출 대신 서울/격자 단위 캐시 가능 여부 |
| 예보범위 | 즉시추천/특정 날짜 일정에 적용 가능한 범위 |
| fallback | 예보범위 밖이면 UNKNOWN 처리 |
| 공수 | 기존 추천 로직에 Context로 붙일 때 예상 난이도 |

**Product 판단:** MVP 반영을 우선 검토할 가치가 높음.

---

## 4.6 Tech 확인 요청 — AirKorea

| 확인사항 | 요청 |
|---|---|
| 최소값 | PM10, PM2.5 |
| 위치 | 측정소/권역 매핑 방식 |
| freshness | `dataTime` 등 최신시각 활용 |
| 캐시 | 서울/권역 단위 캐시 가능 여부 |
| quota | 개발계정 범위에서 MVP 운영 가능한지 |

**Product 판단:**  
기상청만으로도 비·눈·기온 등 **날씨 Context**는 구현 가능하다. 다만 PM10·PM2.5 같은 **대기질은 기상청 단기예보로 대체할 수 없기 때문에 AirKorea가 별도 역할**을 가진다.

따라서 AirKorea는 “안 해도 되는 부가 기능”이라기보다:

> **기상청으로 날씨 Context를 우선 적용하고, AirKorea는 구현 공수가 크지 않다면 함께 붙여 야외 추천 품질을 보강하는 추가 Context**

로 본다.

일정상 제외해야 할 경우에도 환경 Context 전체를 포기하는 것이 아니라 **대기질 축만 후순위로 미루는 것**이다.

다만 개별 상세 URL은 반복적인 패턴으로 검색엔진에 인덱싱되어 있어 HTML 접근 가능성은 있다.

주의사항:

- 서울문화포털 재게시 중복
- 행사별 상세정보 편차
- HTML 변경 취약성
- 자동수집 허용범위 확인 필요

##### A-5. 종로문화재단

공식 프로그램 페이지에서 다음 정보가 풍부한 사례가 확인됐다.

- 장소
- 기간
- 시간
- 대상
- 모집인원
- 접수기간
- 가격
- 문의
- 신청방법

다만 본문 가격과 구조화 `기본가`가 충돌하는 사례가 있고, Product 직접검토에서도 `<동주와 마실>`의 상위 대표값과 세부 프로그램 값이 달랐다.

따라서 **풍부하지만 단순 필드 신뢰는 위험한 소스**로 본다.

##### A-6. 중구문화재단

공식 공개 API는 확인하지 못했다.

공연·전시·좌석·예매·교육/문화행사·월별일정 등의 공식 콘텐츠를 운영한다.

Product 직접검토와 결합하면:

- 공연 → 높은 활용가치
- 교육/문화행사 → 편차 큼

으로 구분하는 것이 적절하다.

##### A-7. 중구청

공식 구정 콘텐츠에는:

- 문화축제
- 행사
- 프로그램
- 교육
- 정책
- 신청사업

등이 섞여 있다.

주민 대상 프로그램도 함께 존재하므로 관광객 추천에는 별도 적합성 판별이 필요하다.

Product 직접검토에서도 시장축제 상세가 중구청 공식 네이버 블로그로 연결되는 사례가 반복됐다.

##### A-8. 기상청

공식 단기예보 API는 REST/JSON·XML 기반이며 위치를 일반 위경도 그대로 쓰는 것이 아니라 KMA `nx/ny` 예보격자로 매핑해야 한다.

Product 관점에서는 별도 날씨 서비스를 만드는 것이 아니라 **비·눈·기온·하늘상태를 추천 Context로 제한적으로 사용하는 방향**이다.

##### A-9. AirKorea

PM10·PM2.5·O3 등의 정보를 제공한다.

개발 호출량과 실시간성 부담을 고려하면 사용자 요청마다 직접 호출하기보다 서울/권역 단위 캐시가 적절하다.

### 부록 B · 데이터 충돌·중복 처리 원칙

##### B-1. 하나의 Source-of-truth로 강제하지 않기

동일 경험이 다음 여러 소스에 존재할 수 있다.

```text
TourAPI
OA-15486
KOPIS
운영기관 공식사이트
```

각 source reference를 별도로 보존하는 방향이 안전하다.

##### B-2. 최소 메타정보

```text
source
source_id
fetched_at
source_updated_at
last_verified_at
conflict
```

##### B-3. 가격

```text
price_min
price_max
price_text
is_free
price_conflict
```

##### B-4. 시간

```text
event_start
event_end
schedule_text
session_start
session_end
duration_minutes
```

##### B-5. 예약

```text
reservation_required
reservation_method
reservation_url
availability_status
availability_checked_at
```

`availability_status=UNKNOWN`은 정상값으로 허용한다.

### 부록 C · 이번 W2에서 더 확대하지 않을 범위

현재 Product 검토 기준으로 이번 W2에서 더 이상 넓히지 않아도 되는 범위:

- 새로운 지역기관 계속 추가 탐색
- 민간 체험플랫폼 추가 탐색
- 중구청 블로그 전체 크롤링 검토
- 모든 이미지에 OCR/비전 적용 결정
- 모든 외국어 지원 데이터 조사
- 실시간 잔여좌석 보장 방법 탐색
- 장기간 데이터 프로파일링

심층 리서치에서는 OA-15486을 장기간 수집해 품질을 프로파일링하는 방법도 제안했지만, 이번 W2의 목적은 **MVP 후보 소스를 좁히는 것**이다.

현재 단계에서는:

> **Tech 소량 샘플링 → 구현가치 판단 → MVP 범위 확정**

까지 진행하고, 장기간 프로파일링은 구현/고도화 단계로 넘긴다.
