## 1. 현재 확인 필요

### D-10 — 가격 상태 정규화
Product 기준은 확정되어 있으며 구현 가능성만 확인한다.

- API별 가격 표현을 `free / paid / unknown / partial-or-ambiguous` 수준으로 안정적으로 정규화할 수 있는가?
- 가격 정규화 상태를 Rule/Data layer에서 무료 필터·예산 조건 판정에 활용하여, **가격 측면의 조건 충족 / 가격 추가 확인 필요 / 가격 조건 완화 여부**를 구분할 수 있는가?

**9/25 Tech 답변**
- 가격 상태 정규화는 **가능**.
- 좌석 등급에 따라 가격이 여러 개로 제공되는 경우가 있어 **Product 가격 기준이 추가로 필요**.
- 유료임은 확인되지만 금액 자동 추출이 어려운 사례가 있어 별도 처리 필요.

**Product 영향**
- 기존의 “확인된 가격만 예산 판정에 사용 / 미확인은 추정하지 않음” 원칙은 유지한다.
- 좌석 등급별 복수 가격과 `paid but amount unknown` 예외는 Product 기준을 추가 확정했다.
- 세부 가격 파싱·환율 구현 확인은 `tech-validation-questions_0925_01.md`에서 계속 추적한다.

**반영 문서:** D-10 / `product/02-input-recommendation-rules.md`  
**상태:** **부분확인** — 기본 정규화 가능 확인, 세부 구현은 후속 Queue

### D-12 — 문화루트 시간 처리
Product 기준은 확정되어 있으며 아래 구현 세부만 확인한다.

- 고정형 / 자율형 자동분류 가능 수준
- **예상 이동시간의 구체 산출 방식과 공수(좌표 활용 포함)**
- 실제 소요시간 / Product 계획용 체류시간 분리 저장 가능 여부
- 최소 시간충돌 판정 가능 수준
- 신뢰 가능한 2개 이상 조합 실패 시 개별추천 Fallback 구현 난이도

**9/25 Tech 답변**
- 문화루트 시간 처리의 기본 구현은 **가능**.
- 예상 이동시간의 구체 산출 방식과 공수(좌표 활용 포함)는 구현 단계에서 추가 보완 필요.

**Product 영향**
- Start Anchor + Time Boundary, 실제값 우선, 고정형/자율형, 실패 Fallback 등 기존 Product 기준은 유지한다.
- 이동시간 산출 방식은 Tech 구현 단계의 추가검증 항목으로 남긴다.
- LF-07·LF-08에서 구체화된 도보 경로선·구간별 시간·거리·Fallback은 `tech-validation-questions_0926_01.md`에서 이어서 확인한다.

**반영 문서:** D-12 / `product/04-route-time-rules.md`  
**상태:** **부분확인** — 기본 처리 가능, 지도·경로 구현 수준 추가검증

### W3 — 기존 일정 AI 구조화
- 자유 텍스트 일정에서 날짜·시간·장소를 우선 구조화할 수 있는가?
- 모호한 Hard Constraint 항목만 부분 수정시키는 구조가 가능한가?

**9/25 Tech 답변**

**Product 영향**
- 기존 여행계획을 선택형 Context로 두고 날짜·시간·장소를 우선 구조화하는 Product 기준은 유지한다.
- 실제 구조화 품질과 부분 수정·재반영은 구현/PoC 전까지 검증 대기로 둔다.

**반영 문서:** D-07·D-14 / `product/04-route-time-rules.md` / `product/06-ai-tech-boundary.md`  
**상태:** **추가검증** — 구현 가능성은 긍정적, 실제 품질 검증 미완료

### W2 후속 — 데이터 품질 확인 상태
추가 상세 질문을 새로 확정하기보다 구현 중 아래 상태를 확인한다.

- 서울문화포털 문화행사 API·KOPIS의 실제 필드 채움률
- TourAPI와 공식 보완 소스 간 동일 콘텐츠 중복 매칭 수준
- 주요 자유기술 필드의 파싱 품질

접근·사용 가능성은 확인됐지만 위 품질까지 완료 검증된 것으로 간주하지 않는다.

**9/25 Tech 실측 답변 — 종로구·중구 6,832건 기준**
- 좌표(LAT/LOT): **98%**. 좌표 이상치 122건(1.8%)은 range 검증으로 drop 처리.
- 무료 여부(IS_FREE): **99%**.
- 상세 금액(USE_FEE): **50%**. 무료/유료 플래그에 비해 상세 금액은 결측이 큼.
- PRO_TIME: **100%**이나 포맷 혼재로 파싱 검증 필요.
- ORG_LINK / HMPG_ADDR / MAIN_IMG / USE_TRGT: **98~100%**.
- PROGRAM(프로그램 상세): **9%**로 낮아 필수 정보로 전제하기 어려움.
- TourAPI와 공식 보완 소스 간 동일 콘텐츠 매칭: 완전+부분 일치 **8/11 (73%)**.
- 주요 자유기술 필드 파싱 품질: **추가 실측 필요**.

**Product 영향**
- 좌표·무료 여부·공식 링크 등은 활용성이 높아 보이나, range 검증·결측 처리를 전제로 한다.
- 상세 금액·PROGRAM·자유기술 파싱은 항상 확보되는 정보로 약속하지 않는다.
- 소스 간 중복 제거는 100% 자동 매칭을 전제로 하지 않는다.

**반영 문서:** `product/03-data-trust-policy.md` 및 구현 중 데이터 검증 기록  
**상태:** **부분확인** — 필드 채움률·소표본 매칭 확인, 자유기술 파싱은 추가검증
