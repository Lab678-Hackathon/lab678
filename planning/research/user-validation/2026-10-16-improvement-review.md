# KONNECT 사용자 검증 후 개선 과제

**2026.10.16 현장 검증 기반 · 개발 가능성 협의안 · 희영(UX/UI) / 민규(Product)**

목적: 10/21 발표 전 변경을 일괄 요구하는 문서가 아닌, 실제 관찰 근거와 우선순위를 공유하고 용택님에게 가능 범위를 확인하기 위한 협의안.

## 01  우선 검토 원칙

- 희영·민규 협의 우선순위: **1~5는 우선 개선 요청·기술 검토**, **6은 개발 여력에 따라 검토**. 번호는 실제 구현 순서가 아니며 난이도·발표 안정성에 따라 팀이 조정 가능.

- **실제 개선 여부는 미확정**. 모든 항목은 ‘검증 근거 → 기대 변화 → 확인해야 할 사항 → 완료 판정 예시’로 기술함.

- **사용자 발언·관찰**과 팀이 제안한 UX 해법을 분리해 해석. 외부 사이트 이용, 기존 AI 오류 경험을 KONNECT 자체 결함으로 오인하지 않음.

## 02  우선 개선 요청 (1~5)

### 1. [A] Select 버튼 가시성 개선

**관찰**  |  **P4에서 Select 버튼**을 쉽게 찾지 못하고 추천 카드의 다른 요소를 클릭함. 희영님도 버튼이 눈에 잘 띄지 않는 상황을 관찰.

**제안**  |  **버튼 크기·문자 크기·대비·위치** 등 시각적 위계 조정. 희영님 제안: 제목과 유사한 수준으로 라벨 가시성 강화. 상세 디자인은 UX 판단.

**확인**  |  모바일 화면에서 버튼 식별 가능 여부와 기존 동작/배치 충돌 확인. UI 변경으로 다른 링크가 가려지지 않는지 검증.

### 2. [A] Directions 버튼 가시성 및 지도 아이콘

**관찰**  |  **기존 Directions는 구현**되어 있으나 참가자가 스스로 찾지 못해 **희영님의 안내 후 실제 눌러** 본 사례 발생(정확한 인원 미집계).

**제안**  |  **지도/길찾기 아이콘 추가**, 텍스트·버튼 가시성 강화. 기능 신규 개발이 아니라 우선 기존 기능 노출 개선.

**확인**  |  모바일 추천 결과 카드에서 Directions 존재·가독성·정상 외부지도 연결 여부 확인.

### 3. [A] 최종 Select 화면에 Directions 제공

**관찰/제안**  |  **선택 완료 후 화면에는 Directions가 없어** 실제 장소 방문으로 연결되는 다음 행동이 부족함. P1의 길찾기 수요와 희영님의 현장 의견을 반영.

**제안**  |  선택 완료 화면에서 **Get Directions** 또는 Directions 동작 제공, 기존 길찾기 로직/링크 재사용 가능성 우선 확인.

**확인**  |  선택된 장소를 대상으로 올바른 지도·경로 이동, 시작점/목적지 오류, 모바일 사용성 점검.

### 4. [A] VISITKOREA 링크의 위계·표현·배치

**관찰**  |  **P1은 VISITKOREA**로 이동 후 그곳에서 탐색을 이어가 복귀 안내가 필요했음. **P3도 외부 사이트 상세 탐색**. 외부 탐색 자체가 잘못된 행동이라는 뜻은 아님.

**협의 문구**  |  **‘See details(VisitKorea)’** (희영·민규 잠정안 — 사이트명 과도한 강조 방지 + 외부 이동처 투명성).

**배치**  |  추천 카드에서 **Official website 아래**에 See details(VisitKorea) 배치. Select 후 선택 완료 화면에서 VISITKOREA 링크를 **제거하거나 노출을 줄이는** 방안 검토.

**확인**  |  외부 링크임을 식별 가능해야 함. 문구/위치 수정 후 실제 이동처·뒤로가기/새 탭 동작·KONNECT 복귀 경로 확인.

### 5. [A] 출발지와 동일한 장소의 중복 추천 방지

**관찰**  |  P4가 **Start from=남산골 한옥마을**로 설정했는데 **추천 1순위**가 같은 남산골 한옥마을로 표시됨.

**제안**  |  장소 식별자 또는 정규화된 위치·장소명으로 **동일 대상 여부를 판정**해 중복 추천 처리. 근처의 다른 문화경험까지 일괄 제외하지 않도록 경계.

**확인**  |  동일 장소 입력을 재현하고, 해당 장소가 불필요하게 자기 자신을 추천하는 사례가 방지되는지/다른 정상 후보는 남는지 점검.

## 03  개발 여력에 따라 검토 (6)

### 6. [B] 미지원 지역 입력 시 종각으로 무안내 대체되는 문제

**관찰**  |  P1 홍대, P3 강남을 B에서 검색하려 했으나 두 지역은 B 지원 범위 밖. 안내 없이 기본 지역 종각으로 설정됨. 현재 B는 A보다 개발 고도화가 덜 진행된 상태. 추가로 **P3는 B에 높은 관심**을 보였고, **P2도 동행인과 다음 날 일정**에 KONNECT를 사용해 보려는 대화를 나눔(**실제 B 조작은 P1·P3만 확인**).

**제안**  |  ‘This location isn't supported yet.’ 등 명시적 안내 → **A Start from 빠른 선택 후보** 중 실제 B에서도 처리 가능한 장소만 제시 → **사용자의 명시적 재선택**.

**조건**  |  **기존 날짜·시간·기타 입력 조건**은 유지하고, 동의 없이 종각이나 다른 기본 지역으로 루트 생성하지 않기. A 빠른 선택 후보 5곳의 B 지원 여부는 확인 전.

**확인**  |  홍대·강남 입력 테스트에서 무안내 대체가 없고, 지원 장소 재선택 및 기존 입력 유지가 동작하는지 확인.

## 04  중장기 확장 및 범위 밖 수요

- **프랑스어 등 추가 언어**: **P1이 프랑스어 지원을 먼저 요청**했고, **P3(네덜란드)·P4(스위스)**도 다국어 지원을 희망함(추가 언어 종류는 미확인). 인터뷰에서 영어 소통이 어려웠던 미참여 사례 존재.

- **쇼핑·음식**: P1·P3 챗봇 직접 입력, P2 구두 관심. 현재 MVP 문화경험 추천 범위 밖; 명동 조사 위치의 영향 가능.

- **실시간 지도 추적**: P1 관심. 기존 Directions 링크 가시성 개선과 별도의 고도화 항목.

- **관광정보 정확성·신뢰성**: P1·P3가 기존 AI 여행정보 오류 경험을 공유, P5 현지 서비스에 대한 기대. KONNECT 자체 정확성은 별도 검증 과제.

## 05  용택님께 확인이 필요한 사항

□ **1~5 중 최소 수정 가능** 항목과 추가 개발이 필요한 항목은 각각 무엇인가? 예상 작업량과 **발표 데모 안정성**에 미치는 영향은?

□ 2번 기존 Directions 동작/연동 방식과 3번 Select 최종 화면 재사용 가능 여부는?

□ 5번 추천 결과의 장소 ID/좌표 등 중복 판정 기준을 어디서 처리하는 것이 적절한가?

□ 4번 외부 링크 문구·배치 수정과 선택 완료 화면 처리의 가능한 범위는?

□ 6번 A 빠른 선택 5곳 중 B가 지원하는 장소는 무엇인가? 지원하지 않는 입력에 대한 안내 및 조건 보존은 어느 수준까지 가능한가?
