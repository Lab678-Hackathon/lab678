# KONNECT Product Baseline

> 역할: 현재 Product의 **범위·사용자·핵심가치·주요 시나리오**를 한눈에 확인하는 기준 문서  
> 연결 결정: D-03, D-01, D-06, D-02, D-05, D-04  
> 최종 Source of Truth: Google Docs `KONNECT 제품 기획 기준서`

## 1. MVP 범위 — D-03 / D-04

### MVP IN
- 즉시 추천
- 특정 날짜 문화루트
- 선택형 기존 여행계획 Context
- 로그인·상태관리
- My Page — 개인화 관리 / 현재 여행·최근 선택 최소 진입점 / 계정 정보

### 필수 MVP OUT
- 다일 전체 여행플래너
- 자체 실시간 내비게이션
- 서비스 내 예약·결제
- Recovery
- Photo Challenge / Stamp / Collection

Photo Challenge·Stamp는 폐기한 아이디어가 아니라 **핵심 기능 완성 후 개발 여력이 있을 때 검토하는 추가 구현 후보 (Stretch)**로 둔다.

즉시 추천(A)과 특정 날짜 문화루트(B)는 모두 진행하며 **A 우선 고도화 → B 후속 구현**으로 진행한다. B의 구현 난도가 예상보다 높으면 팀에 공유한 뒤 범위를 유연하게 조정할 수 있다. 현재 B를 MVP에서 제외한 결정은 아니다.

### 구현 기본
- Mobile-first Web
- 영어 우선
- TourAPI 우선
- 특정 국적 하나로 타깃을 제한하지 않음

영어 우선은 특정 영어권 국가만을 서비스 타깃으로 삼기 때문이 아니라, **4주 개발기간 안에서 다국어를 동시에 구현하지 않고 폭넓게 활용 가능한 언어 하나로 MVP를 완성하기 위한 우선순위 결정**이다.

### 로그인·상태관리 유지 이유
로그인은 같은 여행의 Context·선택 상태 연속성과 이후 추천 개인화를 지원하는 기반 기능으로 유지한다.

로그인·상태관리는 **MVP IN**, 방식은 **Google Social Login 방향**이다. 첫 진입에서 로그인을 강제하지 않으며 **비회원은 첫 추천 결과까지 1회 이용하고, 두 번째 추천 또는 재추천 요청 시 로그인 유도**한다. 비회원→로그인 시 현재 요청 조건·추천 결과·현재 선택 등 경험 연속성에 필요한 상태를 유지하며 같은 요청 재입력·재시작을 요구하지 않는다. 구체 이전·복원 방식은 Tech가 결정한다.

My Page는 MVP IN이며 최소범위는 개인화 관리·현재 여행/최근 선택 최소 진입점·계정 정보다. 사용자 화면에서 A의 현재 선택은 **My Pick**, B의 현재 루트는 **My Route**로 명명한다(전체 과거 이력 관리 신규 필수 아님). 전체 추천 이력·방문 통계·취향 분석·Stamp/Collection은 MVP 필수가 아니며 추가 개인화 입력은 Skip 가능하게 한다. 확인된 선호의 관리·재사용, 로그인 전환 Fallback과 공동 논의 경계는 [06 · AI·Tech 경계](./06-ai-tech-boundary.md)를 따른다.

## 2. 대표 사용자와 사용 순간 — D-01

### 서비스 타깃
서울을 자유여행하는 외국인 FIT(Fully Independent Traveler).

특정 국적·연령·성별로 서비스 범위를 제한하지 않는다.

### 대표 검증 사용자
MVP 대표 검증 Persona는 서울을 최소 한 번 이상 방문한 외국인 FIT(N차 방문객)로 둔다. 재방문 경험이 서울 지명·동선·문화시설 숙련을 의미한다고 가정하지 않는다. 혼자 여행을 대표 시나리오로 보되 소규모 동행 사용을 배제하지 않는다. 식사·쇼핑보다 문화경험을 원하지만 구체 장소는 정하지 않았고, 여행 중 생긴 자유시간 또는 특정 날짜의 빈 시간을 활용하려 한다. 운영시간·예약·이동을 종합해 현재 조건에서 실제 가능한지 빠르게 판단하는 데 어려움이 있다. 2~4시간은 대표 검증 시나리오이며 서비스 이용조건이 아니다. 서비스 전체 타깃은 서울 자유여행 외국인 FIT로 유지하며 첫 방문자를 제외하지 않는다. 기존 우선 검증군인 영어 사용에 익숙한 미국 20~40대 FIT는 유지한다.

### 우선 검증 타깃
4주 MVP의 초기 검증에서는 **영어 사용에 익숙한 미국 20~40대 FIT**를 우선 검증군으로 둔다.

- 서비스 전체 타깃을 미국·20~40대로 제한하는 기준이 아니다.
- 비교적 일관된 사용자군에서 핵심 사용 흐름과 영어 UI를 우선 검증하기 위한 범위다.
- 실제 검증 결과에서 의미 있는 차이가 확인되면 국가·연령 등 후속 세분화를 검토한다.

### 대표 사용 순간

#### 즉시 추천(A)
지금부터 사용할 수 있는 시간이 있고 문화경험 의도는 있으나 구체적인 장소·활동을 정하지 않은 상태에서, 현재 조건에 맞는 다음 선택을 좁혀야 하는 순간이다.

- **원래 있던 자유시간**과 **예상치 못하게 생긴 빈 시간**을 모두 대표 상황으로 본다.
- 둘 중 하나에 우선순위를 두지 않는다.
- `2–4시간`은 대표 검증 시나리오 예시이지 서비스 이용조건이 아니다.

#### 특정 날짜 문화루트(B)
오늘 또는 가까운 특정 날짜에 **정해진 시작점과 사용할 수 있는 시간 구간**이 있고, 그 안에서 고정된 장소 수 상한 없이 실행 가능한 문화경험 최소 2곳을 연결하고 싶은 순간이다.

- 대표적으로 반나절 또는 그 이상도 가능하다.
- 시간 길이 자체보다 ‘특정 날짜의 주어진 시간 구간 안에서 여러 문화경험을 하나의 루트로 구성’하는 Job으로 즉시 추천(A)과 구분한다.

### 경계
- 기존 일정은 필수 속성이 아니라 선택형 Context다.
- 계획이 없는 사용자도 정상 이용할 수 있다.
- 숙박·식음료·쇼핑·교통까지 포함하는 종합 여행플래너로 확장하지 않는다.

### MVP 대표 검증지역
서울 전체를 완전 커버하는 대신 **서울 도심 문화권**에서 우선 검증한다.

- 종로구 남부·중구 중심
- 서촌·경복궁–북촌·인사동–종로·을지로–DDP–명동–남산 권역
- 국립중앙박물관·용산 등은 후속 확장 후보

## 3. 문화경험 범위 — D-06

### 추천 대상 공식 공통명칭
**문화경험(Cultural Experience)**은 KONNECT가 사용자에게 추천하고 실행 가능성을 판단하며 문화루트를 구성할 때 사용하는 **개별 추천 대상의 공통 단위**다.

- 즉시 추천(A)에서는 문화경험을 개별 추천한다.
- 특정 날짜 문화루트(B)에서는 실행 가능한 문화경험 최소 2곳을 고정 상한 없이 연결하며, 빈 시간을 모두 채우기 위해 강제로 추가하지 않는다.
- 데이터 원천을 말할 때의 `콘텐츠 / 데이터 레코드`, 지리적 위치를 말할 때의 `장소`, 세부 운영 단위인 `프로그램 / 회차`는 문화경험과 구분한다.
- 영문 사용자 UI에서는 문맥이 명확하면 `Experience / Experiences`로 줄여 사용할 수 있다.

KONNECT의 기본 문화경험 범위는 아래 5개 유형이다.

1. Hands-on / 직접 참여 체험
2. Performance / 공연
3. Exhibition / 전시
4. Cultural & Historic Visit / 문화·역사 장소 방문
5. Festival & Event / 축제·행사

### 포함
- 전통 공방·원데이클래스
- 전시·박물관·미술관
- 궁궐·한옥마을·역사거리 등 문화·역사 방문
- 구조화된 데이터로 확보 가능한 기간 한정 축제·문화행사

### 제외
- 일반 식당·카페 추천
- 일반 쇼핑
- 스포츠·레저 자체가 목적인 활동
- **팝업**: 현재 안정적인 공개 API나 수집 경로를 확보하지 못해 4주 MVP 후보에서 제외한다. 후속에 구조화된 데이터 확보가 가능해질 때 재검토한다.

`Outdoor`는 독립 유형이 아니라 **속성/태그**로 본다. 문화적 맥락이 명확한 야외 경험은 포함할 수 있다.

위 5개는 **콘텐츠 범위를 관리·분류하기 위한 내부 상위 분류 체계**다. 사용자 화면의 관심사 선택지와 1:1 대응시키지 않는다.

### 사용자 관심사 분류
관심사는 선택·복수 선택 가능한 **Soft Preference**이며, 하나의 콘텐츠에 여러 관심사 태그가 붙을 수 있다.

1. `Traditional Culture` / 전통문화
2. `Palaces & Historic Sites` / 역사·궁궐
3. `Hands-on Experiences` / 문화 체험
4. `Art & Exhibitions` / 미술·전시
5. `Live Performances` / 공연
6. `Festivals & Events` / 축제·이벤트

- `Traditional Culture`: 전통예술·생활문화·공예·국악·의례 등 살아 있는 전통문화에 대한 관심.
- `Palaces & Historic Sites`: 궁궐·유적·역사건축·역사적 장소 방문에 대한 관심. `Traditional Culture`와 복수 태그가 가능하다.
- `Hands-on Experiences`: 사용자가 직접 만들거나 해보거나 참여하는 **단기 문화 프로그램**. 문화체험이 주목적인 김치·전통음식 만들기는 포함할 수 있으나 일반 식사·맛집·시식·식음료 소비는 제외한다. 관람·판매·시연 관람만으로는 포함하지 않고 실제 참여 프로그램 단위의 조건을 적용한다.
- `Festivals & Events`: 축제 및 **기간 한정 특별 문화행사** 중심. 일반 공연·전시라는 이유만으로 모두 Events로 중복 분류하지 않는다.

## 4. 핵심 가치와 차별화 — D-02

KONNECT의 문제 정의는 단순히 문화정보가 부족하다는 것이 아니다.

> 여행자가 시간·위치·관심사·기존 일정·운영조건을 함께 고려해 **지금 실제로 무엇을 할 수 있는지 판단하기 어렵다.**

### 핵심 가치
핵심가치는 개인화 추천 자체보다, 사용자의 현재 조건에서 지금 실제로 가능한 문화경험인지 확인해 선택을 좁히는 데 둔다.

### 개인화의 역할
관심사 등 개인화 정보는 핵심가치를 돕는 추천 수단으로 사용한다. 관심사를 입력하지 않아도 위치·시간·운영조건 등 실행 가능성 정보를 바탕으로 추천할 수 있다.

### 선택을 돕는 정보
- 추천 이유
- 확인된 실행조건
- 아직 확인이 필요한 조건
- 공식 확인 경로
- 다음 행동

을 함께 제공하여 사용자가 실제 선택과 행동으로 넘어가도록 돕는다.

### 신뢰 원칙
- 정보가 없으면 추정하지 않는다.
- 미확인 ≠ 무료 / 예약 불필요 / 이용 가능 보장.
- 실시간 정확성을 과장하지 않는다.
- 공식 확인이 필요한 부분은 그대로 남긴다.

## 5. 핵심 시나리오 — D-05

### 즉시 추천(A)
**현재 위치 + 현재 시각을 빠른 기본값**으로 시작한다. 사용자가 더 구체적으로 설정하려는 경우 출발 위치와 시작 시각을 직접 바꿀 수 있다.

시작 위치·시작 시각·종료 시각을 구조화된 필수 입력으로 확보하고, 관심사·예산·이동 선호·기존 일정·날씨 관련 선호 등은 하나의 자연어 선택 입력 영역에서 보완하는 방향이다. 최대 3~4개 범위의 소수 후보를 목표로 하되 숫자를 강제로 채우지 않는다.

### 특정 날짜 문화루트(B)
오늘 또는 미래 특정 날짜의 사용자가 지정한 문화경험 가능 시간 안에서 **고정 장소 수 상한 없이 실행 가능한 문화경험 최소 2곳을 연결한 루트 1개**를 구성한다.

- 필수: 날짜 + 출발 기준 위치 + 사용 가능 시간 구간
- 선택: 관심사 + 예산 + 기존 여행계획
- 현재 방향: 어떤 조건을 말할지 안내·예시를 제공하는 자연어 대화로 계획·조정을 돕는다. 완전히 빈 자유입력으로 확정하지 않는다.

### 공통 원칙
- `하루 일정`이라는 표현보다 `특정 날짜 문화루트`를 사용한다.
- 기존 여행계획은 **즉시 추천(A)·특정 날짜 문화루트(B) 추천에 선택적으로 반영하는 공통 Context**다.
- 계획이 없는 사용자는 기존 일정 입력을 건너뛰고 즉시 추천(A)·특정 날짜 문화루트(B)를 이용할 수 있다.
- 문화루트에 숙박·식음료·쇼핑을 자동으로 채우지 않는다.
- 정확한 대중교통 ETA·최적경로를 보장하지 않는다.
즉시 추천(A)는 LF-03의 `Select experience`로 후보를 고르고 LF-09에서 별도의 명시적 저장·확정 동작을 완료하면 현재 선택으로 유지한다. 특정 날짜 문화루트(B)의 `이 루트로 갈게요`는 LF-08에서 확정해 유지한다. 이 행동은 내부 실시간 내비게이션 시작이나 실제 방문 완료가 아니다.
