# 07 · 모바일 웹 공통 구현·검증 기준

## 1. 목적

KONNECT MVP는 **플랫폼 중립적인 Mobile-first Web**으로 구현한다.

이 문서는 iPhone용·Galaxy용 네이티브 화면을 각각 만드는 기준이 아니라, 하나의 모바일 웹 UI를 **iPhone Safari와 Android Chrome에서 모두 자연스럽게 사용할 수 있도록 하기 위한 UX/UI·개발 공통 확인 기준**이다.

- 대표 화면은 약 **390px 폭**을 기준으로 설계하되 실제 구현은 **360~430px** 범위에서 깨지지 않도록 대응한다.
- iOS·Android의 브라우저 기본 UI 차이는 허용한다.
- 기능 의미·정보 위계·상태·신뢰 기준은 플랫폼에 따라 달라지지 않는다.
- 이 문서는 기획 기능을 새로 추가하는 문서가 아니라 **구현·검증 시 놓치기 쉬운 모바일 웹 조건을 정리한 공통 체크 기준**이다.

## 3. OS·브라우저별 차이 허용 원칙

다음은 iOS와 Android에서 모양이 달라도 Product 오류로 보지 않는다.

- 브라우저 기본 시간 선택기
- 위치 권한 요청 UI
- Google 로그인 전환 화면
- 시스템 키보드
- 브라우저 주소창·하단바
- 기본 스크롤·overscroll 느낌

단, 위 차이 때문에 다음이 달라지면 수정 대상이다.

- 필수 입력 가능 여부
- CTA 접근 가능 여부
- 결과 상태·추천 이유·미확인 정보의 의미
- 로그인 후 맥락 연속성
- 지도 탐색·카드 선택 가능 여부
- 사용자가 현재 화면에서 다음 행동을 이해할 수 있는지

## 4. KONNECT에서 특히 확인할 흐름

### A · 즉시 추천

- Starting point / Start time / Available until 입력
- 선택 자연어 조건 입력 시 모바일 키보드 동작
- LF-03 지도 + 가로 카드 탐색에서 지도 제스처와 카드 스와이프 충돌 여부
- 결과 카드의 상태·추천 이유·가격·예약·미확인 정보가 작은 화면에서도 구분되는지
- Select experience와 공식 상세·외부 지도 행동이 오동작하지 않는지

### B · 특정 날짜 문화루트

- Guided Chat 입력창이 키보드에 가려지지 않는지
- 필수 4값 확인 후 생성 CTA 접근 가능 여부
- 루트 결과의 방문 순서·시간·구간 이동을 한 화면에서 이해할 수 있는지
- 조건 수정·재구성·로그인 유도 후 현재 루트 맥락이 유지되는지

### 로그인·P-09·My Page

- 모바일 Google 로그인 후 중단 지점으로 정상 복귀
- P-09 관심사 + 추가 선호 자유입력 시 키보드·스크롤·CTA 확인
- 추가 선호의 해석 확인·수정 과정에서 현재 입력이 유실되지 않는지
- My Page의 저장 선호 수정·초기화가 모바일 화면에서 명확한지

## 5. MVP에서 별도로 만들지 않는 것

- iPhone 전용 디자인과 Galaxy 전용 디자인 2종
- iOS Human Interface Guidelines 또는 Material Design을 그대로 모사한 별도 네이티브 화면
- App Store / Google Play 배포 패키징
- 네이티브 앱 전용 내비게이션·제스처
- PWA 설치를 전제로 한 필수 사용 흐름
- 모든 모바일 브라우저를 동일 수준으로 최적화하는 완전 호환성 보장

MVP에서는 **핵심 사용자 흐름이 iPhone Safari와 Android Chrome에서 정상 동작하고 의미가 유지되는 것**을 우선한다.

## 6. 최종 모바일 확인표

배포·사용자검증 전에는 아래를 한 번 확인한다.

- [ ] 360px / 390px / 430px 수준에서 주요 화면이 깨지지 않는다.
- [ ] iPhone Safari에서 A 핵심 흐름을 완료할 수 있다.
- [ ] Android Chrome에서 A 핵심 흐름을 완료할 수 있다.
- [ ] 구현된 경우 B 핵심 흐름을 두 환경에서 완료할 수 있다.
- [ ] 하단 CTA가 브라우저 UI·홈 인디케이터에 가려지지 않는다.
- [ ] 키보드가 입력창·주요 CTA를 가리지 않는다.
- [ ] 시간 입력·수정이 두 환경에서 가능하다.
- [ ] 위치 권한 거부 후 직접 장소 입력이 가능하다.
- [ ] 지도 조작·페이지 스크롤·카드 스와이프가 충돌하지 않는다.
- [ ] 로그인 후 보존 대상 맥락이 유지된다.
- [ ] 브라우저 뒤로가기에서 치명적인 초기화·중복 동작이 없다.
- [ ] 긴 영문 때문에 핵심 상태·정보·CTA가 잘리거나 이해하기 어려워지지 않는다.

## 7. 역할 경계

- **희영 · UX/UI:** 화면폭 대응, 터치 영역, 정보 위계, Bottom Sheet·CTA, 영문 길이, 지도·카드 상호작용 표현을 설계한다.
- **용택 · 개발:** Safari/Chrome 실제 동작, viewport·safe-area·키보드, 로그인 복귀, 브라우저 뒤로가기, 위치 권한·지도 제스처 등 구현 동작을 확인한다.
- **공통:** 실제 모바일에서 핵심 흐름을 확인하고, 사용자-facing 기능 의미·상태·신뢰 기준이 바뀌는 문제가 있을 때만 기획과 다시 조율한다.

구체 CSS·프레임워크·컴포넌트 구현 방식은 개발 판단이며, 화면의 상세 Visual Design·Interaction은 UX/UI 판단이다.
