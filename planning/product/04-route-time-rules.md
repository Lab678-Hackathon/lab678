# KONNECT Route & Time Rules

> 역할: 기존 여행계획 입력, Start Anchor + Time Boundary, 문화루트 시간 결측 Fallback 기준  
> 연결 결정: W3, D-07, D-12, D-13

## 1. 기존 여행계획 입력 원칙

기존 여행계획은 **선택형 Context**다.

### 기존 일정이 없는 사용자
- 현재 또는 사용자가 지정한 시작 위치·시각
- 사용할 시간

만으로 추천을 이용할 수 있다.

### 다음 고정 일정이 있는 사용자
간편 입력:
- **다음 고정 일정의 시작 시각**
- **다음 고정 일정의 장소**

종료시각·일정명·활동유형을 모두 수동 필수값으로 요구하지 않는다.

### 전체 일정이 이미 있는 사용자
전체 일정 텍스트를 선택적으로 붙여넣고 AI가 구조화한다.

---

## 2. AI 일정 구조화

### 우선 구조화
- 날짜
- 시간
- 장소

위 항목은 실행 가능성에 직접 영향을 주는 Hard Constraint다.

### 보조 Context
- 일정명
- 활동유형
- 기타 일정 맥락

확실히 추론 가능한 경우에만 Soft Context로 활용한다.

### 모호성 처리
- 시간·장소가 모호하면 해당 항목만 확인·수정
- 활동유형 등 Soft Context가 모호하면 추가 질문 없이 `UNKNOWN`

전체 재입력을 요구하지 않는 것을 기본으로 한다.

## 3. Start Anchor + Time Boundary

추천은 아래 두 요소를 최소 기준으로 구성한다.

### Start Anchor

#### 즉시 추천 기본값
- 현재 위치
- 현재 시각

즉시 추천은 **현재 위치 + 현재 시각을 빠른 기본값으로 사용하는 경험**이다.

다만 사용자가 더 구체적으로 설정하려는 경우:
- 출발 위치를 직접 변경할 수 있고
- 시작 시각도 직접 지정할 수 있다.

즉, `현재 위치 + 현재 시각`은 기본값이지 변경 불가능한 Hard Rule이 아니다.

#### 특정 날짜 문화루트
- 사용자가 지정한 시작 위치
- 사용자가 지정한 시작 시각

### Time Boundary
- 사용자가 지정한 사용 가능시간
- A에서는 사용자가 다음 고정 일정 이동 여유를 고려해 직접 설정한 종료시각

A의 다음 고정 일정 장소·복수 일정 입력은 선택형 Context다. 10/13 MVP에서는 자동 일정 파싱·다음 약속까지 이동시간 산출·시간충돌 검증을 보장하지 않는다. 적용하지 않은 일정은 반영한 것으로 표시하지 않고, `Available until`에 사용자 스스로 다음 일정 이동 여유를 반영하도록 안내한다.

전체 일정이 제공된 경우 인접한 앞뒤 일정은 AI가 추가 Context로 활용할 수 있으나, 직전 일정을 별도 수동 입력시키지 않는다.

### 입력 노출 원칙 — Progressive Disclosure

입력 UX는 **처음에는 핵심 행동과 필수 정보만 보여주고, 사용자가 원하거나 추천 정확도를 높이는 데 필요할 때 추가 설정을 단계적으로 여는 방식**을 따른다.

#### 즉시 추천
- 시작 위치·시작 시각·종료 시각을 구조화된 필수 입력으로 확보한다. 현재 위치·현재 시각은 변경 가능한 기본값이다.
- **LF-02 가용시간 입력 범위:** 최소 **60분(1시간) 이상**, 종료 경계는 **시작일의 24:00까지**다. 별도의 4·6·12시간 등 시간 상한은 두지 않는다. 시작일 24:00은 익일 00:00과 같은 경계 시점의 당일 종료 표기이며, 그 경계를 넘는 익일 종료는 MVP에서 지원하지 않는다.
- 종료 시각의 자동 기본값은 없다. 시작 시각 변경 시 선택한 종료 시각을 유지하고 **자동 연장하지 않는다**. 시작 시각이 종료 시각 이상이면 종료 시각 재선택을 요청한다.
- 종료 시각 미입력·시작/종료 역전·60분 미만·종료 경계 초과는 **추천 전 입력 오류 또는 제한**으로 처리한다. **유효한 입력에서 적합 후보가 없는 경우만** 기존 추천 0건 및 원인별 Fallback을 사용한다.
- **10/19 변경:** 최소 60분은 출발지에서 이동 후 실제 문화경험에 사용할 수 있는 시간을 확보하기 위한 **A 즉시 추천의 입력 정책**이며, 각 경험의 필수 관람시간이나 관람 완료 보장을 뜻하지 않는다. 이동시간은 가용시간에 포함한다. 기존 빠른 선택 `In 1 hr / In 2 hr / In 3 hr / In 4 hr`는 유지한다. `About 60 min` 등 예상·권장 관람시간은 필수 체류시간이 아닌 참고값이다. 신규 시간 계산·체류시간 필터는 이번 변경에 포함하지 않는다. 이 입력 범위는 즉시 추천(A)에만 적용하며 B 문화루트의 시간 범위를 새로 확정하지 않는다.
- 선택조건은 개별 Form을 늘리기보다 하나의 자연어 입력 영역에서 보완하는 방향이다. 기존 여행계획도 이 영역에서 선택적으로 전달할 수 있다.

#### 특정 날짜 문화루트
- 날짜·출발 위치·시작 시각·종료 경계는 필수다. 안내·입력 예시가 있는 자연어 대화를 중심으로 확보하고 `문화루트 보기`로 생성한다.
- 관심사·예산·동행·기존 일정은 선택정보다. 오늘 현재 위치는 수정 가능한 기본값이며 미래 날짜에 현재 GPS를 자동 가정하지 않는다.
- 이미 제공한 값을 반복 질문하지 않고 누락·모호한 필수값만 확인한다. 묶음 질문·직접 수정 경로는 [02 · B 입력 기준](./02-input-recommendation-rules.md#특정-날짜-문화루트b)을 따른다.

#### 목적
- 한 번에 많은 입력을 요구해 생기는 인지 부하를 줄인다.
- 사용자가 첫 화면에서 해야 할 핵심 행동을 명확하게 한다.
- 기본 흐름만 원하는 사용자와 세부 제어를 원하는 사용자를 함께 지원한다.

이 원칙은 Product의 정보구조 기준이며, 구체적인 노출 방식·Interaction·Visual Design은 UX/UI가 설계한다.

## 4. 문화루트 시간정보 원칙

- **하루 1코스·루트 1개, 실행 가능한 문화경험 최소 2곳**. 고정된 장소 수 상한은 두지 않는다. 단, 가용시간을 모두 채우기 위해 후보를 늘리지 않고 실행 가능성과 필요 정보 확인이 우선이다.
- **실행 가능성·필수 조건 검증 후 관심사·이동 부담의 균형**으로 조합한다. 구체 가중치·알고리즘은 Tech가 판단한다.
- 실제 운영시간·회차·입장마감·공식 러닝타임·확인 가능한 소요시간을 최우선 사용한다.
- 출발점·방문 순서·예상 종료·구간 이동·확인된 비용·경험별 예약·미확인 조건을 표시한다.

결측이 있다는 이유로:
- 90분
- 60분
- 20분

같은 숫자를 실제값처럼 임의 생성하지 않는다.

## 5. 고정형 / 자율형

### 고정형 경험
예:
- 공연
- 워크숍
- 해설투어
- 시간제 체험

세션·러닝타임 등 실행시간이 확인되지 않으면 **자동 문화루트에서 제외**한다.

### 자율형 경험
예:
- 전시
- 박물관
- 문화공간 방문

사용자가 체류시간을 조절할 수 있으므로 실제 소요시간과 구분된 **KONNECT 계획용 체류시간**을 사용할 수 있다.

**10/13 회의 후 Product 채택 기준:** 공식 확인 시간(러닝타임·회차·공식 권장시간) → 사용자가 지정한 계획시간(자율형에 한정) → 아래 유형별 KONNECT 계획 체류시간 범위 → 미확인. 고정 회차·러닝타임은 사용자 계획값이나 유형별 계획값으로 덮어쓰지 않는다. 장소별 일괄 40분은 임시 구현이며 Product 최종 기준이 아니다.

| 문화경험 유형·방문 성격 | Product 채택 계획 체류시간 범위 |
|---|---|
| 동상·기념물(짧은 감상 중심) | 15~20분 |
| 문화적 맥락이 있는 공원·역사 명소 | 30~45분 |
| 소규모 전시·갤러리 | 45~60분 |
| 박물관·규모 있는 전시 | 60~90분 |
| 공연·예약형 체험 | 공식 회차·러닝타임 우선 |

위 범위는 **문화루트 구성용 Product 계획값**으로 채택한 것이며 실제 관람 소요시간, 방문 완료, 운영·예약 가능성을 보장하지 않는다. **실측·대표 사례를 통한 산정 근거 검증, 범위 내 개별 계획값 산정 방식, Tech의 실제 구현·적용 여부는 후속 확인**한다. 시간 출처와 성격(확인된 실제값/예상값/계획값/미확인)을 분리하고 근거 없는 시간을 실제 소요시간처럼 표시하지 않는다. 이 범위를 근거로 운영시간·입장마감·이동시간 검증을 생략하거나 실행 가능성을 확정해서는 안 된다.

## 6. 시간값 상태

시간 관련 값은 아래 상태를 구분한다.

- 확인된 실제값
- 계산된 예상값
- Product 계획값
- 미확인

예상 이동시간은 실제 ETA로 표현하거나 보장하지 않는다.

### 지도·도보 이동 기준
- 즉시 추천(A)은 LF-03 결과+지도에서 LF-02로 확정한 출발 위치·후보 장소와 신뢰 가능한 이동정보를 함께 보여준다. 실제 도보 경로선·거리·시간은 각각 검증된 범위에서만 표시한다. 정보가 부족하면 핀·신뢰 수치·외부 지도 Fallback을 제공하며, 별도 LF-07 화면은 사용하지 않는다. 경로선만 확보하지 못하면 출발/도착 핀과 신뢰 가능한 시간·거리·외부 지도, 시간·거리도 신뢰하기 어려우면 핀과 외부 지도 확인으로 낮춘다. 도심권 도보를 우선하되 내부 대중교통 경로 계산은 MVP 필수가 아니고 상세·실시간 길찾기는 외부 지도 연결로 보조할 수 있다. 실제 경로를 계산하지 못하면 임의 직선을 실제 도보 경로처럼 표시하지 않는다.
- 특정 날짜 문화루트(B)는 시작점 → 장소 1 → 장소 2 → 장소 3의 방문 순서를 분명히 한다. 즉시 추천(A) 우선 고도화 → 특정 날짜 문화루트(B) 후속 구현으로 모두 진행한다. B의 실제 난도가 예상보다 높으면 팀에 공유한 뒤 범위를 유연하게 조정할 수 있으며 현재 루트 기준은 유지한다. 실제 도보 경로선·구간별 거리·예상시간의 구체 구현 수준만 구현 단계에서 후속 확인하며, 어렵다면 번호+장소명이 대응되는 핀·순서·신뢰 가능한 구간 이동정보·외부 지도 연결로 대체한다. 2개 장소 루트는 시작점→장소 1→장소 2로 같은 구조를 적용한다. 임의 직선을 실제 경로처럼 표시하지 않는다.
- 지도+목록 동시 표시, 전환, 요약 후 별도 지도 중 모바일 구성은 UX가 1–2안 제안해 협의한다.

## 7. 문화루트 수정·재구성·실패 Fallback

- 조건 수정 시 변경하지 않은 유효 입력을 유지하고, 장소 제외 시 해당 재구성에 제외 장소를 임의 재삽입하지 않는다.
- 조건 수정·장소 제외 후 시간·운영·이동·비용 등 영향받는 실행 가능성을 재검증한다. 정상 재구성 루트에도 최소 2곳·장소 수 상한 없음·실행 가능성 우선 기준을 적용한다.
- 새 루트를 사용자가 명시적으로 선택하기 전 자동 확정하지 않는다.
- 재구성 실패 시 이전 조건·결과를 새 조건과 구분해 유지하고 **직전 조건·결과로 복귀할 최소 경로**를 제공한다. 이전 루트를 새 조건의 정상 결과로 표시하거나 기존 확정 선택을 자동 교체·삭제하지 않는다. 전체 루트 히스토리 관리는 요구하지 않는다.

신뢰 가능한 경험 2개 이상을 조합할 수 없으면:

- 임의의 시간·장소 수를 만들어 루트를 강제 편성하지 않는다.
- 개별 추천으로 전환하거나
- 루트 구성 실패 상태로 처리한다.
- 원인이 **가용시간 부족**이면 다른 실패 원인과 구분해 안내하고 `시간 조건 수정` 또는 `가능한 개별 경험 보기`로 이어간다.
- `시간 조건 수정`은 시작시각·종료시각/가용시간을 다시 조정하는 하나의 Fallback이다. 충분한 근거 없이 시스템이 임의 시각을 생성하지 않는다.

## 8. Tech 후속 검증
**10/13 회의 후 채택·검증 구분:** 유형별 계획 체류시간 범위는 Product 채택 완료(§5 참조). **실측·대표 사례 근거, 범위 내 개별값 산정 규칙, 공식/사용자/유형/미확인 매핑과 실제 Tech 적용 여부**는 후속 검증한다. B 실행시간·이동·마감 충돌 판정과 과다 장소 여부도 미검증이다. A의 다음 일정까지 이동시간 자동계산은 현 MVP 필수 범위에서 제외하되, 사용자가 이동 여유를 포함해 종료경계를 정하도록 UX 안내한다.


Product 원칙은 확정되었으며 아래 구현 세부만 Tech 확인 대상으로 둔다.

- 고정형/자율형 자동분류 가능 수준
- **예상 이동시간의 구체 산출 방식과 공수(좌표 활용 포함)**
- 특정 날짜 문화루트(B)의 실제 도보 경로선 및 구간별 예상 시간·거리의 구체 구현 수준(구현 단계 후속 확인). 어려우면 경로선·번호 핀·시간/거리·외부 연결 중 가능한 범위를 구분한다.
- 실제 소요시간과 계획용 체류시간의 분리 저장
- 최소 시간충돌 판정
- 기본 시간 처리·실패 Fallback의 구현 가능성은 확인 완료이며 재질문하지 않는다. 실제 데이터의 조합·충돌 판정, 조건 수정 반영, 재구성·최소 복구 구현은 미검증이다.
- B-01~B-04 후속 미회신 항목은 [10/4 Tech 확인 요청](../research/tech-validation/tech-validation-questions_1004_01.md)의 B-T01~B-T06을 따른다.

Tech 답변은 D-12을 다시 열기 위한 선행조건이 아니라 H1/H2 및 구현 범위에 반영할 후속 입력값이다.
