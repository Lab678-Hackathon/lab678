## 1. 주최 측 제공 항목

참가자 가이드에 명시된 개발 환경 지원은 다음 두 가지다.

| 항목 | 제공 내용 | 확인된 범위 |
|---|---|---|
| Naito API | 팀장 계정에 API 토큰 추가 제공 | 토큰 제공 사실만 명시. endpoint·인증 헤더·모델명·요청 형식은 별도 안내 확인 필요 |
| GPU 서버 | V100 서버 지원 | GPU 연산 서버 지원 사실만 명시. SSH·포트·저장공간·인터넷·배포 방식은 별도 안내 확인 필요 |

## 2. 가이드에 명시되지 않은 항목

참가자 가이드에는 다음 항목의 제공 여부가 적혀 있지 않다.

- 웹 프론트엔드 호스팅
- FastAPI 등 백엔드 상시 실행 서버
- PostgreSQL 또는 Supabase DB
- 사용자 인증 서비스
- 파일·오브젝트 저장소
- 도메인·TLS 인증서
- GPU 서버의 외부 공개 URL 또는 포트
- Naito API의 정확한 base URL, 모델 목록, rate limit, 사용량 제한

따라서 **V100 서버가 곧 웹 서버 또는 DB 서버라고 가정하면 안 된다.** 서버 접속 정보와 네트워크 정책을 별도로 확인해야 한다.

## 3. 해커톤 최소 웹앱 구성

이번 대회는 10월 30일 주제 공개 후 11월 1일 13:00까지 제출해야 하므로, 처음부터 DB와 계정을 모두 넣기보다 실제 시연 경로를 먼저 완성한다.

```text
정적 프론트엔드
  ↓ HTTPS
백엔드 API 서버
  ├─ /health
  ├─ /api/plan/chat
  ├─ /api/recommend 또는 주제별 핵심 API
  ├─ Naito API 호출
  └─ 당일 필요한 외부 API 호출
```

### 필수 기능

- 주제에 맞는 입력 화면
- 핵심 AI 기능 1개
- 결과 화면
- 로딩·오류·재시도 상태
- Naito API 연결 adapter
- API 키를 브라우저에 노출하지 않는 백엔드 프록시
- `/health` 확인용 엔드포인트
- README 실행 방법과 `.env.example`
- 2분 시연 영상에서 입력부터 결과까지 재현되는 고정 시나리오

### 초기에는 생략 가능한 기능

- 회원가입·로그인
- 사용자별 장기 저장
- 채팅 이력
- 관리자 화면
- RAG용 pgvector
- 실시간 스트리밍
- 복잡한 멀티테넌트 설정

DB가 없더라도 일회성 추천, Naito 채팅, 결과 표시, 시연 영상 제작은 가능하다. 발표 시 저장 기능을 구현하지 않았다면 “이번 MVP 범위에서 제외”라고 명시한다.

## 4. DB가 필요한 경우

다음 기능을 실제로 포함할 때만 Supabase 또는 PostgreSQL을 연결한다.

| 기능 | DB 필요 |
|---|---:|
| 비회원 1회 입력·결과 표시 | 아니오 |
| Naito 일회성 채팅 | 아니오 |
| 새로고침 후 결과 복원 | 선택 |
| 로그인 | 예 |
| 사용자 선호 저장 | 예 |
| 채팅 이력 | 예 |
| RAG 문서·임베딩 저장 | 예 |
| 팀별 콘텐츠·관리자 기능 | 예 |

## 5. 현재 KONNECT에 적용할 실행 순서

### 1단계: 제공 서버 확인

운영진 또는 멘토에게 다음을 확인한다.

1. V100 서버가 웹 요청을 받을 수 있는가?
2. 외부에서 접근 가능한 IP 또는 URL과 포트가 있는가?
3. SSH 접속 방식과 계정은 무엇인가?
4. Docker·Python·CUDA·인터넷 접근이 가능한가?
5. 서버에 프로세스를 대회 종료까지 유지할 수 있는가?
6. 팀별 자원과 GPU 사용량 제한이 있는가?
7. Naito endpoint·모델·인증 헤더·rate limit은 무엇인가?

### 2단계: 가장 얇은 백엔드 실행

- FastAPI 서버를 제공 서버 또는 기존 Render에 배포
- `GET /health` 먼저 검증
- Naito 토큰은 서버 환경변수로만 입력
- `POST /api/plan/chat`을 Naito adapter와 연결
- 주제 공개 후 핵심 API를 하나 추가

### 3단계: 필요한 경우에만 저장 기능 추가

- 발표 시연이 안정화된 뒤 Supabase를 연결한다.
- 로그인·저장·RAG가 주제의 핵심이 아니면 추가하지 않는다.
- DB 연결 실패가 핵심 AI 시연을 막지 않도록 선택 기능으로 격리한다.

## 6. 제출·개발 규칙

가이드에 따라 다음을 반드시 지킨다.

- 주제는 10월 30일 공개 후 개발한다.
- 사전 보유 코드와 외부 API·오픈소스를 발표자료의 외부 자원 활용 내역에 기재한다.
- 발표자료·2분 이내 MP4 시연 영상·전체 소스코드를 모두 제출한다.
- 소스코드는 최종 커밋 기준으로 심사되므로 11월 1일 13:00 전 최종 커밋을 확정한다.
- GitHub 저장소는 Public으로 유지한다.
- API 키와 인증정보는 커밋하지 않는다.
- README에 설치·환경설정·실행 방법을 적는다.
- 발표자료에는 Naito API, GPU 서버, 사전 보유 KONNECT 코드 등 사용한 자원을 빠짐없이 적는다.

## 7. 현재 결론

- **Naito API 토큰:** 반드시 adapter를 미리 준비한다.
- **V100 서버:** AI 실행용으로 활용하되 웹 호스팅·DB 제공으로 추정하지 않는다.
- **웹 백엔드:** 제공 서버의 네트워크 조건을 확인하기 전까지 기존 FastAPI/Render를 예비 경로로 유지한다.
- **DB:** 초기 MVP에는 넣지 않는다. 로그인·저장·RAG가 주제상 필요할 때만 추가한다.
- **프론트:** React를 도입하지 않고 Vanilla JS를 유지한다.
- **최소 성공 기준:** 입력 → Naito 또는 핵심 AI 처리 → 결과 표시를 실제 화면에서 안정적으로 재현하는 것.
